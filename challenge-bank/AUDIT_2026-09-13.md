# Challenge Bank — verification audit

**Date:** 2026-09-13
**Scope:** the whole `challenge-bank/` project — data, gates, generated site, and the three
hand-written documents (PLAN.md, README.md, STANDARD.md).
**Method:** every number below was recomputed from `data/*.json` and from the tools' own output,
independently of what the documents claim. The gates were also *tested* by injecting deliberate
defects, to prove they reject rather than pass everything.

---

## 1. Verdict

**The bank itself is sound. The documents describing it are not.**

Every quality gate passes on the real data. What is broken is the paperwork: PLAN.md, README.md and
STANDARD.md each state a *different, and all three stale,* question count, and several other figures
in them are out of date. Two of them are also internally inconsistent with each other.

### 3.1 The gate is not vacuous — it was tested

Nine defects were injected into a throwaway copy of `data/`, one at a time, each from a clean copy:

| # | Injected defect | Caught? |
|---|---|---|
| 1 | `marks` set to 1 (below the floor) | **yes** — 2 failures |
| 2 | a false expression in `verification.assertions` | **yes** — 1 failure |
| 3 | `challenge_mechanism` emptied | **yes** — 2 failures |
| 4 | part marks no longer summing to `marks` | **yes** — 1 failure |
| 5 | `difficulty` set to 2 | **yes** — 1 failure |
| 6 | `(M1)(A1)` annotations stripped from an answer | **yes** — 1 failure |
| 7 | `syllabus_ref` set to `"Z.9"` (malformed) | **NO — silently ignored** |
| 8 | `answer` truncated to 2 words (length floor) | **yes** — 1 failure |
| 9 | `parts` emptied | **yes** — 2 failures |

**Finding (§3.1, item 7).** STANDARD.md §1 claims "the validator rejects any syllabus code that is not
in that map". That holds only for codes that *match* the subject's pattern
(`Physics HL` → `\b([A-E]\.\d)\b`, etc.). A malformed code such as `Z.9` never matches the pattern, so it
is never examined, and the item passes on the strength of any valid code left in `topic`/`subtopic`.
A well-formed but invalid code (`E.9`) *is* caught. So the check is sound but not total: a typo that
produces a non-matching token is invisible. Low severity, worth a one-line hardening.

## 8. Quality spot-check (by eye)

`MATH-P3-004` (P3, 19 marks, difficulty 5, `problem_solving`) was read in full as a sample:
`a_n = ∫₀¹ xⁿ/(1+x) dx`, five interlocking parts, lever = "no closed form, so find a recurrence and
squeeze". It carries a markscheme annotated `(M1)(A1)(AG)` at each award, 10 machine-checked assertions
(including `approx(log(2), 0.69314718, 1e-8)`), a six-step `solution_skeleton`, a `verification.method`
naming midpoint quadrature cross-checks, and `provenance` citing 高考压轴 with a stated adaptation.
This is the standard the rest of the bank is held to, and it is real.

## 9. Recommended fixes, in order

1. **Commit the 53 unversioned questions** (and the regenerated `site/`) — this is the only item with
   actual risk attached; the work is currently unprotected.
2. **Refresh the three documents** to 164 / 166-of-166 / 1652 assertions / 20,266-item corpus, and make
   README.md's table and prose agree. Add the missing batch log entries to PLAN.md.
3. **Harden the syllabus check** so a malformed code is reported rather than skipped
   (e.g. warn when no code matches the subject pattern, and fail when `syllabus_ref` is non-empty but
   yields no recognised code).
4. Optionally reconcile the stored `originality` blocks by re-running
   `similarity_check.py --write` so the recorded scores match the current corpus.
