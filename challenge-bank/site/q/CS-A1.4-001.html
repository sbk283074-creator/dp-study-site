A1.4 Choosing between interpretation and compilation when a script runs N times

Computer science HL · CS-A1.4-001

Theme A: Concepts of computer scienceA1.4 Translation (HL only): translators, interpreters and compilersP116 marksdifficulty 4technology: allowedStateShow thatCalculateJustify

Question

A greenhouse controller runs a short rule script once every sampling cycle. The script can be executed in either of two ways.

  • Interpreted. Each statement is translated every time it is met, so nothing is produced in advance. This costs $0.050$ ms per execution of the loop body and has no start-up cost.
  • Compiled. The whole script is translated once into bytecode, at a one-off cost of $6.0$ ms. The bytecode is then executed directly at $0.010$ ms per execution of the loop body.

The figure shows the total time taken by each strategy against $N$, the number of times the loop body executes.

The controller samples every $2$ minutes, and in a typical cycle the loop body executes $400$ times.

  1. [3 marks](a)

    State, for each strategy, when the translation of the source code takes place and what, if anything, is produced by that translation.

    (State)
  2. [4 marks](b)

    Show that the two strategies take the same total time when $N = 150$, and determine which strategy is faster, and by how much, for a cycle in which the loop body executes $400$ times.

    (Show that)
  3. [4 marks](c)

    Calculate the total time saved over one day of continuous operation by using the compiled strategy, and express that saving as a percentage of the time the interpreted strategy would have taken.

    (Calculate)
  4. [5 marks](d)

    A developer argues that the script should always be compiled, because compiled code runs faster. Justify why this is wrong for a script that is executed only once, and determine the least value of $N$ for which compiling becomes worthwhile if a slower translator raises the one-off cost to $12.0$ ms while both per-execution times are unchanged.

    (Justify)

Total: 16 marks. Try the question before revealing anything below.

Reveal the answer

(a) Interpreted. Translation happens at run time, every time the statement is met, and no separate translated version of the program is produced; the source is read, analysed and executed statement by statement. One mark for each of 'at run time' and 'nothing is produced', and one mark for making clear that the translation is repeated on each pass. Note also that the compiled route produces bytecode rather than native machine code, so the output is still executed by a virtual machine; what has changed is that the analysis of the source happens once rather than on every pass. This is why the translated output can be reused without the source being present, and why the advantage of compiling grows with the number of executions instead of being a fixed speed-up applied once.

Compiled. Translation happens once, before execution, and produces a separate translated version — here bytecode — which is then executed without reference to the original source. One mark for 'before execution / once' and one mark for naming bytecode as the output. Up to three marks in total across the two strategies, awarded for the pair of contrasts: when the translation happens, and what it leaves behind.

(b) Interpreted: $T_I = 0.050N$. Compiled: $T_C = 6.0 + 0.010N$. Setting them equal: $0.050N = 6.0 + 0.010N$, so $0.040N = 6.0$ and $N = 150$. At $N = 150$ both take $0.050(150) = 7.5$ ms, which confirms the crossing. For $N = 400$: $T_I = 0.050(400) = 20.0$ ms, while $T_C = 6.0 + 0.010(400) = 6.0 + 4.0 = 10.0$ ms. The compiled strategy is faster by $20.0 - 10.0 = 10.0$ ms per cycle. A sign check confirms the direction: $T_I - T_C = 0.040N - 6.0$, which is negative for $N < 150$ and positive for $N > 150$. Because $400 > 150$ the compiled route must win, and the size of the win, $0.040(400) - 6.0 = 10.0$ ms, agrees with the direct subtraction.

(c) One day is $24(60) = 1440$ minutes, and the controller samples every $2$ minutes, so there are $1440/2 = 720$ cycles per day. The saving is $10.0$ ms per cycle, so the total saved is $720 \times 10.0 = 7200$ ms $= 7.2$ s per day. As a percentage of the interpreted time: $\dfrac{20.0 - 10.0}{20.0} \times 100 = 50\%$. Note that the percentage is a property of the two strategies at $N = 400$ and does not depend on how often the controller samples. The absolute figures behind it are $720 \times 20.0 = 14\,400$ ms $= 14.4$ s per day for the interpreted route against $720 \times 10.0 = 7.2$ s for the compiled route, so the time the controller spends on this script halves. Whether that reduction matters in practice depends on what else the controller has to do inside its two-minute window, which is exactly why the percentage, rather than the absolute saving, is the figure worth quoting.

(d) The developer's argument compares only the per-execution figures, $0.010$ ms against $0.050$ ms, and ignores the one-off translation cost, which is incurred in full however few times the script runs. At $N = 1$ the interpreted route takes $0.050$ ms while the compiled route takes $6.0 + 0.010 = 6.01$ ms — about $120$ times longer. For a script executed once, compiling is therefore plainly wrong; it would also be wrong for any script whose total number of executions is below the break-even. The saving per execution is not $0.010$ ms but the difference, $0.050 - 0.010 = 0.040$ ms, and that is the figure which has to repay the translation. With a one-off cost of $12.0$ ms the condition becomes $0.040N \ge 12.0$, so $N \ge 300$: the least value is $N = 300$. This is exactly double the original break-even, as expected, because the break-even is proportional to the one-off cost. Writing the condition generally, with one-off cost $C$ and per-execution saving $s$, the requirement is $sN \ge C$, that is $N \ge C/s$; the given figures are $C = 6.0$ ms and $s = 0.040$ ms, giving $N \ge 150$. Only the ratio matters, so a change in $C$ rescales the answer directly while a change in $s$ rescales it inversely.

Markscheme notes

(a) Accept 'at run time / each time' and 'before execution / once' as the contrast. Candidates who say only that an interpreter is 'slower' without saying when translation happens earn no marks: the question asks when, not how fast. Do not require the word bytecode — 'object code', 'machine code' or 'a translated version' is acceptable, since the question stem itself names bytecode.

(b) Award one mark for each correct expression, one for solving the equality to $N = 150$ and one for the $10.0$ ms difference. A candidate who reads $N = 150$ off the figure without the algebra earns the first two only. Follow-through applies to a candidate whose arithmetic slips provided the method of equating the two totals is shown.

(c) One mark for $720$ cycles, one for $7200$ ms, one for $7.2$ s and one for $50\%$. Condone a candidate who works in seconds throughout. Do not penalise the omission of the observation that the percentage is independent of the sampling interval.

(d) Award up to two marks for the explanation, but only if the candidate identifies that the one-off cost is incurred regardless of $N$; a bare 'it is slower for one run' earns one. One mark for the $N = 1$ comparison, one for noting that the relevant saving is $0.040$ ms per execution rather than $0.010$ ms, and one for $N = 300$. The final observation — that doubling the translation cost doubles the break-even — is creditworthy as an alternative route to the same answer.

Why this question is hard

The item is not really about compilers; it is about which quantity is the right one to compare. The two per-execution figures, $0.010$ ms and $0.050$ ms, are the numbers on the page and the numbers every candidate reaches for, but the saving per execution is their difference, $0.040$ ms. That single slip moves the break-even from $N = 120$ (if you compare $0.050$ against $6.0$) or from 'immediately' (if you compare $0.010$ against $0.050$) to the correct $N = 150$.

Once the right difference is identified, everything else is a consequence. The break-even is the one-off cost divided by the per-execution saving, so it scales linearly with the translation cost and the item can ask for it again with a different cost. The time saved per cycle is the difference of the two totals, and the daily saving is that times the number of cycles — two separate multiplications that candidates routinely conflate.

The conceptual point behind part (d) is that a fixed cost and a running cost behave differently, and that 'faster per execution' is not the same claim as 'faster overall'. A script that runs once is the limiting case that exposes this immediately. It is also worth noting what the item deliberately leaves out: a just-in-time compiler would sit between the two strategies, translating only the hot parts of the script after observing how often they run, and would avoid paying the full translation cost on code that never executes. That is the reason the break-even exists at all rather than one strategy dominating.

Part (a) is not decoration. The contrast that the rest of the item turns on — a cost paid once against a cost paid every time — is the same contrast that defines the two translation strategies, so a candidate who cannot locate the difference in (a) has no model to bring to (b). Marking it first also gives a route into the arithmetic for candidates who freeze at the algebra.

The lever here is the design decision rather than the computation. Nothing in the item is hard to calculate; what is hard is noticing that the obvious comparison, $0.010$ against $0.050$, is the wrong one, and that the relevant figure is the difference between them. That is a mistake about which quantity governs the decision, not a mistake about arithmetic, and it is the sort of error a competent candidate makes confidently.

The item is adapted from a UK A-level treatment of translation strategies, which typically asks for the contrast qualitatively. The quantitative break-even model, the sampling-rate scaling in (c), and the single-execution counter-example in (d) are all new here, so the mathematical structure rather than the source material is what carries the difficulty.
