B4.1 Choosing an implementation for a priority queue when the number of extractions, not the complexity class, decides the winner

Computer science HL · CS-B4.1-201

A counting model for three priority-queue implementations

A priority queue stores items and always returns the one with the highest priority. Three implementations are being compared: an unsorted array, an array kept in sorted order, and a binary heap.

To make the comparison concrete, charge each operation as follows.

* An operation that only touches one end of the structure costs 1 step.
* An operation that has to work through the stored items costs $m/2$ steps on average, where $m$ is the number of items in the structure. This is the average over the position of the item being sought, and it is the convention used here so that the two array implementations are charged on the same footing.
* A binary heap costs $\log_2 m$ steps for every operation, whether it is an insertion or an extraction.

The workload holds $n = 1024$ items throughout, so $\log_2 n = 10$. The items are all inserted first, and the extractions then take place one at a time.

Question

A student claims that the binary heap is the right implementation because its operations are $O(\log n)$ while the unsorted array's are $O(n)$, and that this settles the choice. The claim is to be tested against the counting model above, first with the full workload and then with the number of extractions reduced.

  1. [4 marks](a)

    Determine the total number of steps taken by the unsorted array and by the binary heap when 1024 items are inserted and then all 1024 are extracted, and hence show that the heap performs about 25.6 times fewer steps.

    (Determine)
  2. [4 marks](b)

    Show that the sorted array performs exactly the same total number of steps as the unsorted array on this workload, and explain why two structures with opposite cost profiles can produce the same total.

    (Show that)
  3. [5 marks](c)

    The number of extractions is now reduced from 1024 to $k$, with the 1024 insertions unchanged. Determine the largest value of $k$ for which the unsorted array is still the cheaper choice, and state the smallest value of $k$ at which the heap is cheaper.

    (Determine)
  4. [3 marks](d)

    Explain why the student's complexity-class argument is not by itself a sufficient reason to choose the heap for this workload.

    (Explain)

Total: 16 marks. Try the question before revealing anything below.

Reveal the answer

(a) For the unsorted array, an insertion appends to the end and costs 1 step, and an extraction scans the array and costs $n/2 = 512$ steps (M1):

$$1024 \times 1 + 1024 \times 512 = 1024 + 524\,288 = 525\,312 \tag{M1}$$

For the heap, every operation costs $\log_2 1024 = 10$ steps, so the insertions and the extractions are charged alike (M1):

$$1024 \times 10 + 1024 \times 10 = 10\,240 + 10\,240 = 20\,480 \tag{A1}$$

The ratio is (A1)

$$\frac{525\,312}{20\,480} = 25.65$$

so the heap performs about 25.6 times fewer steps on this workload.

(b) For the sorted array, an insertion has to find the insertion point and shift the items above it, which costs $m/2 = 512$ steps, while an extraction takes the item at the front and costs 1 step (M1):

$$1024 \times 512 + 1024 \times 1 = 524\,288 + 1024 = 525\,312 \tag{M1}$$

which is the same total as the unsorted array (A1).

The two totals agree because the two structures pay the same linear cost the same number of times, in opposite phases (A1). The unsorted array does nothing to maintain order on insertion and pays for the disorder on every extraction; the sorted array pays for the order on every insertion and collects it back for free on every extraction. With $n$ insertions and $n$ extractions the two phases have equal length, so the cost simply changes place. The equality is a property of this workload and not of the structures: if the workload were 1024 insertions and 10 extractions, the sorted array would be far more expensive, and if it were 1024 insertions and 1024 extractions of a *known* minimum the unsorted array's scan could be avoided altogether.

(c) With $k$ extractions the unsorted array costs (M1)

$$1024 + 512k$$

and the heap costs (M1)

$$10\,240 + 10k$$

Setting them equal (M1):

$$1024 + 512k = 10\,240 + 10k \quad\Longrightarrow\quad 502k = 9216 \quad\Longrightarrow\quad k = \frac{9216}{502} = 18.36 \text{ (to 2 d.p.)}$$

Since $k$ counts extractions it must be a whole number, so the crossover lies between 18 and 19 (A1). Substituting both:

| $k$ | unsorted array | binary heap | cheaper |
|---|---|---|---|
| 18 | $1024 + 9216 = 10\,240$ | $10\,240 + 180 = 10\,420$ | unsorted array |
| 19 | $1024 + 9728 = 10\,752$ | $10\,240 + 190 = 10\,430$ | binary heap |

So the largest $k$ for which the unsorted array is still cheaper is 18, and the smallest $k$ at which the heap is cheaper is 19 (A1). The threshold is about 1.8% of $n$: unless the structure is drained of more than roughly one item in fifty, the array wins.

(d) The statement "$O(\log n)$ beats $O(n)$" compares how the cost of each structure *grows* as $n$ increases without bound, and it is true. It says nothing about which is cheaper at a particular $n$, and it says nothing at all when the mixture of operations is allowed to vary (M1). Here $n$ is fixed at 1024 and the number of extractions is the free variable, so the comparison has to be made at a point rather than in the limit (M1).

The reason the limit is misleading in this case is that the heap's advantage is paid for in advance. It commits 10 steps to each of the 1024 insertions, which is 10 240 steps before a single extraction has happened, whereas the unsorted array has spent only 1024. The array's expensive operation is the one that may never occur in large numbers, and the heap's expensive operation is the one that always occurs (A1). An argument from complexity classes cannot see either of those facts, because both of them are about the workload rather than about the growth rate.

Markscheme notes

(a) (M1) for the two cost expressions, (M1) for the unsorted total, (M1) for the heap total, (A1) for the ratio 25.6. Accept 25.65 or 25.7; do not accept a bare "about 25 times" without the two totals shown, because the part asks for them.

(b) (M1) for charging the sorted array's insertion at 512 and its extraction at 1, (M1) for the total, (A1) for the equality with (a), (A1) for the explanation that the linear cost is paid the same number of times in the opposite phase. The explanation mark requires the observation that the two phases are of equal length here; a candidate who says only "the costs cancel" has not said why they cancel.

(c) (M1) for the unsorted cost expression in $k$, (M1) for the heap expression, (M1) for equating them and solving, (A1) for the non-integer value 18.36 and the observation that $k$ must be an integer, (A1) for 18 and 19 with the substitution shown. A candidate who answers "18.36 extractions" without rounding down has not answered a question about a count and loses the final mark. Follow-through applies from an incorrect (a).

(d) (M1) for the observation that the complexity class describes growth rather than a point, (M1) for identifying the number of extractions as the variable that governs, (A1) for the point that the heap pays its logarithmic cost on the insertions that may be the whole workload. A candidate who merely repeats the crossover value from (c) without saying why the asymptotic argument cannot find it earns no marks here.

Forfeits: comparing $O(\log n)$ with $O(n)$ at $n = 1024$ and concluding that the heap is 102 times faster, which is a category error rather than a rounding error; treating the heap's cost as $\log_2 n$ for the whole workload rather than per operation, which gives 10 steps in total. Condonation: a candidate who writes the heap cost as $2n\log_2 n$ but uses it consistently should be given full follow-through credit, since the model's convention is stated rather than derived.

Why this question is hard

This item is about a mistake that survives because the statement behind it is true. "A binary heap is $O(\log n)$ per operation and an unsorted array is $O(n)$" is not an approximation or a simplification; it is correct, and it is the reason heaps exist. The student's error is not in the mathematics but in the belief that a correct asymptotic statement answers a question about a finite workload with a particular mixture of operations. Complexity classes describe the shape of a curve as its argument grows; they do not compare two points on it.

The item is built so that the student has to do the comparison twice, once where the heap wins by a wide margin and once where it loses, and the two answers have to come from the same arithmetic. Part (a) makes the heap look obviously right, part (b) shows that the two arrays tie, and part (c) asks for the threshold. By the time the threshold appears -- eighteen extractions against nineteen -- the claim in the stem has already been dismantled, because a structure that loses to the naive one until it is drained of nearly two percent of its contents is not the structure the complexity class recommends.

The conceptual content is the idea that the operation *mixture* is part of the specification of a data structure choice, and that it is usually the part that is left unwritten. A priority queue is described by its operations, and any real use of one weights those operations very unevenly. A scheduler that inserts thousands of jobs and extracts a handful of the most urgent ones is a different problem from one that drains the queue as fast as it fills, and the same abstract type is the right answer to both -- while the same implementation is not.

The item also rewards the student who notices that the tie in part (b) is not a coincidence. Two structures with opposite cost profiles produce the same total exactly when the workload is symmetric between the cheap and the expensive operation, and recognising that symmetry is what makes part (c) tractable: once the total is understood as "a fixed cost plus a per-extraction cost", the crossover is one linear equation. The final part then asks the student to say out loud why the asymptotic argument could not have found it, which is the step that turns a calculation into a principle.

Challenge lever
The complexity class of an operation is a statement about the limit as the size grows, at a fixed mixture of operations. The question here fixes the size and varies the mixture, which is the opposite arrangement, so the asymptotic ranking is not the ranking that answers the question. A heap commits $\log_2 n$ steps to every insertion, including the 1024 insertions that the unsorted array performs in one step each, and those committed steps have to be earned back by the extractions before the heap can be ahead. The variable that governs the answer is the number of extractions, and it is not named in the question.
