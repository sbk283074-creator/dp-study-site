B2.4 The same loop taking twelve iterations on one three-digit pair and two on another, and the worst case that has to be derived

Question

The figure shows two traces of the same function, which is written below. Division is integer division and MOD returns the remainder.

FUNCTION f(a, b)
WHILE b > 0 DO
t = a MOD b
a = b
b = t
END WHILE
RETURN a
END FUNCTION

One iteration means one execution of the loop body. For the input a = 377, b = 233 the loop body is executed twelve times and the successive pairs of values are listed in the figure. For the input a = 1000, b = 3 the loop body is executed twice. Both inputs are three-digit numbers, and neither of the two inputs is noticeably harder to read than the other.

(a) State the value returned by the function for the input a = 377, b = 233, and state the value returned for the input a = 1000, b = 3.

(b) Explain what property of the pair (a, b) determines how many iterations the loop performs, and explain why the number of digits in a and b does not determine it.

(c) Determine the largest number of iterations the loop can perform for any input pair with 1 <= b <= a <= 1000, and state a pair of values that achieves it. Justify your answer in terms of the sequence of remainders.

Reveal the answer

(a) The loop returns the last non-zero value of b before the remainder reaches zero, which is the largest integer that divides both of the original inputs. For a = 377 and b = 233 the figure ends at the pair (1, 0), so the value returned is 1 (A1). For a = 1000 and b = 3 the pairs are (3, 1) and (1, 0), so the value returned is also 1 (A1). Both inputs therefore produce the same answer, and the number of iterations differs by a factor of six.

(b) The number of iterations is set by how quickly the pair of values shrinks, and that is set by the size of the quotient produced at each step. When a is much larger than b the first remainder is small, so the pair collapses in a step or two: at a = 1000, b = 3 the quotient is 333 and the remainder is 1, and the loop is over almost immediately (M1). When a is only slightly larger than b the quotient is 1 and the remainder is a minus b, so the pair (a, b) becomes (b, a minus b) and shrinks by only a small factor each time; in the trace for 377 and 233 every quotient is 1 and the values fall by the golden ratio, 377 to 233 to 144 to 89 and so on, which is the slowest shrinkage the loop can produce (A1). The number of digits is not the governing quantity because it only bounds how many halvings are available, and the actual count is usually far below that bound: two inputs of three digits can need two iterations or twelve, and the deciding factor is the ratio of the two numbers and how close the quotients come to 1, not how large the numbers are.

(c) The largest number of iterations is 14, attained by a = 987 and b = 610 (A1). The justification runs backwards through the loop. If the pair (a, b) with a greater than b takes n iterations, then after one iteration it becomes (b, a MOD b) and that pair takes n minus 1 iterations, so the smallest pair needing n iterations is obtained by making the quotient 1 at every step, which gives the backward recurrence a = b + c where c is the next value in the sequence (M1). Starting from the smallest possible end, the pair (1, 0), and reversing the rule gives (1, 1), (2, 1), (3, 2), (5, 3), (8, 5) and so on: the Fibonacci sequence, in which the largest value is 987 at the sixteenth term. If a pair takes 14 iterations then its larger member is at least 987, so any pair with both values at most 1000 that needs 14 iterations must sit exactly at 987 and 610, and 15 iterations would require a larger member of at least 1597, which is above the limit. Checking the two candidates confirms it: the pair (987, 610) takes 14 iterations, while the pair (1000, 999) takes 2 and the pair (233, 144) takes 11 (A1). The same argument explains why the trace in the figure is the slow case for its size: 377 and 233 are the fourteenth and thirteenth Fibonacci numbers, so they are the worst pair below 400, and scaling them up to 987 and 610 keeps them the worst pair below 1000.

Markscheme notes

(a) (A1) for 1 from the first input, with the final pair (1, 0) identified; (A1) for 1 from the second. The second mark is for the second value as well as the statement that both answers agree; a candidate who writes only one value scores at most one mark. Do not accept a candidate who reads the returned value as the number of iterations.

(b) (M1) for the observation that the size of the quotient at each step sets how fast the pair shrinks, with the contrast between a large quotient and a quotient of 1; (A1) for the statement that the count is fixed by the ratio of the inputs and how close the successive quotients come to 1, and that the number of digits only gives an upper bound that is usually not attained. A candidate who says only that the algorithm is logarithmic, or that larger inputs take longer, does not answer the question and scores nothing: the figure shows the larger inputs taking the fewer iterations.

(c) (A1) for 14 as the maximum; (M1) for the backward recurrence with a quotient of 1 at every step, from which the Fibonacci sequence follows; (A1) for 987 and 610 as an attaining pair, together with the check that 15 iterations would need a value above 1000. Accept 377 and 233 as the attaining pair for a limit of 400 if stated as such, but for a limit of 1000 the answer is 987 and 610. A candidate who gives 14 without deriving it, or who gives the number of digits as the bound, loses the middle mark.

Why this question is hard

The trap in this item is a slogan that is true. The loop is logarithmic in the size of its inputs, the syllabus says so, and every candidate will write it down. What the slogan does not do is predict anything about a particular pair, and the figure supplies two pairs of the same size whose costs differ by a factor of six and whose answers are identical. So the candidate has to abandon the slogan and look at what the loop actually does to the numbers.

What it does is replace (a, b) by (b, a MOD b). The size of the second value after one iteration is a MOD b, which is the remainder that is left after removing as many copies of b as will fit. If b is small compared with a the quotient is large and the remainder is small, so the pair drops by a large factor immediately; that is the 1000 and 3 case, where the quotient is 333 and the pair goes straight to (3, 1). If b is close to a the quotient is 1 and the remainder is a minus b, so the pair only slides along by the difference; that is the Fibonacci case, and its slow rate is the golden ratio, which is the slowest rate any pair can achieve. Quoting a logarithm hides all of this because a logarithm is a bound and the question is about actual counts.

The worst case is worth deriving because the derivation is a single reversal of the loop. Ask instead which pair is the smallest that can need a given number of iterations, and the answer is forced: to need many iterations from as small a starting point as possible, every quotient has to be 1, which means each pair is built from the next by adding, which is exactly the Fibonacci recurrence. The worst pair below a limit is therefore the largest pair of consecutive Fibonacci numbers below it, and for 1000 that is 987 and 610. The trace in the figure is the same phenomenon one scale down, which is a useful thing to notice: the answer to a worst-case question about an algorithm is often sitting visibly in the example that was chosen to illustrate the algorithm, if the example is chosen honestly.

There is one further general point. The number of digits is a convenient proxy for the cost of an algorithm when the cost really does depend on magnitude, and it is a misleading one whenever the cost depends on structure instead. Here the three-digit number 999 paired with 1000 costs two iterations and the three-digit pair 987 and 610 costs fourteen. Two inputs of the same length, seven times the work, decided entirely by how the numbers relate to each other rather than by how big they are.

Challenge lever
Every candidate has been told that this loop is logarithmic and that the cost therefore depends on the size of the inputs, and both statements are true in the way that makes them useless here. Two pairs of three-digit numbers differ by a factor of six in the number of iterations, so the size of the inputs plainly is not what sets the cost, and quoting a logarithm does not produce the twelve or the two. The quantity that sets the cost is how quickly the remainders shrink, and the slowest possible shrinking happens when every quotient is one, which forces the pair to be consecutive terms of the Fibonacci sequence. That gives the worst case as a derived number rather than a quoted one: the largest input that can still take n iterations is a Fibonacci number, so the maximum for inputs up to a thousand is fourteen iterations, attained at 377 and 233 scaled up to 987 and 610. The figure is constructed so that the slow pair and the fast pair have the same number of digits and the same answer, which removes both the size of the inputs and the value returned as ways of explaining the difference.
