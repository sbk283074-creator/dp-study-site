A1.3 Operating systems and control systems

Computer science HL · CS-P2-004

Theme A: Concepts of computer scienceA1.3 Operating systems and control systems (A1.3.4 resource management, deadlock), A2.1 Network fundamentalsP216 marksdifficulty 5technology: allowedExplainConstructCalculateEvaluate

Parcel packing cells

A fulfilment centre runs four identical packing cells. Each cell processes one parcel per cycle of 45 s. Every parcel must pass through three shared resources, each of which can serve only one cell at a time: a labelling arm, a weighbridge and a dispatch chute. A cell claims the resources one at a time as its control program reaches each stage, holds every resource it has already claimed while it waits for the next, and releases them all only when the parcel has been dispatched. The three resources are attached to the site network so that any cell can request any of them. The centre currently achieves 320 parcels per hour when nothing goes wrong. On average, once in every 40 cycles the four cells deadlock: each holds one or two resources and waits for one held by another. There is no detection, so the deadlock persists until a supervisor notices the queue, walks to the cell, and performs a manual reset taking 6 minutes, which also discards the four parcels in flight. You have been asked to review the design.

Question

Using the case study, answer all four parts. The four cells are named C1 to C4 and the three resources are L (labelling arm), W (weighbridge) and D (dispatch chute).

  1. [4 marks](a)

    Explain, with reference to each of the four conditions required for deadlock, why this system deadlocks. Your answer must name all four conditions and show that each is present.

    (Explain)
  2. [5 marks](b)

    Construct a resource-allocation scheme that makes deadlock impossible. State the rule, show that it removes at least one of the four conditions you identified, and explain what has to change in the control program of each cell.

    (Construct)
  3. [4 marks](c)

    Calculate the average throughput of the centre in parcels per hour given the current deadlock rate, and hence the percentage of capacity lost. Show your working.

    (Calculate)
  4. [3 marks](d)

    An engineer proposes instead to leave the resource requests unchanged and to add a timeout: any cell waiting more than 20 s releases everything it holds, waits 5 s and starts the parcel again. Evaluate this proposal against your scheme in (b).

    (Evaluate)

Total: 16 marks. Try the question before revealing anything below.

Reveal the answer

(a) All four Coffman conditions hold.

*Mutual exclusion:* each of L, W and D can serve only one cell at a time, so the resources are non-sharable. (A1)

*Hold and wait:* a cell that has claimed the labelling arm keeps it while it waits for the weighbridge, so processes hold resources while requesting others. (A1)

*No pre-emption:* nothing in the system can take a resource away from a cell; the only way resources are released is by the cell finishing, which is exactly what it cannot do. (A1)

*Circular wait:* with four cells and three resources a cycle is easy to form, for example C1 holds L and wants W, C2 holds W and wants D, and C3 holds D and wants L. Because each cell requests resources in whatever order its stage is reached, and the stages differ between parcels, no ordering prevents that cycle from forming. (A1)

(b) Impose a global ordering on resource acquisition: assign each resource a fixed rank, say L = 1, W = 2, D = 3, and require every cell to request resources in strictly increasing rank order, never requesting a lower-ranked resource while holding a higher-ranked one. (M1)(A1)

This removes the circular-wait condition. (A1) A cycle would require each participant to hold a resource and wait for one of lower or equal rank; since ranks strictly increase along any wait chain, the chain cannot close. Formally, in any cycle the ranks would have to satisfy $r_1 < r_2 < \dots < r_k < r_1$, which is impossible. (A1)

The control program must change in two ways: each cell must determine the full set of resources its parcel will need before claiming any of them, and must then claim them in rank order. Where a parcel genuinely needs them in a different order, the cell must claim all three up front and hold them for the whole cycle, which reduces concurrency but is safe. (A1)

(c) Without deadlock the centre does $4 \times \dfrac{3600}{45} = 320$ parcels per hour. (A1)

In 40 cycles the four cells process $4 \times 40 = 160$ parcels, taking $40 \times 45 = 1800\ \mathrm{s}$. One deadlock adds a 6-minute ($360\ \mathrm{s}$) reset, so 160 parcels take $1800 + 360 = 2160\ \mathrm{s}$. (M1)(A1)

$$\text{throughput} = \frac{160}{2160} \times 3600 = 266.7 \approx 267\ \mathrm{parcels\,h^{-1}}$$ (A1)

$$\text{loss} = \frac{320 - 267}{320} \times 100\% = 16.7\%$$

(d) The timeout does not prevent deadlock; it detects and breaks it. (A1) That is better than an indefinite hang, but it is worse than prevention in three respects. First, every near-deadlock costs 20 s of waiting plus a 5 s backoff plus the wasted work already done on the parcel, so each event costs at least 25 s of cell time against 0 s under ordering. Second, if all four cells time out together and restart together they are likely to re-form the same cycle, an effect known as livelock, which the proposal does nothing to prevent since there is no randomised backoff. (A1) Third, the parcels are discarded either way, so the material loss is unchanged. (A1)

By contrast the ordering scheme in (b) eliminates the events entirely, at the cost of holding all three resources for some parcels and so losing some concurrency. A reasonable evaluation is therefore that the timeout is an acceptable safety net to keep in place, but it should not be the primary mechanism: prevention should be used first and detection second.

Markscheme notes

(a) Award one mark for each condition correctly named and shown to be present; a candidate who names all four but does not apply them to this system earns at most two. The circular-wait mark is the one most often missed and requires an explicit example of a cycle. (b) Accept any consistent global ordering, not necessarily L-W-D, provided the rule is stated as a total order and the reasoning about cycles is given. A candidate who proposes requesting all resources at once (simultaneous acquisition) is also acceptable and should be credited equivalently, since it removes the hold-and-wait condition instead; note in that case that utilisation falls. The final mark is for identifying the change to the control program, which is the practical consequence and is frequently omitted. (c) Accept 266 to 267 parcels per hour and a loss between 16% and 17%. Award the method mark for converting the deadlock rate into an amortised time penalty; a candidate who simply subtracts 6 minutes per hour has the wrong model. (d) The key distinction is prevention versus detection, and candidates who conflate them should not earn the first mark. Credit the livelock observation even if the term is not used, provided the idea that simultaneous restart recreates the cycle is stated. There is no single right conclusion, so award the final marks for a judgement supported by the analysis given.

Why this question is hard

Deadlock is one of the few topics in the syllabus where the correct answer is a property of the whole system rather than of any single piece of code. No individual cell's control program is wrong: each one claims a resource, uses it, and later asks for another. The fault is the absence of a global rule, which is why the question asks for all four Coffman conditions explicitly. Naming them is not rote learning here; it is the diagnostic that tells you which one is cheapest to remove. Mutual exclusion cannot be removed, because a weighbridge genuinely cannot serve two parcels at once. Hold-and-wait can be, by claiming everything up front, but that costs concurrency. Circular wait is the cheapest to break, because imposing an order on requests costs nothing in throughput and requires only that the program decide its requirements in advance.

The quantification in (c) is there to make the cost concrete, and the result is larger than most students expect: one deadlock every forty cycles costs a sixth of the centre's output, because a six-minute reset is eight full cycles lost. That reframes the decision. A fix that costs a little concurrency on every cycle is clearly worth buying against a one-in-forty chance of losing eight cycles.

Part (d) is where the question discriminates. Adding a timeout feels like a fix and is not one: it converts a permanent hang into a recurring 25-second penalty and, because all four cells are running the same cycle time and will therefore tend to time out together, it risks livelock where the system makes no progress at all despite no process being blocked. The mature answer is that prevention and detection are complementary, and that the ordering scheme should be primary with the timeout retained as a backstop. Recognising that a mechanism which breaks a deadlock is not the same as one that prevents it is the transferable idea.
