B2.4 An algorithm that is correct except for one class of input: the final run is never recorded

Computer science HL · CS-B2.4-002

Theme B: Computational thinking and problem-solvingB2.4 Programming algorithms and B2.3 Programming constructsP1 · Section B16 marksdifficulty 4technology: not allowedDetermineExplainConstructEvaluate

Question

A programmer writes the following method to find the length of the longest run of identical adjacent values in a one-dimensional array $A$ of $N$ integers, where $N \geq 1$. The array is indexed from $0$ to $N - 1$.

LONGEST = 0
CURRENT = 1
loop I from 1 to N - 1
    if A[I] = A[I - 1] then
        CURRENT = CURRENT + 1
    else
        if CURRENT > LONGEST then
            LONGEST = CURRENT
        end if
        CURRENT = 1
    end if
end loop
return LONGEST

The programmer tests the method on the array $[3, 3, 1, 1, 1, 2]$ and obtains $3$, which is correct.

  1. [4 marks](a)

    Determine the value returned by the method for each of the following arrays.

    (i) $[4, 4, 4]$

    (ii) $[5]$

    (iii) $[2, 7, 7]$

    (iv) $[9, 9, 6, 6, 6]$.

    For each array, state also the value the method should return.

    (Determine)
  2. [4 marks](b)

    Identify the two classes of input for which the method returns a value that is too small, and explain, by reference to the pseudocode, why each occurs.

    (Explain)
  3. [4 marks](c)

    Rewrite the method so that it returns the correct value for every array of length $N \geq 1$. Your answer must be given in the same pseudocode style, and you must state what you changed.

    (Construct)
  4. [4 marks](d)

    A second programmer suggests correcting the method by changing the first line to LONGEST = 1 and making no other change.

    Evaluate this suggestion: state whether it produces the correct answer for every array, and support your answer either by explaining why it works or by giving a specific counter-example and tracing it.

    (Evaluate)

Total: 16 marks. Try the question before revealing anything below.

A programmer writes the following method to find the length of the longest run of identical adjacent values in a one-dimensional array $A$ of $N$ integers, where $N \geq 1$. The array is indexed from $0$ to $N - 1$. ``` LONGEST = 0 CURRENT = 1 loop I from 1 to N - 1 if A[I] = A[I - 1] then CURRENT = CURRENT + 1 else if CURRENT > LONGEST then LONGEST = CURRENT end if CURRENT = 1 end if end loop return LONGEST ``` The programmer tests the method on the array $[3, 3, 1, 1, 1, 2]$ and obtains $3$, which is correct. (a) Determine the value returned by the method for each of the following arrays. (i) $[4, 4, 4]$ (ii) $[5]$ (iii) $[2, 7, 7]$ (iv) $[9, 9, 6, 6, 6]$. For each array, state also the value the method should return. [4 marks] (Construct) (d) A second programmer suggests correcting the method by changing the first line to `LONGEST = 1` and making no other change. Evaluate this suggestion: state whether it produces the correct answer for every array, and support your answer either by explaining why it works or by giving a specific counter-example and tracing it. [4 marks] (Evaluate)
Reveal the answer

(a)(i) The loop runs for $I = 1$ and $I = 2$. At $I = 1$, $A[1] = A[0]$ so $CURRENT = 2$; at $I = 2$, $A[2] = A[1]$ so $CURRENT = 3$. The loop ends with $LONGEST = 0$, so the method returns 0; the correct value is 3 (A1).

(a)(ii) The loop runs from $1$ to $0$, which is empty, so it never executes and the method returns 0; the correct value is 1, since a single element is a run of length one (A1).

(a)(iii) At $I = 1$, $A[1] = 7 \neq A[0] = 2$, so $CURRENT = 1 > LONGEST = 0$ gives $LONGEST = 1$ and $CURRENT$ resets to $1$; at $I = 2$, $A[2] = A[1]$ so $CURRENT = 2$. The loop ends and the method returns 1; the correct value is 2 (A1).

(a)(iv) At $I = 1$, $A[1] = A[0]$ so $CURRENT = 2$; at $I = 2$, $A[2] \neq A[1]$, so $LONGEST = 2$ and $CURRENT = 1$; at $I = 3$ and $I = 4$, $CURRENT$ becomes $2$ then $3$. The loop ends and the method returns 2; the correct value is 3 (A1).

(b) The two classes are:

Arrays of length 1. With $N = 1$ the loop from 1 to N - 1 runs from $1$ to $0$, which is empty, so $LONGEST$ keeps its initial value of $0$ and the method returns $0$ instead of $1$ (A1).

Arrays whose longest run ends at the final element. The variable $CURRENT$ is only ever compared with $LONGEST$ inside the else branch, that is, at the moment a run is discovered to have ended (A1). The run that is still in progress when the loop finishes is never compared with anything (A1). So whenever the longest run is the last one -- as in (i), (iii) and (iv) -- the method reports the longest run it happened to close off, or $0$ if it closed off none (A1).

The programmer's test array $[3, 3, 1, 1, 1, 2]$ is misleading: its longest run of three $1$s ends at index $4$ and is closed off by the $2$ at index $5$, so the defect is invisible.

(c) One correct version compares $CURRENT$ with $LONGEST$ once more after the loop has finished:

if N = 0 then
    return 0
end if
LONGEST = 1
CURRENT = 1
loop I from 1 to N - 1
    if A[I] = A[I - 1] then
        CURRENT = CURRENT + 1
    else
        CURRENT = 1
    end if
    if CURRENT > LONGEST then
        LONGEST = CURRENT
    end if
end loop
return LONGEST

The essential change is that the comparison with $LONGEST$ is moved outside the else branch so that it happens on every iteration, including the last (A1). With that change $CURRENT$ is compared after every element is processed, so the run in progress at the end of the loop is included (A1). Initialising $LONGEST = 1$ rather than $0$ handles $N = 1$ (A1), and the guard for $N = 0$ keeps the method defined if the problem statement is ever relaxed (A1).

Alternative correct answers are acceptable, for example initialising $LONGEST = 1$ and appending a single if CURRENT > LONGEST then LONGEST = CURRENT after end loop. Credit the version a candidate gives if it is correct for $N = 1$ and for a final-run array.

(d) The suggestion does not work in general (A1). It does fix the $N = 1$ case: the loop is empty and the method returns $1$, which is correct (A1). It does nothing for the final-run case. Take $A = [4, 4, 4]$ (A1). With $LONGEST = 1$: at $I = 1$, $A[1] = A[0]$ so $CURRENT = 2$ and the else branch is not taken; at $I = 2$, $A[2] = A[1]$ so $CURRENT = 3$, again without the else branch. The loop ends and the method returns $LONGEST = 1$, but the longest run is $3$ (A1).

The lesson is that the two defects have different causes and need different fixes. The $N = 1$ case is an initialisation defect; the final-run case is a structural one, and no choice of initial value can repair an algorithm that never performs the comparison it needs.

Markscheme notes

(a) Award (A1) for each row, both the returned value and the correct value. Accept a brief trace in place of an explanation. No penalty for using 1-based indexing consistently, provided the trace matches the candidate's stated convention.
(b) Award (A1) for the length-1 case with a reason that refers to the loop bounds; (A1) for noticing that the comparison is inside the else branch; (A1) for stating that the in-progress run at the end of the loop is never compared; (A1) for characterising the failing inputs as those whose longest run ends at the final element. A candidate who identifies only 'arrays ending in a run' without the length-1 case earns at most three of the four marks.
(c) Award (A1) for moving the comparison so it executes on every iteration or appending it after the loop, (A1) for handling N = 1 correctly, (A1) for a correct initialisation, (A1) for stating clearly what was changed or for presenting valid pseudocode. Do not penalise the absence of an N = 0 guard, since the question specifies N >= 1; credit it if present.
(d) Award (A1) for stating that it does not work in general, (A1) for acknowledging that it does fix N = 1, (A1) for a specific counter-example, (A1) for a correct trace of that counter-example. A candidate who says only 'it does not work' without a counter-example earns at most two marks. Accept any counter-example whose longest run is its last.

Why this question is hard

This is a defect that survives casual testing, which is the only kind of testing most candidates do. The programmer in the stem tests one array and gets the right answer -- not by luck, but because that array's longest run happens to be followed by a different value. Almost any hand-picked test array will behave that way, because a run that ends at the very last element feels like a special case when it is in fact one of the two things that can go wrong.

The structural point is about where the update lives. The variable $CURRENT$ is only compared with $LONGEST$ at the moment a run is *discovered to have ended*, and a run that ends because the array ends is never discovered to have ended at all. There is no event for it. That is why the fix is not a tweak to the initial conditions but a change to where the comparison sits: it has to happen on every iteration, or once more after the loop, and either choice works.

Part (d) is where the two defects get separated, and it is the part that most candidates get wrong in an instructive way. Changing the initial value genuinely does fix the length-1 case, so the suggestion is not obviously bad -- it is half right. Recognising that it is half right, and that the other half cannot be fixed by any initial value, is a stronger claim than simply calling the suggestion wrong. The counter-example does the rest: $[4, 4, 4]$ returns $1$ when the answer is $3$, and there is nothing about the initialisation that could change that.
