A1.2 Overflow in a two's-complement subtraction used as a comparison

Computer science HL · CS-A1.2-002

Theme A: Concepts of computer scienceA1.2 Data representation and computer logic (binary representation of integers; two's complement; overflow)P1 · Section B16 marksdifficulty 4technology: not allowedExplainDetermineStateJustify

Question

An environmental control system stores each temperature reading as an eight-bit signed
integer in two's complement form, so the representable range is $-128$ to $127$. The system
compares two readings, $a$ and $b$, using the single line

if a - b < 0 then output "a is the lower reading"

and the subtraction is performed in eight bits, with no overflow detection.

(a) Explain what happens when the line is executed with $a = 100$ and $b = -50$, and state the
value the system compares with zero. \tag{3}

(b) Determine the range of values of the true difference $d = a - b$ for which the comparison
gives the correct result. \tag{4}

(c) Determine the number of ordered pairs $(a, b)$, with $a$ and $b$ each in the range
$-128$ to $127$, for which the comparison gives the wrong result, and hence the proportion of
all pairs that fail. \tag{5}

(d) State a comparison that is correct for every pair in the range, and justify it. \tag{4}

  1. [3 marks](a)

    Explain what happens when the line is executed with $a = 100$ and $b = -50$, and state the value compared with zero.

    (Explain)
  2. [4 marks](b)

Reveal the answer

(a) The true difference is $100 - (-50) = 150$ (A1). Eight-bit two's complement can only
represent $-128$ to $127$, so $150$ cannot be stored; the value wraps by subtracting $256$ and
the system obtains $150 - 256 = -106$ (M1). Since $-106 < 0$ the system reports that
$a$ is the lower reading, which is wrong: $100 > -50$ (A1).

The general rule is that a result outside the representable range has $256$ added to or
subtracted from it until it falls inside, which is exactly what modular arithmetic does. No
flag is raised and no exception is thrown, so the error is invisible at run time.

(b) The comparison is correct exactly when the subtraction does not overflow, that is when the
true difference is itself representable (M1):

$$-128 \le a - b \le 127 \tag{A1}$$

Equivalently $-128 \le d \le 127$ (A1). Outside that interval the stored value differs from the
true difference by a multiple of $256$ and, because the magnitude of the correction is larger
than the magnitude of the value being represented, the sign is reversed (A1). For example
$d = 150$ is stored as $-106$, and $d = -150$ is stored as $+106$; in both cases the sign is
wrong and so is the comparison.

(c) For a given difference $d$, the number of ordered pairs with $a - b = d$ and both values
in $[-128, 127]$ is $256 - |d|$, valid for $-255 \le d \le 255$ (M1). Summing over the correct
range from part (b),

$$N_{\text{correct}} = \sum_{d=-128}^{127} (256 - |d|) = 24512 + 256 + 24384 = 49152 \tag{A1}$$

The total number of ordered pairs is (A1)

$$N_{\text{total}} = 256 + \sum_{d=-255}^{255} (256 - |d|) - 256 = \sum_{d=-255}^{255}(256-|d|) = 65536$$

so the number that fail is (A1)

$$N_{\text{wrong}} = 65536 - 49152 = 16384 \tag{A1}$$

and the proportion is $\dfrac{16384}{65536} = 0.25$: exactly one quarter of all comparisons
give the wrong answer.

(d) Compare the signs first, and subtract only when the signs match (M1):

if (a < 0) and (b >= 0) then output "a is the lower reading"
else if (a >= 0) and (b < 0) then output "a is the higher reading"
else if a - b < 0 then output "a is the lower reading"
else output "a is the higher reading"

Justification (A1): if the signs differ, the comparison is settled by the signs alone and no
subtraction is needed, which is precisely the case in which the true difference is largest and
the subtraction most likely to overflow. If both values are non-negative then
$a - b$ lies between $-127$ and $127$; if both are negative then $a - b$ also lies between
$-127$ and $127$ (A1). In either case the result is representable, so the subtraction cannot
overflow and the test is safe (A1).

An alternative correct answer is to widen the stored type before subtracting — for example by
promoting both operands to sixteen bits — since the difference of two eight-bit values always
fits in nine bits. This is simpler but costs memory in a system that stores thousands of
readings, which is why the sign test is preferred here.

Markscheme notes

(a) (A1) for the true difference $150$. (M1) for the wrap-around, which must be explained
as a modular reduction rather than merely asserted. (A1) for $-106$ and the conclusion that the
output is wrong.

(b) (M1) for linking correctness to the absence of overflow. (A1) for the interval
$-128 \le d \le 127$. (A1) for restating it in terms of $d$. (A1) for noting that the sign is
reversed outside the interval — a candidate who gives the interval alone has not explained why
the comparison then fails.

(c) (M1) for $256 - |d|$ as the count for a given difference. (A1) for $49152$ correct pairs.
(A1) for $65536$ total pairs. (A1) for $16384$ failing pairs. (A1) for the proportion $0.25$.
Credit any correct route to the count, including a direct enumeration argument, but the
summation must be shown rather than asserted. Condone small arithmetic slips in the partial
sums if the method is sound and the final proportion is consistent with them.

(d) (M1) for a comparison that avoids the subtraction when the signs differ. (A1) for the
justification in terms of the signs. (A1) for the bound $|a - b| \le 127$ when the signs match.
(A1) for concluding that no overflow is then possible.

Accept the alternative of promoting to a wider type, with full marks, provided the candidate
states that nine bits suffice. Do not accept "check the sign of the result", which does not
work: after the wrap the sign of the stored value is a valid sign, just the wrong one.

Why this question is hard

The bug is a classic and it survives code review, because the line reads like arithmetic
and the arithmetic is correct. The problem is that it is not arithmetic — it is a range
question wearing arithmetic's clothes. The subtraction has to produce a result in eight bits,
and the result of a subtraction of two eight-bit values needs nine.

The reason the failure rate is exactly a quarter is worth seeing rather than taking on trust.
For any particular difference $d$, the number of ordered pairs that produce it is
$256 - |d|$, because the larger the difference the fewer starting values leave room for it.
Summing that over the representable differences gives $49152$ of the $65536$ possible pairs,
and the complement is $16384$, which is exactly one quarter. The figure is not an artefact of
the numbers chosen: it is $\frac{1}{4}$ for any even word length, and getting close to it for
any word length at all.

What makes this dangerous in a control system is the absence of any signal. There is no
exception, no overflow flag that the high-level code checks, and no value that looks wrong. The
program compares $-106$ with zero, correctly concludes that $-106 < 0$, and proceeds. The only
way to find the bug is to reason about the range of the operands, which is exactly what the
question asks for.

The fix in part (d) is worth dwelling on because it is not the obvious one. The obvious fix is
to widen the integer, and that works — nine bits are always enough for the difference of two
eight-bit numbers. But it costs memory in exactly the applications where eight-bit
representation was chosen for compactness, and it is not needed. The sign test costs two
comparisons and removes the problem entirely, because the dangerous case is precisely the case
where the signs differ, and in that case the answer is known without subtracting anything.

More generally, this is the reason comparisons in serious code are written as comparisons
rather than as subtractions. A compiler may or may not be able to prove that a subtraction is
safe; a sign test is safe by construction, and "safe by construction" is worth more than "safe
because the inputs happen to be small".
