Exam technique — the single most expensive habit in Paper 2

Writing pseudocode when the question asked for Java or Python. The exam gives you the pseudocode; your job is to translate it into a real language correctly. B2.1 · Variables, constants and data types

A variable is a named location in memory holding a value that can change. A constant is a named value that must not change after it is set — using one is not decoration; it prevents a whole class of bug and it tells the reader that the number means something.

Python

VAT_RATE = 0.20        # constant by convention: uppercase
name = "Amara"         # str
age = 17               # int
height = 1.68          # float
isPrefect = True       # bool  (capital T)
grade = 'A'            # str of length 1

# Python is dynamically typed: the type travels with the value
print(type(age), type(height))   # <class 'int'> <class 'float'>

# Casting
ageText = input("Age: ")   # input() ALWAYS returns a string
age = int(ageText)         # must cast before arithmetic

Java

final double VAT_RATE = 0.20;   // final = cannot be reassigned
String name = "Amara";
int age = 17;
double height = 1.68;
boolean isPrefect = true;       // lowercase
char grade = 'A';               // single quotes for char, double for String

// Java is statically typed: you declare the type, and it is checked
// at compile time
System.out.println(age + " " + height);

// Casting
String ageText = scanner.nextLine();
age = Integer.parseInt(ageText);   // explicit parse
double avg = (double) total / count;   // cast int to double BEFORE dividing
Trap — integer division

In Python 2 and in Java, dividing two integers gives an integer: 7 / 2 is 3, not 3.5. In Java this is the source of "my average is always 0" — total / count with both int truncates before the assignment promotes it to double. Fix it by casting first: (double) total / count. In Python 3, / always produces a float and // is the integer-division operator — so 7 / 2 is 3.5 and 7 // 2 is 3. Know which language you are writing.

Worked example 1 Types, casting and the MOD/DIV pattern

Question. Write a program that reads a number of seconds and prints it as minutes and seconds.

Python

total = int(input("Seconds: "))
minutes = total // 60          # DIV
seconds = total % 60           # MOD
print(minutes, "min", seconds, "s")

Java

Scanner sc = new Scanner(System.in);
System.out.print("Seconds: ");
int total = sc.nextInt();
int minutes = total / 60;      // int / int = int  (DIV)
int seconds = total % 60;      // remainder        (MOD)
System.out.println(minutes + " min " + seconds + " s");

Sample run.

Seconds: 145
2 min 25 s
  1. 145 // 60 = 2 (the whole number of minutes); 145 % 60 = 25 (the leftover seconds).
  2. The identity that makes this safe: total = (total DIV 60) × 60 + (total MOD 60), i.e. 2 × 60 + 25 = 145.
  3. Check the boundary: 120 seconds → 2 min 0 s ✓; 59 seconds → 0 min 59 s ✓.
Answer: 2 min 25 s. This DIV/MOD pair is the standard way to convert between units, and it also appears whenever you need to split a linear index into (row, column) for a 2-D array: row = index DIV width, column = index MOD width.

B2.3 · Selection and iteration

Python — selection

mark = int(input("Mark: "))

if mark >= 80:
    grade = "A"
elif mark >= 60:      # elif, not "else if"
    grade = "B"
elif mark >= 40:
    grade = "C"
else:
    grade = "Fail"

print("Grade:", grade)

Note: Python has no switch before 3.10 (match); use if/elif chains.

Java — selection

int mark = sc.nextInt();
String grade;

if (mark >= 80) {
    grade = "A";
} else if (mark >= 60) {
    grade = "B";
} else if (mark >= 40) {
    grade = "C";
} else {
    grade = "Fail";
}

System.out.println("Grade: " + grade);

// switch works on int, char, String and enum
switch (grade) {
    case "A" -> System.out.println("Excellent");
    case "B" -> System.out.println("Good");
    default  -> System.out.println("Keep going");
}
Trap — ordering the branches

Both versions above test the highest band first. If you write if mark >= 40 first, a mark of 85 is caught immediately and graded C. The program runs, produces no error, and silently gives the wrong answer — a logic error of the kind discussed on the B1 page. When writing a banding chain, always go from the most restrictive condition to the least.

Iteration: for versus while

How to choose

Use for when you know in advance how many times the loop must run — for every element of an array, for i from 0 to 9, for each character in a string. Use while when the loop continues until something happens and you cannot predict how many iterations that will take — until the user types "quit", until the end of a file, until the guess is right. Choosing while when you have a known count invites the classic bug of forgetting to increment the counter, producing an infinite loop.

Python — iteration

# count-controlled
for i in range(10):        # 0 .. 9
    print(i)

for i in range(1, 11):     # 1 .. 10
    print(i)

for i in range(0, 10, 2):  # 0, 2, 4, 6, 8
    print(i)

# condition-controlled
answer = ""
while answer != "quit":
    answer = input("Command (quit to stop): ")
    print("You typed:", answer)

# do-while equivalent (body runs at least once)
while True:
    n = int(input("Enter 1-10: "))
    if 1 <= n <= 10:
        break              # exit the loop

Java — iteration

// count-controlled
for (int i = 0; i < 10; i++) {
    System.out.println(i);
}

for (int i = 1; i <= 10; i++) {   // 1 .. 10
    System.out.println(i);
}

// enhanced for over an array
for (int value : numbers) {
    System.out.println(value);
}

// condition-controlled
String answer = "";
while (!answer.equals("quit")) {
    answer = sc.nextLine();
    System.out.println("You typed: " + answer);
}

// do-while: body always runs at least once
int n;
do {
    n = sc.nextInt();
} while (n < 1 || n > 10);
Trap — comparing strings with == in Java

== compares references — whether two variables point at the same object — not contents. So if (answer == "quit") is usually false even when the user typed quit, because the literal and the input are different objects. Always use answer.equals("quit"). In Python, == does compare values, so the equivalent trap does not exist — but is in Python is the reference comparison and should almost never be used for strings or numbers.

Worked example 2 IB-style · 6 marks · nested loops and a 2-D grid problem

Question. A 4 × 5 grid holds temperatures. Write a program that fills it from input and prints the row number and value of the hottest cell.

Python

ROWS, COLS = 4, 5
grid = []
for r in range(ROWS):
    row = []
    for c in range(COLS):
        row.append(int(input(f"Row {r}, col {c}: ")))
    grid.append(row)

hottest = grid[0][0]
hotRow = 0
for r in range(ROWS):
    for c in range(COLS):
        if grid[r][c] > hottest:
            hottest = grid[r][c]
            hotRow = r

print("Hottest:", hottest, "in row", hotRow)

Java

final int ROWS = 4, COLS = 5;
int[][] grid = new int[ROWS][COLS];

for (int r = 0; r < ROWS; r++) {
    for (int c = 0; c < COLS; c++) {
        grid[r][c] = sc.nextInt();
    }
}

int hottest = grid[0][0];
int hotRow = 0;
for (int r = 0; r < ROWS; r++) {
    for (int c = 0; c < COLS; c++) {
        if (grid[r][c] > hottest) {
            hottest = grid[r][c];
            hotRow = r;
        }
    }
}
System.out.println("Hottest: " + hottest + " in row " + hotRow);

Sample run with values 12 15 9 20 7 / 22 18 25 11 13 / 5 8 30 2 4 / 19 21 17 6 10:

Hottest: 30 in row 2
  1. The grid is stored row-major: grid[row][column]. Row 2 is the third row, because indexing starts at 0.
  2. The seed value is grid[0][0], not 0 — see the B1 trap; temperatures can be negative.
  3. The outer loop selects the row, the inner loop walks along it, so the cells are visited in reading order.
  4. Total iterations = ROWS × COLS = 20, which is why nested loops over one collection are O(n²) in the number of rows when the grid is square.
Answer: Hottest: 30 in row 2. Marks: 1 for correct nested input loop, 1 for correct nested search loop, 1 for seeding with the first element, 1 for row-major indexing, 1 for correct output, 1 for the index being 0-based (row 2 means the third row). The most common error is writing grid[c][r].

Trap — Python list assignment does not copy

b = a makes both names refer to the same list; changing b changes a. To copy, use b = a[:] or b = list(a). The same trap exists in Java: int[] b = a; copies the reference. Use Arrays.copyOf(a, a.length). This matters enormously in sub-procedures (below) and in the IA, where "my other list changed" bugs can cost hours.

Worked example 3 Two-dimensional array: summing a border

Question. Given a 3 × 4 grid, calculate the sum of the cells on the outer border.

Python

grid = [[2,4,1,7],
        [3,9,5,2],
        [8,1,6,3]]

rows = len(grid)
cols = len(grid[0])
total = 0
for r in range(rows):
    for c in range(cols):
        if r == 0 or r == rows - 1 or c == 0 or c == cols - 1:
            total += grid[r][c]
print("Border sum:", total)

Output: Border sum: 46

  1. Top row: 2+4+1+7 = 14. Bottom row: 8+1+6+3 = 18.
  2. Left column excluding corners: 3. Right column excluding corners: 2.
  3. Total: 14 + 18 + 3 + 2 = 37… let me redo carefully: the condition includes corners once because it is a single if per cell. Top row 14, bottom row 18, middle rows' first column: grid[1][0] = 3; middle rows' last column: grid[1][3] = 2. So 14 + 18 + 3 + 2 = 37.

Java

int[][] grid = {{2,4,1,7},
                {3,9,5,2},
                {8,1,6,3}};
int rows = grid.length, cols = grid[0].length, total = 0;
for (int r = 0; r < rows; r++) {
    for (int c = 0; c < cols; c++) {
        if (r == 0 || r == rows - 1 || c == 0 || c == cols - 1) {
            total += grid[r][c];
        }
    }
}
System.out.println("Border sum: " + total);   // 37
Answer: 37. The condition r == 0 || r == rows-1 || c == 0 || c == cols-1 is the reusable pattern for "is this cell on the edge" — worth memorising, because border and neighbour questions recur. Using and instead of or here is a common slip that counts only the four corners.

Sub-procedures and functions

A sub-procedure performs an action and returns nothing. A function computes and returns a value. The distinction is not stylistic: it tells the reader whether calling it changes anything.

Python

def greet(name):            # procedure: no return
    print("Hello,", name)

def square(x):              # function: returns
    return x * x

def addStudent(students, name):   # list is MUTABLE
    students.append(name)         # so the caller's list changes

roster = ["Ana"]
addStudent(roster, "Bo")
print(roster)          # ['Ana', 'Bo']  — the caller WAS changed

def doubleIt(n):            # int is immutable
    n = n * 2               # rebinds the local name only
    return n

a = 5
doubleIt(a)
print(a)               # 5 — unchanged unless you assign the result

Java

public static void greet(String name) {   // void = no return value
    System.out.println("Hello, " + name);
}

public static int square(int x) {
    return x * x;
}

public static void addStudent(ArrayList<String> list, String name) {
    list.add(name);        // object reference: caller's list changes
}

ArrayList<String> roster = new ArrayList<>();
roster.add("Ana");
addStudent(roster, "Bo");
System.out.println(roster);   // [Ana, Bo]

public static void doubleIt(int n) {
    n = n * 2;             // primitive: local copy only
}
int a = 5;
doubleIt(a);
System.out.println(a);     // 5 — unchanged
Why pass by value versus by reference actually matters

Both languages pass the value of the variable. The subtlety is what that value is. For a primitive (int, double, boolean) or an immutable object (Python's int, str, tuple; Java's String), the value is the data, so the callee gets a copy and cannot affect the caller. For a mutable object (a Python list or dict, a Java array, an ArrayList, any object), the value is a reference — an address — so the callee holds a copy of the address, which still points at the same object. Calling append or .add() on it mutates the caller's object. Reassigning the parameter (students = []) does not, because that only changes what the local copy of the address points at. Knowing which operations mutate and which rebind is the difference between a working program and a mysteriously broken one.

Trap — global variables

A global variable is declared outside any sub-procedure and is visible everywhere. They are dangerous because any part of the program can change them, so when a value is wrong you have no way to know which of twenty places broke it. They also make sub-procedures non-reusable: a function that secretly depends on a global cannot be moved to another program. Use parameters for input, a return value for output, and reserve globals for genuine constants. In Python, note that a function that assigns to a name creates a local variable unless you declare global — which is itself a reason to avoid the pattern.

Worked example 5 IB-style · 6 marks · local scope and parameter passing

Question. State the output of each program and explain the difference.

Python

def mystery(numbers):
    numbers = numbers + [99]     # creates a NEW list, rebinds the local name
    print("inside:", numbers)

values = [1, 2, 3]
mystery(values)
print("outside:", values)
def mystery2(numbers):
    numbers.append(99)           # mutates the SAME list
    print("inside:", numbers)

mystery2(values)
print("outside:", values)
  1. mystery: numbers + [99] builds a new list; assigning it to numbers rebinds the local name. The caller's list is untouched. Output: inside: [1, 2, 3, 99] then outside: [1, 2, 3].
  2. mystery2: append mutates the object that both names refer to. Output: inside: [1, 2, 3, 99] then outside: [1, 2, 3, 99].
  3. The one-word test: does the line assign to the parameter, or call a method on it? Assignment rebinds; a method call mutates.
Answer: mystery → outside [1,2,3]; mystery2 → outside [1,2,3,99]. This exact distinction is examined because it is the single most common misunderstanding of parameter passing. It also explains why a recursive function that passes path + [x] down the recursion is safe from accidental sharing, while one that appends to a shared list must undo the append on the way back.

Recursion

A recursive sub-procedure calls itself. Every correct recursive solution has exactly two parts:

  1. A base case — an input small enough to answer directly, with no further recursive call. This is what stops the recursion.
  2. A recursive case — the problem is restated as a smaller version of itself, so each call moves closer to the base case.
Why Why infinite recursion crashes rather than merely running slowly
  1. Every time a sub-procedure is called, the machine creates an activation record (a stack frame) holding the parameters, the local variables and the return address, and pushes it onto the call stack.
  2. When the procedure returns, its frame is popped and execution resumes where it left off.
  3. The stack occupies a finite region of memory. A recursive call with no base case — or with a base case that is never reached — pushes frame after frame and never pops any.
  4. Eventually the stack region is exhausted and the program fails: Python raises RecursionError: maximum recursion depth exceeded, Java throws StackOverflowError. Both are runtime errors, not syntax errors, and both mean the same thing: your recursion did not terminate.
  5. Hence the rule: before you finish writing a recursive function, identify the base case and argue that each recursive call makes the argument strictly smaller. If you cannot make that argument, the function is wrong.

What it means: recursion is not magic; it is a stack of pending calls, and every recursive function is really an explicit stack that the language maintains for you.

Python — factorial and Fibonacci

def factorial(n):
    if n == 0 or n == 1:      # base case
        return 1
    else:
        return n * factorial(n - 1)   # recursive case

print(factorial(5))    # 120


def fib(n):
    if n == 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fib(n - 1) + fib(n - 2)

print(fib(6))          # 8

Java — factorial and Fibonacci

public static int factorial(int n) {
    if (n == 0 || n == 1) {          // base case
        return 1;
    } else {
        return n * factorial(n - 1); // recursive case
    }
}
System.out.println(factorial(5));    // 120


public static int fib(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    return fib(n - 1) + fib(n - 2);
}
System.out.println(fib(6));          // 8
Why naive Fibonacci is a warning, not an example to copy

fib(n) calls fib(n-1) and fib(n-2), and each of those calls both again, so the same values are recomputed an enormous number of times: fib(5) is computed once from fib(6), twice from fib(7), three times from fib(8)… The number of calls grows like the Fibonacci sequence itself, roughly \(O(2^{n})\). Computing fib(40) that way takes minutes; computing it with a loop takes microseconds. This is the standard example of when recursion is the wrong tool: the naive recursive form is beautifully clear and catastrophically slow, because the sub-problems overlap. The fix is memoisation (store each computed value and reuse it), which brings it back to O(n).

How to use it — recursion versus iteration

Use recursion when the problem is naturally self-similar and the sub-problems do not overlap: traversing a tree (B4), computing a factorial, exploring a maze, quicksort and mergesort, parsing nested structures such as JSON or an expression tree. Use iteration when the sub-problems overlap (naive Fibonacci), when the depth could be large enough to risk stack overflow, or when a simple loop states the solution more clearly. Every recursion can be rewritten as a loop with an explicit stack — and sometimes you should.

Question. State the output of the following, and explain what the function computes.

def f(n):

B2.5 · File processing

Four modes matter: read (r), write (w — creates the file or erases it if it exists), append (a — adds to the end, preserving existing content), and read/write. Forgetting the difference between write and append destroys data silently, which is why it is examined.

Python — files

# WRITE (overwrites!)
with open("log.txt", "w") as file:
    file.write("Session start\n")
    file.write("User: ada\n")

# APPEND (preserves existing content)
with open("log.txt", "a") as file:
    file.write("User: bob\n")

# READ all lines into a list
with open("log.txt", "r") as file:
    lines = file.readlines()

for line in lines:
    print(line.strip())     # strip removes the newline

# READ line by line, handling EOF naturally
with open("log.txt") as file:
    for line in file:       # stops at end of file automatically
        print(line.strip())

# Check existence first to avoid an exception
import os
if os.path.exists("log.txt"):
    with open("log.txt") as file:
        print(file.read())

Java — files

// WRITE (overwrites)
try (PrintWriter out = new PrintWriter("log.txt")) {
    out.println("Session start");
    out.println("User: ada");
}

// APPEND (preserves existing content)
try (FileWriter fw = new FileWriter("log.txt", true);
     PrintWriter out = new PrintWriter(fw)) {
    out.println("User: bob");
}

// READ: loop until readLine() returns null, which signals EOF
try (BufferedReader br = new BufferedReader(new FileReader("log.txt"))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line.trim());
    }
} catch (IOException e) {
    System.out.println("Could not read the file: " + e.getMessage());
}

// Check existence first
File f = new File("log.txt");
if (f.exists()) { /* safe to open */ }
Trap — the three file errors that cost marks
  1. Opening with "w" when you meant append. The file is truncated to zero length the moment it is opened. No warning, no undo.
  2. Not closing the file. Data sits in a buffer and may never reach the disk; on some systems you also lock the file against other processes. Python's with and Java's try-with-resources close it automatically even if an exception occurs — always use them.
  3. Ignoring EOF. In Java, readLine() returns null at end of file, so the idiom while ((line = br.readLine()) != null) is both the loop and the EOF test. In Python, iterating a file object with for line in file handles EOF for you — the cleanest form.
Worked example 7 IB-style · 8 marks · read, filter, write

Question. A file marks.txt contains one record per line in the form name,mark. Write a program that reads the file, writes the names of students scoring below 50 to resit.txt, and prints how many there were.

Python

count = 0
with open("marks.txt") as inFile, open("resit.txt", "w") as outFile:
    for line in inFile:
        line = line.strip()
        if line == "":              # skip blank lines
            continue
        name, markText = line.split(",")
        mark = int(markText)
        if mark < 50:
            outFile.write(name + "\n")
            count += 1

print("Students needing a resit:", count)

Java

int count = 0;
try (BufferedReader br = new BufferedReader(new FileReader("marks.txt"));
     PrintWriter out = new PrintWriter("resit.txt")) {

    String line;
    while ((line = br.readLine()) != null) {   // null = EOF
        line = line.trim();
        if (line.isEmpty()) continue;
        String[] parts = line.split(",");
        int mark = Integer.parseInt(parts[1]);
        if (mark < 50) {
            out.println(parts[0]);
            count++;
        }
    }
} catch (IOException e) {
    System.out.println("File error: " + e.getMessage());
}
System.out.println("Students needing a resit: " + count);

Input file.

Dara,31
Eve,88

Output.

  1. Chen scored exactly 50, so mark < 50 is false and Chen is not included — the boundary case that decides whether you need < or <=.
  2. Skipping blank lines prevents a crash on a trailing newline at the end of the file, which is the most common real-world EOF bug.
  3. Both versions open the output with a mode that creates or overwrites, which is correct here because we are producing a fresh report.

Exception handling

An exception is an event that disrupts the normal flow because the program cannot proceed: the file is missing, the input is not a number, the divisor is zero, the index is out of range. Handling it means catching it and doing something sensible instead of crashing.

Python

try:
    age = int(input("Age: "))
    print("Next year you will be", age + 1)
except ValueError:
    print("That was not a whole number.")
except ZeroDivisionError:
    print("Cannot divide by zero.")
except Exception as e:      # last resort only
    print("Unexpected error:", e)
else:
    print("Input accepted.")   # runs if no exception
finally:
    print("Done.")             # always runs

Java

try {
    int age = Integer.parseInt(sc.nextLine());
    System.out.println("Next year you will be " + (age + 1));
} catch (NumberFormatException e) {
    System.out.println("That was not a whole number.");
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero.");
} catch (Exception e) {        // last resort only
    System.out.println("Unexpected error: " + e.getMessage());
} finally {
    System.out.println("Done.");   // always runs
}
Exam technique — why you catch specific exceptions

Writing except Exception or catch (Exception e) catches everything, including bugs you did not anticipate, and then reports one vague message for all of them. That hides errors rather than handling them: a typo that produces an index error looks identical to a user typing letters, so you cannot tell the user what to do differently. Catch the specific exception you expect (a number-format error, a file-not-found error) and let anything else fail loudly — during development, a loud failure is a gift. In an exam answer, naming two specific exception types scores better than one generic catch.

How to use it — a debugging method that actually works
  1. Reproduce it reliably. Find the exact input that causes the failure. If you cannot make it happen on demand you cannot tell when you have fixed it.
  2. Read the error message properly. It gives the exception type and a line number. "Index out of bounds at line 42" tells you more than any amount of staring.
  3. Form one hypothesis and test it. Not "maybe it's the loop" — "if the bug is an off-by-one, then with n = 1 the loop should execute zero times but I predict it executes once".
  4. Instrument rather than guess. Add a print of the variables at the top of the loop, or set a breakpoint and watch them. Compare what actually happens with what you predicted.
  5. Bisect. If the program is long, print or break halfway. Find the point where the state stops matching your expectation; the bug is before it.
  6. Fix the cause, not the symptom. If an index is out of range, do not add a try around it — work out why the index is too large.
  7. Add a test for it. The regression test is what stops the bug coming back, and in your IA it is also evidence of systematic testing.

  1. State the output.

    nums = [4, 7, 2, 9, 5]
total = 0
for i in range(len(nums)):

        total += nums[i]

    Show answer

    Odd values: 7, 9, 5 → total = 21. Output: 21.

    Note: % is MOD, so nums[i] % 2 == 1 tests oddness. For negative numbers % 2 in Python still gives 1 (Python's modulo follows the sign of the divisor), while in Java -3 % 2 is -1 — a genuine cross-language trap.

  2. Explain the difference between a sub-procedure and a function, and give a situation where each is the better choice.

    Show answer

    A sub-procedure performs an action and returns no value (void in Java; a function with no return in Python). Use it when the purpose is an effect: printing a menu, writing to a file, updating an object's state.

    A function computes and returns a value. Use it when the caller needs a result it will use in further computation: average(marks), distance(a, b), isValid(email).

    The practical reason it matters: a function can be used inside an expression (if isValid(email):), and it has no side effects to reason about, which makes it far easier to test and to reuse.

  3. Write a program in your chosen language that reads 10 integers into an array and prints the second-largest distinct value. Explain how you handled the case where all values are equal.

    Show answer

    Python

    values = [int(input()) for _ in range(10)]
largest = max(values)
rest = [v for v in values if v != largest]
if rest:
    print("Second largest:", max(rest))
else:
    print("All values are equal:", largest)
    1. Find the largest, then find the largest of everything that is not equal to it.
    2. If rest is empty, every element equalled the largest, so there is no second-largest — the program reports that instead of crashing.
    3. Note this returns the second-largest distinct value: for [5, 5, 3] it gives 3, not 5. If the question wanted the second element in sorted order, the answer would be 5 — always check which is meant, and say so.
    Marks: 2 for finding the largest, 2 for filtering it out, 2 for handling the all-equal case explicitly. The last part is the one most answers omit.

  4. State the output of this recursive function and explain the pattern.

    def stars(n):
    if n == 0:
        return ""
    return "*" + stars(n - 1)

for i in range(1, 5):
    print(stars(i))
    Show answer
    *
**
***
****

    stars(1) = "*" + stars(0) = "*" + "" = "*". stars(2) = "*" + "*" = "**", and so on. The base case returns the empty string, which is the identity for concatenation — the same trick as returning 1 for factorial (the identity for multiplication) or 0 for a sum.

    Key insight: choosing the correct identity element for your base case is what makes recursive string and list building work cleanly. Getting it wrong ("" for a sum, 0 for a product) is a classic bug.

  5. Explain why the following recursive function is dangerous, and rewrite it iteratively.

    def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
    Show answer

    Why it is dangerous: the sub-problems overlap — fib(5) is recomputed from scratch inside fib(6) and again inside fib(7) — so the number of calls grows exponentially, roughly O(2ⁿ). fib(40) takes minutes or worse. It also uses O(n) stack space.

    Iterative rewrite

    def fib(n):
    if n <= 1:
        return n
    prev, curr = 0, 1
    for _ in range(2, n + 1):
        prev, curr = curr, prev + curr
    return curr

    This is O(n) time and O(1) space: each value is computed once and only the last two are kept. If you want to keep the recursive form, add memoisation — a dictionary of computed values checked at the top of the function — which also brings it to O(n).

  6. Describe what happens if a program opens a file for writing when the file already contains data, and state how to avoid losing that data.

    Show answer

    Opening in write mode ("w" in Python, new PrintWriter(file) or new FileWriter(file) without the append flag in Java) truncates the file to zero length immediately, before anything is written. The existing contents are lost permanently, with no error, no confirmation and no undo.

    To avoid it: open in append mode ("a", or new FileWriter(file, true)) when you want to add to existing content; check whether the file exists first; or write to a new file and rename it once the write has succeeded — which is the safest pattern, because a crash mid-write leaves the original intact.

  7. A program crashes with ValueError: invalid literal for int() with base 10: 'twelve'. Identify the type of error, explain the cause, and write the code that handles it.

    Show answer

    It is a value error raised at run time: int() was asked to convert the string "twelve", which does not represent an integer in base 10. It is a runtime error rather than a syntax error because the code is grammatically valid — it fails only on this particular input.

    while True:
    text = input("Enter a whole number: ")
    try:
        value = int(text)
        break                 # valid input, leave the loop
    except ValueError:
        print("That is not a whole number. Try again.")
print("You entered", value)

    The loop is the important part: it handles the exception and re-prompts, so the program recovers instead of just reporting the problem and stopping. In Java the equivalent catches NumberFormatException.

  8. Explain why using a global variable inside a sub-procedure is usually a bad idea, and describe how to achieve the same result without one.

    Show answer
    1. No local reasoning. Any part of the program can change a global, so when the value is wrong, the fault could be anywhere — you have destroyed your ability to locate the bug by looking at one function.
    2. No reuse. A sub-procedure that reads a global cannot be copied into another program, or even called twice for two different data sets, without that global being set up first.
    3. Hidden dependencies. The function's signature no longer tells you what it needs, so a reader cannot tell that calling it will change something else.
    4. Concurrency breaks. Two parts of a program running at the same time cannot safely share a mutable global.
    5. Instead: pass the data in as a parameter and return the result. If several values must move together, pass an object (B3) or a collection — the data is then explicit in the signature and the function becomes testable in isolation.
