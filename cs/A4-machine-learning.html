A4 · Machine learning

Traditional programming is you writing the rules and the computer applying them. Machine learning inverts that: you supply the data and the answers, and the computer works out the rules. That inversion is one of the most important ideas in modern computing, and it is new to this syllabus — which means the questions are still settling into a pattern, but the conceptual core is stable: what a model is, how it learns, how you know whether it learned anything, and what happens when it is wrong. Every idea on this page is taught with numbers you can reproduce by hand, because the exam can only ask you to do what you can calculate.

Machine learning is the clearest case where knowing the computing matters more than knowing the software: you cannot evaluate a system that diagnoses patients, shortlists job applicants or prices insurance unless you understand what the model was trained on, what it optimised, and how it can fail. 1 · What machine learning actually is SL / HL

Here is the inversion, stated precisely.

Traditional programmingMachine learning
Input to the machineRules + dataData + answers
Output from the machineAnswersRules (a model)
Who writes the rulesYouThe learning algorithm
ExampleYou code "if the message contains 'free iPad' then spam"You show the system 10 000 messages labelled spam or not, and it finds patterns you never wrote down
Works well whenYou can articulate the rule exactlyThe rule exists but you cannot state it — recognising a face, translating a sentence, predicting demand
Fails whenThe rule has too many special cases to writeYou have no representative data, or the future does not look like the past

The test for whether machine learning is the right tool is therefore not "is this problem hard?" — it is "can I state the rule, and do I have examples of the answer?" Calculating VAT is not a machine learning problem, because you can state the rule in one line. Deciding whether a photograph contains a cat is, because no human can write down the rule, yet any child can produce ten thousand correct answers.

Trap — "the computer learns like a human"

It does not, and saying so loses marks. What happens is narrowly this: the system has a large set of adjustable numbers (parameters or weights) and a fixed procedure that adjusts them slightly to reduce a number called the loss (a measure of how wrong its outputs are on the training data). Repeat that adjustment many times and the parameters end up at values that perform well on the data seen. There is no understanding, no intention and no generalisation beyond what the data supports. The correct phrase is "the model is fitted to the data" or "the parameters are optimised", never "the model understands". If you write in an exam that the model "knows" or "thinks" or "decides", replace the word before you move on.

The seven words you must be able to define

Dataset
The whole collection of examples you are working with. The fourteen rows above are the dataset. Datasets are conventionally written as a table where each row is one example and each column is one property.
Instance (example)
One row — one thing the model will be asked about. Kira's row (6, 5, Pass) is one instance. Examiners also call this a sample, a record or a data point.
Feature
An input property the model is allowed to use. Here there are two features: h and p. Choosing which properties become features is called feature selection, and it is often worth more than choosing a cleverer algorithm.
Label
The correct answer attached to a training instance — "Pass" or "Fail". A dataset with labels is labelled; one without is unlabelled. Labels are expensive, which is the single biggest practical reason unsupervised learning exists.
Model
The thing the learning algorithm produces: a fixed mathematical object (a set of numbers, a tree, a set of cluster centres) that takes features in and puts a prediction out. Once training stops, the model does not change. It is an artefact, like a compiled program.
Training (fitting)
The process of adjusting the model's internal numbers so its predictions match the labels in the training data more closely. Training is expensive; it is where the compute goes.
Inference (prediction)
Using the finished model on a new instance. Inference is cheap — a single forward pass — and, crucially, the weights are frozen during it. Nothing is learned at inference time.
Two sentences that earn marks anywhere in A4

First: "A model is a function fitted to data; it reproduces the regularities in that data, whether or not those regularities are the ones we want." Second: "The model optimises the loss function it was given, so anything missing from that loss function is something the model will happily sacrifice." Almost every ethical question in A4.4 is an application of the second sentence.

2 · Supervised, unsupervised and reinforcement SL / HL

Supervised learning

The training data is labelled: every example comes with the correct answer. The model learns to map input to that answer, and training consists of comparing its output with the known label and correcting the difference.

Classification — the label is a category: is this email spam, is this tumour malignant, which digit is this?

Regression — the label is a number: what will this house sell for, how many units will we sell next week, what score will this student get?

Everyday example: a photo app shown thousands of pictures labelled "cat" or "not cat".

Unsupervised learning

The training data is unlabelled. There is no right answer to learn; the model is asked to find structure. The main case is clustering — grouping instances so that members of a group are similar to each other and different from other groups. A second case is dimensionality reduction: describing the data with fewer numbers while losing as little information as possible.

Everyday example: a music service noticing that you and 40 000 other listeners play the same obscure tracks, and building a "you might like" group — nobody told it the genre existed.

Reinforcement learning

There is no dataset at all. An agent acts in an environment and receives a reward signal; it learns a policy (what to do in each state) that maximises total reward over time. It learns by trial and error, including from rewards that arrive long after the action that earned them.

Everyday example: a program that learns to play a game by playing it millions of times, receiving +1 for a win and −1 for a loss, with no human ever showing it a good move.

3 · The workflow, and what preprocessing is for HL only

Learning does not start with an algorithm. It starts with data that is usually in worse condition than you expect, and the syllabus gives this stage its own sub-topic (A4.2) precisely because it is where most real projects succeed or fail.

  1. Collect data. More relevant data beats a cleverer algorithm, almost always. But collection is where bias enters: if you collect only from one group, the model only works for that group.
  2. Clean it. Real data has missing values, duplicates, impossible values (a person aged 240), inconsistent spellings and units (kg mixed with lb), and outliers. You must handle missing data — drop the row, or impute a value such as the column mean or median — remove duplicates, and decide whether an outlier is a data-entry error or a genuine extreme that matters. Dropping genuine extremes because they are inconvenient is a way of lying with statistics.
  3. Encode categorical data. Models need numbers. "Red / green / blue" becomes numbers, and you must be careful: encoding them as 1, 2, 3 smuggles in a false ordering (is green "between" red and blue?). The standard fix is one-hot encoding — one column per category, holding 0 or 1.
  4. Select and engineer features. Irrelevant features add noise; too many features relative to the number of instances makes overfitting far more likely. Engineering means creating a better feature from existing ones — total revision time from hours and papers, or "days since last login" from a raw timestamp.
  5. Scale the features (see below) for any distance- or gradient-based method.
  6. Split the data into training, validation and test sets.
  7. Train on the training set; tune the hyperparameters on the validation set; evaluate once on the test set.
  8. Deploy and monitor. Performance decays as the world changes (model drift), so the model must be retrained on a schedule, not once.
Vocabulary — preprocessing
missing value — a cell with no data; handled by deleting the row or imputing a substitute value
outlier — a value far from the rest; may be an error or may be the most interesting row in the dataset
imputation — replacing a missing value with an estimate such as the mean or median
one-hot encoding — representing a category by several 0/1 columns, one per possible value
normalisation — rescaling every feature into the same range, usually 0 to 1
standardisation — rescaling so each feature has mean 0 and standard deviation 1
feature engineering — creating a more useful input from the raw inputs you already have

4 · Training, validation and test sets HL only

You split the data because the only thing that matters is performance on data the model has not seen, and the only way to measure that is to withhold data.

Worked example 1 Splitting a dataset · 4 marks

Question. A hospital has 2400 labelled scans. It splits them 60 % / 20 % / 20 % into training, validation and test sets. (a) State how many scans are in each set. (b) The team then tries four values of a hyperparameter, picks the best by test-set accuracy, and reports that accuracy as the model's real-world performance. Explain what is wrong.

  1. Training: 0.60 × 2400 = 1440 scans.
  2. Validation: 0.20 × 2400 = 480 scans.
  3. Test: 0.20 × 2400 = 480 scans. Check: 1440 + 480 + 480 = 2400 ✓.
  4. (b) Choosing the hyperparameter by test-set accuracy is learning from the test set. You have selected the setting that happens to suit those 480 particular scans, so the reported figure is optimistically biased and is no longer an estimate of performance on unseen data.
  5. The correct procedure: choose the hyperparameter using the validation set, then report the accuracy of the chosen model on the test set exactly once.
  6. Also worth a mark: split randomly, and if the classes are imbalanced, split stratified — keep the same proportion of each class in every set. If the data is a time series, split by time: train on the past, test on the future, never the other way round.
Answer: 1440 / 480 / 480. Marks: 1 per correct count (or 2 for all three), 1 for identifying test-set contamination, 1 for stating the correct alternative.
What to do when the dataset is too small to split

Our fourteen-student dataset is too small: a 60/20/20 split leaves two test students, and an accuracy measured on two instances is meaningless (it can only be 0 %, 50 % or 100 %). The standard answer is k-fold cross-validation: split the data into k equal parts, train k times, each time holding out a different part as the validation set, and average the k scores. With k = 5 every instance is used for validation exactly once and for training four times. Say this if a question hands you a small dataset — it shows you know why the rule exists, not just what the rule is.

5 · Overfitting and underfitting HL only

Why Why the split works — and why training error can only ever fall
  1. The purpose of a model is not to do well on data it has seen; it is to do well on data it has not seen. That property is called generalisation, and it is the only thing we care about.
  2. Accuracy on the training set is therefore a meaningless measure of quality on its own. A model with enough parameters can memorise the training set perfectly — including its noise, its typos and its mislabelled rows — and be worthless on anything new. That is overfitting.
  3. The opposite failure is underfitting: the model is too simple to capture the pattern at all, so it does badly on training and test data alike. A straight line fitted to a curved relationship is the classic case.
  4. So we hold data back. If the model has never seen that data, its performance there is an honest estimate of generalisation.
  5. Why three sets and not two? Because choosing hyperparameters on the test set is itself a form of learning from it — you would be selecting the settings that happen to suit that particular sample. The validation set absorbs that selection pressure, leaving the test set genuinely untouched for one final estimate.
  6. In one sentence: training error tells you how well the model memorised; validation error tells you how well it learned. The gap between them is the diagnosis.

What it means: a training accuracy of 99 % and a validation accuracy of 62 % is not a good model — it is an overfitted one.

How to use it — the remedies, with their mechanism
  1. Get more training data. The best remedy and the hardest to arrange. With enough data, even a flexible model cannot memorise its way to a low training error.
  2. Reduce the model's capacity — fewer features, fewer parameters, fewer layers, a shallower tree, a larger k in k-NN. Less capacity means less ability to fit noise.
  3. Regularisation. Add a penalty for large weights to the loss function, so the model is discouraged from contorting itself to pass through individual points. It trades a little training accuracy for a smoother, better-generalising function.
  4. Early stopping. Monitor validation error during training and stop when it stops improving (Figure 1, dashed line). Cheap, effective, and easy to explain.
  5. Data augmentation. Create additional plausible training examples from existing ones — rotating or cropping an image, paraphrasing a sentence. This teaches invariance: a rotated cat is still a cat.
  6. Ensembling / averaging. Average several models; the errors partially cancel. Mentioned for completeness — you will not be asked to implement it.

6 · k-nearest neighbours HL only

k-NN is the algorithm to study because you can do the whole thing by hand, so the exam can ask you to. The idea is almost insultingly simple: to classify a new instance, find the k training instances closest to it in feature space and take a majority vote among their labels. There is no training phase at all — the "model" is just the dataset itself, which is why k-NN is called a lazy learner.

How to use it — the procedure, in five steps
  1. Choose k. An odd k avoids tied votes in a two-class problem.
  2. Compute the distance from the query point to every training instance, usually Euclidean: d = √((x₁ − a₁)² + (x₂ − a₂)²) for two features, and the obvious extension for more.
  3. Sort the distances ascending and take the k smallest.
  4. Count the labels among those k neighbours; assign the majority label. Report the vote (3–0 is a very different claim from 3–2).
  5. For regression rather than classification, output the mean of the k neighbours' values instead of taking a vote.

In general pseudocode (no particular language — the syntax is not what is being examined):

// k-NN classification — general pseudocode
TRAINING = list of (features, label) pairs
Q        = the new instance to classify
k        = chosen number of neighbours

loop I from 0 to length(TRAINING) - 1
    DISTANCE[I] = EUCLIDEAN(Q, TRAINING[I].features)
end loop

NEAREST = the k entries of TRAINING with the smallest DISTANCE
output MAJORITY_LABEL(NEAREST)      // or MEAN(value) for regression

Manhattan distance, and why the choice of metric is a modelling decision

Euclidean distance is the straight-line ("as the crow flies") distance. Manhattan (or city block) distance adds the absolute differences instead: d = |x₁ − a₁| + |x₂ − a₂|. It is the distance you would walk between two points in a city laid out on a grid.

For Q = (6, 4) using Manhattan: A 4 + 3 = 7; B 3 + 2 = 5; C 4 + 1 = 5; D 2 + 3 = 5; E 1 + 2 = 3; F 0 + 3 = 3; M 1 + 2 = 3; N 3 + 0 = 3; G 1 + 1 = 2; H 2 + 2 = 4; I 3 + 0 = 3; J 1 + 3 = 4; K 0 + 1 = 1; L 2 + 0 = 2. The three smallest are K (1), G (2) and L (2) — the same three as before, so the prediction is still Pass. Different metric, different numbers, same answer: worth saying in a "compare" question. Manhattan is preferred when the features are not really spatial (you cannot walk diagonally from 3 hours to 4 papers) or when you want the distance to be less dominated by one large difference.

Why Why feature scaling is not optional — a worked demonstration

Suppose we add a third feature: annual household income in yuan. Consider three students and one query.

  1. S1: 2 hours studied, income 600 000. S2: 9 hours studied, income 900 000. Query Q: 9 hours studied, income 610 000.
  2. Unscaled Euclidean. d(Q, S1)² = (9 − 2)² + (610 000 − 600 000)² = 49 + 100 000 000, so d ≈ 10 000.002. d(Q, S2)² = (9 − 9)² + (610 000 − 900 000)² = 0 + 84 100 000 000, so d = 290 000.
  3. Nearest neighbour: S1 — the student with completely different study habits, chosen purely because the incomes happened to be close. The hours feature contributed 49 out of 100 000 049, i.e. about 0.00005 % of the distance. It was silently ignored.
  4. After normalising both features to 0–1 (divide hours by 10, income by 1 000 000): Q becomes (0.90, 0.61), S1 becomes (0.20, 0.60), S2 becomes (0.90, 0.90).
  5. d(Q, S1)² = 0.70² + 0.01² = 0.4900 + 0.0001 = 0.4901 → d ≈ 0.700. d(Q, S2)² = 0² + 0.29² = 0.0841 → d = 0.290.
  6. Nearest neighbour: S2 — the student with identical study hours. The answer flipped.

What it means: preprocessing is not administration; it decides what the model is able to see. When it matters less: tree-based methods test one feature at a time against a threshold, so they are largely indifferent to scale — a genuinely useful comparison point in an exam answer.

Trap — forgetting to take the square root, and forgetting to sort

Two mechanical errors account for most lost marks on k-NN questions. First, students compare squared distances and then quote the squared value as the distance — if you write d = 13 when you mean d² = 13, every subsequent line is wrong. Write the column heading "d²" explicitly and take roots at the end. Second, students pick the k first rows of the table rather than the k smallest distances. Always rewrite the list in ascending order before you vote; it takes fifteen seconds and it is the step the markscheme rewards.

7 · Linear regression HL only

Regression answers "how much?", and the simplest useful model is a straight line. Given a dataset of (x, y) pairs, the line of best fit (also called the least-squares regression line) is ŷ = mx + c, where ŷ is the predicted value. "Best" means: the line that minimises the sum of squared errors — Σ(y − ŷ)² — over the training data. Squaring means errors above and below the line both count positively, and large errors are punished much more heavily than small ones.

SymbolMeaning
nnumber of instances
x, ythe feature and the (numeric) label for one instance
x̄, ȳthe mean of x and the mean of y
Σxythe sum of the products x × y over all instances
Σx²the sum of the squared x values (square first, then add — not the same as (Σx)²)
mthe slope: how many units ŷ rises when x rises by one
cthe intercept: the predicted value when x = 0

The formulas, which you should be able to apply but will not be asked to derive:

m = ( n·Σxy − Σx·Σy ) / ( n·Σx² − (Σx)² )

c = ( Σy − m·Σx ) / n          equivalently:  c = ȳ − m·x̄
How to use it — the six-column method that prevents arithmetic slips
  1. Make a table with columns x, y, x² and xy. Fill it in row by row.
  2. Add each column to get Σx, Σy, Σx², Σxy. Count n.
  3. Substitute into the formula for m. Keep at least four significant figures in the intermediate values.
  4. Substitute into the formula for c.
  5. Sanity check: the line must pass through the centroid (x̄, ȳ). Substitute x̄ into your line and confirm you get ȳ. If you do not, you have made an arithmetic error — find it before continuing.
  6. Predict by substitution, then ask whether the prediction is interpolation (inside the range of the data, trustworthy) or extrapolation (outside it, not trustworthy).

Trap — four ways to misuse a regression line

One: extrapolating well beyond the data range, as the 40-hour example shows. Two: reading the intercept as meaningful — here c = 40 says "a student who studies zero hours scores 40", but no such student is in the data and the claim is untested. Three: confusing correlation with causation. The line shows that hours and score move together; it says nothing about whether forcing a student to study longer raises their score, because a third variable (prior ability, teaching quality, sleep) may drive both. Four: assuming the relationship is linear. If the true pattern curves — diminishing returns after eight hours — a straight line will systematically under-predict in the middle and over-predict at the ends. Say "the residual pattern would reveal it": residuals that go negative, positive, negative in a curve mean the model is mis-specified.

8 · k-means clustering HL only

Throw away the labels in our dataset and you still have structure: two clouds of students. k-means finds that structure without ever being told the answer. You choose k (the number of clusters), the algorithm places k centroids (the mean position of a cluster), and then repeats two steps until nothing changes:

How to use it — the algorithm
  1. Choose k and initialise k centroids (randomly, or by picking k instances).
  2. Assign: every instance joins the cluster whose centroid is nearest (Euclidean distance).
  3. Update: recompute each centroid as the mean of the instances now in its cluster.
  4. Repeat steps 2–3 until the assignments stop changing (or the centroids barely move). That is convergence.
  5. Report the clusters. The algorithm has no idea what the clusters mean — naming them is your job.

The comment that earns the last marks. The algorithm never knew there were two groups; it found the split because the instances genuinely form two clouds. That is why implementations run k-means several times with different starting points and keep the result with the lowest total within-cluster distance. And the algorithm will always produce k clusters even when the data has no clusters at all — it cannot tell you that k was wrong.

Choosing k

k is a hyperparameter you must supply, and there is no label to check it against. The standard approach is the elbow method: run the algorithm for k = 1, 2, 3, 4 … and plot the total within-cluster distance (the sum of distances from each point to its own centroid). That total always falls as k grows — with k equal to the number of instances it reaches zero and every point is its own cluster, which is useless. You look for the "elbow": the value of k beyond which adding another cluster stops buying much improvement. Describe it in words rather than quoting a formula: "at k = 3 the total distance drops sharply; from k = 4 onwards it falls only slightly, so k = 3 is the natural choice."

Exam technique — clustering answers that score

Three sentences separate a 2-mark answer from a 6-mark one. (1) State that the data is unlabelled and the algorithm minimises within-cluster distance, so this is unsupervised learning. (2) Show one assignment step with actual numbers — even one row of a distance table earns more than a paragraph of description. (3) Add the limitation: the result depends on the initial centroids, k must be chosen in advance, and the clusters need a human to interpret them. Examiners consistently report that candidates describe the algorithm and stop at step 1.

9 · Decision trees HL only

A decision tree asks a sequence of questions about the features and gives an answer at the bottom. Each internal node tests one feature against a threshold; each leaf holds a prediction. To classify an instance you start at the root, answer the question, follow the branch, and repeat until you reach a leaf.

How the tree is built (conceptually)

The learning algorithm chooses, at each node, the split that makes the two resulting groups as pure as possible — as close as possible to containing a single class. A group of ten instances that are all "Pass" is perfectly pure; a group split five–five is maximally impure. So the algorithm tries every feature and every sensible threshold, measures the purity of the split each would produce, and takes the best. Then it recurses on each branch, stopping when a group is pure, when it is too small to split further, or when a depth limit is reached.

For our fourteen-student dataset the first split chosen is hours ≥ 6.5: that gives a left group of {A, B, C, D, E, F, N} (six Fail, one Pass) and a right group of {G, H, I, J, K, L, M} (six Pass, one Fail) — much purer than the fourteen–row starting point, which is seven–seven. The second split on the left is papers ≥ 3.5, which isolates Noah (3, 4, Pass) from the six Fail students; on the right it is papers ≥ 3, which isolates Mia (7, 2, Fail) from the six Pass students. Four leaves, all pure.

10 · Neural networks HL only

The perceptron: one unit, done completely

A single artificial neuron (a perceptron) does four things in order:

  1. Take its inputs x₁, x₂, … , xn.
  2. Multiply each by its own weight w₁, w₂, … , wn and add them up. The weight says how much that input matters; a negative weight says the input counts against firing.
  3. Add the bias b, an adjustable constant that shifts the unit's tendency to fire. The bias is what lets the unit output 1 even when all inputs are 0, or stay silent when all inputs are positive.
  4. Apply the activation function f to the result: output = f(w₁x₁ + w₂x₂ + … + b). The weighted sum is usually called z, so output = f(z).
Worked example 7 A perceptron that computes a logic gate · 6 marks

Question. A perceptron has two inputs, weights w₁ = 0.6 and w₂ = 0.6, bias b = −0.8, and the step activation f(z) = 1 if z ≥ 0, else 0. Complete the truth table.

  1. (0, 0): z = 0.6(0) + 0.6(0) − 0.8 = −0.8. Since −0.8 < 0, output = 0.
  2. (0, 1): z = 0 + 0.6 − 0.8 = −0.2 < 0 → output = 0.
  3. (1, 0): z = 0.6 + 0 − 0.8 = −0.2 < 0 → output = 0.
  4. (1, 1): z = 0.6 + 0.6 − 0.8 = +0.4 ≥ 0 → output = 1.
  5. The truth table is 0, 0, 0, 1 — the AND gate.
  6. The bias is what makes this work. Without it (b = 0), the (0, 0) case gives z = 0 → output 1, which is NAND, not AND. The bias moves the firing threshold.

Why Why the activation function must be non-linear — the collapse argument
  1. Each unit computes a weighted sum of its inputs — a linear operation.
  2. A linear function of a linear function is still linear. So if the activation were linear (or absent), a hundred-layer network would mathematically collapse into a single linear function of the inputs.
  3. That network could only ever draw a straight line (or a flat plane) as its decision boundary — no more powerful than the simplest possible model, no matter how many layers you stacked.
  4. Inserting a non-linearity after each sum breaks the collapse. Each layer can now bend the function a little, and many layers bend it enough to represent very complex boundaries.
  5. ReLU is the standard modern choice because it is cheap and its gradient does not vanish for positive values, which keeps deep networks trainable. The sigmoid squashes any input into (0, 1), which is why it is used where the output must be interpretable as a probability — but it saturates, so it is rarely used in hidden layers today.

What it means: the non-linearity is not a detail; it is the entire source of a neural network's expressive power.

Training a network, conceptually

Loss (cost) function
A single number measuring how wrong the network's outputs are across the training data. For regression a common choice is the mean squared error; for classification a "cross-entropy" style loss is typical. Training is the minimisation of this number.
Epoch
One complete pass through the training data. Networks are trained for many epochs — tens, hundreds, or thousands — because one pass barely moves the weights.
Batch
A subset of the training data used for one weight update. Using batches rather than the whole dataset makes each update cheaper and adds noise that can help escape poor solutions.
Gradient descent
The optimisation method. The loss, viewed as a function of the weights, is a landscape; the gradient points uphill, so you step in the opposite direction. Repeat, and you walk downhill towards a low point.
Learning rate
How big each step is. Too large and you overshoot and oscillate or diverge; too small and training takes forever and can stall on a mediocre solution. It is a hyperparameter.
Backpropagation
The algorithm that works out, efficiently, how much each weight contributed to the error — it applies the chain rule backwards from the output to the inputs. You should know what it is for; you will not be asked to derive it.
Worked example 9 Gradient descent with one weight, by hand

This is the smallest possible training problem, and it shows the whole idea. One training instance: x = 2, true value y = 1. Model: ŷ = w·x, so the only adjustable number is w. Loss = (y − ŷ)².

  1. Start at w = 0. ŷ = 0, error = 1 − 0 = 1, loss = 1² = 1.000.
  2. Which way to move? Try a slightly larger w: at w = 0.2, ŷ = 0.4, loss = (1 − 0.4)² = 0.360. The loss went down, so increasing w is the right direction.
  3. The gradient of the loss with respect to w is 2(ŷ − y)·x. At w = 0.2: 2(0.4 − 1)(2) = −2.4. Negative means "the loss decreases as w increases", so we step w upwards.
  4. With learning rate 0.1: new w = 0.2 − 0.1 × (−2.4) = 0.2 + 0.24 = 0.44. (The minus sign in front of the learning rate is why it is called descent.)
  5. At w = 0.44: ŷ = 0.88, loss = (1 − 0.88)² = 0.0144. Much better.
  6. Next gradient: 2(0.88 − 1)(2) = −0.48, so w := 0.44 + 0.048 = 0.488; loss = (1 − 0.976)² = 0.000576.
  7. Continue and w approaches 0.5, where ŷ = 1 exactly and the loss is 0 — the correct answer, found without anyone solving an equation.
  8. The same procedure, applied to millions of weights using backpropagation to get all the gradients at once, is what trains a real network. Nothing mystical happens; it is this loop, repeated.
Answer: the loss falls 1.000 → 0.360 → 0.0144 → 0.000576 as w moves 0 → 0.2 → 0.44 → 0.488, converging on 0.5. Use this as your mental model of training whenever a question asks you to "explain how a neural network learns".
Exam technique — what will and will not be asked

You will not be asked to implement backpropagation or derive a gradient. You will be asked to: identify the layers and say what each does; explain what a weight and a bias are; perform a forward pass with given weights (as in Worked example 8); explain the role of the activation function; explain why training requires many examples and much computation; and explain why the model's decisions are hard to explain. Practise the forward-pass arithmetic until it is mechanical — it is the one place in this topic where a numeric answer is unambiguously right or wrong.

Worked example 11 Imbalanced data: why 99.9 % can be worthless

Question. A bank processes 100 000 card transactions a month; 100 are fraudulent. A fraud model flags 80 transactions, of which 60 are genuinely fraudulent. (a) Build the confusion matrix. Trap — "the model is 98 % accurate, so it is good"

Three questions must be answered before that sentence means anything. Accurate on what data? — a training-set figure is worthless. Accurate compared with what baseline? — if 98 % of instances are negative, predicting "negative" always gives 98 %. Accurate at what cost? — 98 % accuracy with all the errors concentrated in one group (one demographic, one store, one disease stage) is a fairness problem, not a success story. Answering all three is what turns a definition into an evaluation.

12 · Bias, data and ethics SL / HL

This is the part of A4 that is examined hardest, because it is where machine learning meets the social and ethical reasoning the IB cares about. Each issue below has a mechanism — learn the mechanism, not just the slogan. A six-mark answer names the mechanism and applies it to the scenario in front of you.

Bias and discrimination

Mechanism: the model learns whatever regularities exist in the training data, including the ones produced by historical prejudice. If a company hired mostly men for a decade, a model trained on those decisions learns that being male predicts being hired. The model is not prejudiced; it is accurately reproducing a prejudiced process — which is worse, because it does so at scale, automatically, and with the appearance of objectivity. Also: under-representation means fewer examples for some groups, so the model simply performs worse for them. Removing the protected attribute does not fix it, because other features correlate with it (postcode correlates with ethnicity; first name correlates with gender).

Representativeness

Mechanism: a model can only be valid for the population its data came from. A skin-cancer classifier trained mostly on light skin performs worse on dark skin; a speech recogniser trained on native speakers of one accent fails on others; a model trained on hospital patients does not transfer to people who never reached hospital. The technical name is dataset shift: the deployment distribution differs from the training distribution. Ask, always: who is missing from this data, and what happens to them?

Lack of explainability

Mechanism: a large model's decision is the combined effect of millions of weights, none of which corresponds to a human-understandable rule. So the model can be right without anyone being able to say why. This matters legally (data-protection regimes in many jurisdictions grant a right to an explanation for automated decisions) and practically (if you cannot explain a diagnosis, a doctor cannot verify it, and a developer cannot debug it). Explainable AI exists because this is a real barrier to deploying models in high-stakes settings.

Privacy

Mechanism: models are trained on personal data and can leak it — a model trained on medical records may reproduce details of individuals when prompted. Consent is also weak: data collected for one purpose is routinely reused for training without a fresh decision by the subject. Techniques worth naming: differential privacy (adding calibrated noise so no individual's data materially affects the output) and federated learning (train on the device, share only the updates).

Accountability

Mechanism: the chain from data collector to trainer to deployer to user makes it easy for everyone to disclaim responsibility, and a probabilistic system gives everyone a ready excuse ("it is usually right"). "The algorithm decided" is not an answer the law accepts. A defensible deployment assigns a named human owner for the decision, keeps a human in the loop where individuals are affected, logs decisions so they can be audited, and provides a route to challenge an outcome.

Environmental cost

Mechanism: training a large model means running thousands of power-hungry processors for weeks, consuming electricity and the water used to cool data centres, plus the embodied carbon of the hardware. The honest nuance: for widely deployed models, inference now dominates total energy use, because a model is trained once and used billions of times — so the argument is about deployment scale as much as training runs. Also worth naming: rare-earth mining and e-waste from accelerated hardware replacement.

Deepfakes and misinformation

Mechanism: generative models produce photorealistic images, video and audio of people saying and doing things they never did. The damage is not only individual (fraud, revenge, political manipulation) but epistemic: when convincing fakes are cheap, people can dismiss genuine evidence as fake — the "liar's dividend". Detection is an arms race, so the durable responses are provenance (cryptographic signing of authentic media) and literacy, not detection alone.

Job displacement

Mechanism: machine learning automates tasks rather than whole jobs, but the tasks it automates first are the routine cognitive ones that have historically been entry-level professional work. The distributional effect matters: productivity gains accrue to the owners of the system while displacement costs fall on individuals. And new tasks appear — someone must label the data, audit the model and handle the exceptions — so the honest answer is about transition and distribution, not about a single unemployment number.

How to write the ML evaluation — the structure that scores
  1. Say what kind of system this is and what it optimises. "This is a supervised classification system trained on historical hiring decisions, so it optimises accuracy against those past decisions."
  2. Name the stakeholders — applicants, the employer, existing staff, regulators, and groups historically under-represented in the industry.
  3. Develop two benefits concretely: consistency (the same application always gets the same treatment, unlike a tired human at 5 pm), and throughput (thousands of applications screened cheaply).
  4. Develop two harms concretely, with the mechanism: historical bias in the training labels is learned and then amplified; unsuccessful applicants cannot be told why they were rejected, so they cannot appeal or improve.
  5. Propose mitigations: audit outcomes for disparate impact across groups before deployment; keep a human in the loop for decisions affecting individuals; publish the features used; retrain and re-audit on a schedule; document the data provenance.
  6. Reach a judgement: "acceptable as a screening aid with a human decision and regular auditing; not acceptable as an autonomous reject mechanism, because the harms are concentrated on individuals who have no route to challenge the outcome."

The single sentence that most improves these answers distinguishes what the model was optimised for from what we actually want. Everything you forgot to put into the loss function is something the model will happily sacrifice.

Weak versus strong, on the same question

Question: "A school uses a machine-learning model to predict which students will fail their finals, so that teachers can offer extra support. Discuss the use of this system." [6 marks]

Weak answer (2/6)Strong answer (6/6)
The system is useful because teachers can help students who are struggling. It can look at lots of data very quickly, which a teacher cannot do. However, it might be biased and it might get some students wrong, which is bad. Also the data might not be private. Overall it is a good idea if it is used carefully. The system is supervised classification: historical records come with the eventual outcome, so the model is fitted to predict a category (fail / not fail) for each student. Benefit: support can be targeted earlier than a teacher would notice, and patterns across hundreds of students — attendance combined with a particular assessment profile — can be surfaced that no individual teacher sees. Harm with mechanism: because the labels are past outcomes, the model learns whatever disadvantages existed historically; groups already over-represented among past failures will be flagged disproportionately, and being labelled "at risk" can lower expectations, making the prediction self-fulfilling. Second harm: the prediction is probabilistic, so some flagged students were never at risk (wasted support) and some who were at risk are missed and receive nothing. Mitigation: audit false-positive and false-negative rates by group each term, use the output only to offer help, tell students what data is used, and keep the decision with a teacher who knows the student. Judgement: defensible as a prompt for a human conversation about support, provided it is audited and transparent; not defensible as an autonomous allocation of teaching time, because the cost of a wrong prediction falls on an individual child with no route to challenge it.

The difference is not length for its own sake. The strong answer classifies the system, develops each point with a mechanism, names stakeholders, and lands on a judgement that says what the system may and may not be used for. Every one of those moves is a markscheme bullet.

Trap — the five errors that cost the most marks
  1. Saying the model "understands", "knows" or "thinks". Use "is fitted to", "optimises", "predicts". This single wording habit is the most common reason a candidate loses a mark in A4.
  2. Confusing supervised with unsupervised. The test is not "is it complicated?" but "do the training examples come with the correct answer?" Check before you write.
  3. Ignoring feature scaling in any distance-based method. If a question gives you features in wildly different units, scaling is almost certainly the point of the question.
  4. Quoting training accuracy as evidence the model is good. Always ask which set the figure was measured on, and always compare it with the validation figure.
  5. Describing an ethical issue without a mechanism. "It could be biased" is a heading, not an answer. "It was trained on ten years of decisions made by panel X, so it reproduces panel X's preferences" is an answer.

  1. Define the terms dataset, instance, feature, label, model and inference, using the fourteen-student dataset on this page to illustrate each.

    Show the answer
    1. Dataset — the whole collection of examples; here, the fourteen rows recording hours, papers and result.
    2. Instance — one row; Kira's row (6, 5, Pass) is one instance.
    3. Feature — an input property the model may use; here h (hours studied) and p (past papers completed).
    4. Label — the correct answer attached to a training instance; here "Pass" or "Fail".
    5. Model — the artefact produced by training: the fitted function, tree or set of weights that maps features to a prediction.
    6. Inference — applying the finished model to a new instance to get a prediction; the weights do not change while this happens.
    Why this is worth knowing: these six words appear in almost every A4 question, and a definition is the cheapest mark on the paper — provided you illustrate it, because "a label is the answer" alone is worth less than "a label is the correct answer attached to a training instance, such as Pass or Fail".

  2. For each scenario, state whether it is supervised classification, supervised regression, unsupervised clustering or reinforcement learning, and give the one feature of the scenario that decides it.

    (a) Predicting the price of a flat from the prices of 5000 flats sold last year.
    (b) Sorting 20 000 news articles into groups without being told what the groups are.
    (c) Training a system to control a heating system by rewarding it for keeping the temperature near 21 °C.
    (d) Deciding whether an X-ray shows a fracture, using X-rays that radiologists have already marked.

    Show the answer
    1. (a) Supervised regression — past sale prices are known, and the answer is a quantity.
    2. (b) Unsupervised clustering — there is no correct group label; the groups are to be discovered.
    3. (c) Reinforcement learning — no dataset; there is an environment, actions and a reward signal.
    4. (d) Supervised classification — the radiologists' marks are labels, and the answer is a category.
    Why this is worth knowing: the deciding feature is always the same question — does the training data contain the correct answer, and is that answer a category or a number? Naming the deciding feature is what converts a guess into a justified answer.

  3. A team has 3600 labelled images and splits them into training, validation and test sets in the ratio 70 : 15 : 15. (a) Calculate the number of images in each set. (b) Explain why three sets are used rather than one, and why the validation set must not be used to tune the model and then reported as its accuracy.

    Show the answer
    1. Total parts = 70 + 15 + 15 = 100, so one part = 3600 / 100 = 36 images.
    2. Training = 70 × 36 = 2520; validation = 15 × 36 = 540; test = 15 × 36 = 540. Check: 2520 + 540 + 540 = 3600 ✓.
    3. Three sets, because each has a different job: training adjusts the parameters, validation selects hyperparameters and decides when to stop, and test gives one final estimate of real-world performance.
    4. Choosing hyperparameters on the test set is a form of learning from it: you select settings that suit that particular sample, so the reported accuracy is optimistically biased and no longer estimates performance on unseen data.
    5. The validation set absorbs that selection pressure; the test set is then touched exactly once.
    Why this is worth knowing: "report the test accuracy after tuning on the test set" is the single most common methodological error in coursework and in exam answers, and spotting it is a reliable mark.

  4. A model gives a training error of 1.8 % and a validation error of 19.4 %. (a) Identify the problem and explain what has happened. (b) Suggest three changes that would improve generalisation, and explain the mechanism of each.

    Show the answer
    1. Overfitting: the model has fitted the training data — including its noise and any mislabelled rows — rather than the underlying pattern, so performance collapses on unseen data.
    2. The diagnostic is the gap (17.6 percentage points), not either number alone; training error alone would have looked excellent.
    3. Get more data — with enough examples the model cannot memorise its way to a low training error.
    4. Reduce capacity — fewer features, fewer parameters, fewer layers, a shallower tree, a larger k. Less flexibility means less ability to fit noise.
    5. Regularise or stop early — penalise large weights so the function stays smooth, or halt training at the epoch with the lowest validation error (the dashed line in Figure 1).
    6. Also worth a mark: check for data leakage, where information about the held-out data has accidentally entered training; it produces the same symptom.
    Why this is worth knowing: the train-versus-validation gap is the central diagnostic of the whole topic, and examiners regularly present it as two numbers and ask you to interpret them.

  6. The regression line fitted earlier is ŷ = 5.714x + 40, where x is hours studied and ŷ is the predicted mock score out of 100. (a) Predict the score for a student who studies 7 hours. (b) Explain why using the same line to predict the score for a student who studies 40 hours is not valid. (c) State one further reason why this model might mislead the school.

    Show the answer
    1. (a) ŷ = 5.714 × 7 + 40 = 40.0 + 40 = 80 (nearest mark).
    2. (b) 40 hours is far outside the training range of 1–6 hours — a large extrapolation. The line gives ŷ = 5.714 × 40 + 40 = 268.6, which is impossible for a score out of 100: the model has no knowledge of the ceiling because no data told it one exists.
    3. (c) The relationship may not be linear: beyond some point, extra hours bring diminishing returns, so a straight line will over-predict at high effort.
    4. Also creditworthy: correlation is not causation — the line shows that hours and score move together, not that forcing a student to study longer raises their score, since prior ability or teaching quality may drive both.
    Why this is worth knowing: "extrapolation", "correlation is not causation" and "the relationship may not be linear" are the three standard evaluation points for regression, and any of them can be the difference between 4 and 6 marks.

  7. Six unlabelled instances are (2, 2), (3, 2), (2, 3), (9, 9), (10, 9) and (9, 10). Run one iteration of k-means with k = 2, starting from centroids (2, 3) and (9, 9). Show the assignment of every point and the recomputed centroids.

    Show the answer
    1. To C1 (2, 3): (2,2) → √(0 + 1) = 1.000; (3,2) → √(1 + 1) = 1.414; (2,3) → 0.000; (9,9) → √(49 + 36) = 9.220; (10,9) → √(64 + 36) = 10.000; (9,10) → √(49 + 49) = 9.899.

    3. Each point joins the nearer centroid: cluster 1 = {(2,2), (3,2), (2,3)} and cluster 2 = {(9,9), (10,9), (9,10)}.
    4. New C1 = ((2 + 3 + 2)/3, (2 + 2 + 3)/3) = (7/3, 7/3) = (2.33, 2.33).

    Why this is worth knowing: the assignment step and the update step are different operations, and candidates routinely compute the distances and forget to recompute the centroids — which is half the algorithm.

  8. A perceptron has three inputs x₁ = 1, x₂ = 0, x₃ = 1, weights w = (0.5, −0.3, 0.8) and bias b = −0.4. (a) Calculate the weighted sum z. (b) State the output if the activation is the step function. (c) State the output if the activation is the sigmoid. (d) Explain the role of the bias.

    Show the answer
    1. (a) z = 0.5(1) + (−0.3)(0) + 0.8(1) + (−0.4) = 0.5 + 0 + 0.8 − 0.4 = 0.9.
    2. (b) Step: z ≥ 0, so output = 1.
    3. (c) Sigmoid: 1 / (1 + e−0.9) = 1 / (1 + 0.4066) = 1 / 1.4066 = 0.711 (3 s.f.).
    4. (d) The bias is an adjustable constant added to the weighted sum; it sets how readily the unit fires independently of its inputs, effectively moving the decision threshold. Without it, a unit whose inputs are all zero would always produce the same output, whatever the weights.
    5. Note the difference between (b) and (c): the step function throws away the information that 0.9 is only modestly positive, while the sigmoid preserves it as a confidence-like value of 0.711.
    Why this is worth knowing: the forward pass is the one calculation in A4 with a single unambiguously correct answer, so it is the safest place in the paper to bank marks — provided you remember to add the bias.

  9. A spam filter processes 5000 emails, of which 250 are spam. It flags 200 emails as spam and 180 of those really are spam. (a) Construct the confusion matrix. (b) Calculate accuracy, precision and recall. (c) Explain, with reference to the figures, why accuracy alone would mislead the developers.

    Show the answer
    1. TP = 180; FP = 200 − 180 = 20; FN = 250 − 180 = 70; TN = 5000 − 180 − 20 − 70 = 4730. Check: 180 + 20 + 70 + 4730 = 5000 ✓.
    2. Accuracy = (180 + 4730) / 5000 = 4910 / 5000 = 0.982 = 98.2 %.
    3. Precision = 180 / 200 = 0.90 = 90.0 %.
    4. Recall = 180 / 250 = 0.72 = 72.0 %.
    5. (c) A filter that flagged nothing would be correct on all 4750 genuine emails: accuracy = 4750 / 5000 = 95.0 %. So the model's 98.2 % is only about three points better than doing nothing, and accuracy says nothing about the 70 spam messages that still reached inboxes.
    6. For a spam filter, precision is the more important measure: a false positive hides a genuine message — a job offer, a password reset — which the user may never see, whereas a false negative merely costs the user two seconds of deleting one more junk email.
    Why this is worth knowing: comparing a model against a do-nothing baseline is the fastest way to show you understand imbalanced data, and it turns a calculation question into an evaluation question.

  10. Discuss the use of facial recognition to take school attendance automatically as students enter the classroom. [8 marks]

    Show the answer
    1. Classify the system: a supervised classification model (identify which enrolled face this is), trained on images of the students, possibly using a pre-trained network fine-tuned on the school's data.
    2. Stakeholders: students, teachers, parents, the school administration, the supplier, and any visitor or staff member captured incidentally.
    3. Benefits, developed: registration takes seconds rather than minutes, so more teaching time; attendance records are consistent and cannot be falsified by a friend answering "here"; patterns of absence are detected earlier than a weekly check would find them.
    4. Harm with mechanism 1 — accuracy is not uniform: face recognition error rates are known to vary by skin tone, age and gender, because training datasets have historically been unrepresentative. A mis-recognition here is not symmetrical: a student marked absent when present may be disciplined for truancy they did not commit.
    5. Harm with mechanism 2 — biometric privacy: a face is an irrevocable identifier. Unlike a password it cannot be changed if the database is breached, and the students are minors who cannot meaningfully consent. Scope creep is a real risk: a system built for attendance can later be used for behaviour monitoring.
    6. Harm with mechanism 3 — function creep and normalisation: routine biometric surveillance in childhood normalises it, and the data may be retained far longer than the stated purpose requires.
    7. Mitigations: publish measured error rates per demographic group and act on them; store a template rather than the image, encrypted, with a fixed deletion date; obtain parental consent with a genuine opt-out that is not penalised; keep a teacher able to correct the register within the lesson; never use the output as the sole evidence for a sanction; audit annually.
    8. Judgement: the efficiency gain is real but modest — a register takes two minutes — while the harms are concentrated on identifiable children and include an irreversible privacy loss. Acceptable only with measured and published per-group error rates, an opt-out with no penalty, a human correction step and a hard deletion schedule; not acceptable as sole evidence for disciplinary action, because the student has no way to challenge a probabilistic match.
    Why this is worth knowing: this is the template for every A4.4 discuss question — classify, stakeholders, two developed benefits, two harms with mechanisms, mitigations, judgement. Notice that the judgement names what the system may and may not be used for; "it depends" scores nothing.
