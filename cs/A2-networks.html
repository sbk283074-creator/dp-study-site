A2 · Networks

A network is an agreement before it is a cable. Every device on the internet agrees on how to name every other device, how to chop a message into pieces, how to route those pieces across dozens of independent networks, and how to detect that a piece arrived corrupted. This topic is where the course stops being about one machine and starts being about systems — and it is the topic where Paper 1 most often asks you to evaluate, because every network design decision is a trade-off.

Two distinctions examiners like. Internet vs intranet: an intranet is a private network using internet technologies (web servers, browsers, TCP/IP) but accessible only to one organisation; the internet is the global public network of networks. An extranet is an intranet selectively opened to chosen outsiders (suppliers, customers). Client–server vs peer-to-peer is a different axis entirely — it describes who provides the service, not how big the network is. See below.

Why a VPN is "virtual" and why that is the whole point

A company with offices in three cities cannot afford to lay its own cable between them, so it sends data over the public internet — which anyone can observe. A VPN solves this by encrypting each packet at the sender's edge and decrypting it at the receiver's edge, so the packet travels through the public internet as unreadable ciphertext inside an ordinary IP packet. The private network therefore exists as a logical overlay with no dedicated hardware: that is what "virtual" means. The trade-off is explicit: you gain confidentiality over an untrusted medium at the cost of encryption overhead (slightly lower throughput, slightly higher latency) and of all your traffic now passing through the VPN provider, who becomes a new party you must trust.

Topologies

A topology is the arrangement of the connections: the graph of who is wired to whom. Physical topology is the actual cabling; logical topology is the path data takes (a network can be physically a star but logically a bus — early Ethernet over a hub did exactly that).

TopologyHow it worksAdvantagesDisadvantagesWhat happens if one link fails
BusAll nodes share one cable (the backbone); every node sees every transmission and keeps only the ones addressed to it Cheapest cabling; easy to extend a short segment Collisions: only one device can transmit at a time or signals corrupt each other; performance collapses as nodes are added; hard to fault-find Whole network fails — the shared cable is a single point of failure, and a break also causes signal reflection
StarEvery node has its own cable to a central switch or hub One cable failure affects one node only; no collisions on a switch; easy to add or remove nodes; easy to monitor centrally Most cabling, so highest cost; the central device is a single point of failure; limited by the switch's port count and backplane capacity Only that node is disconnected — unless the central switch itself fails, in which case everything goes down
RingNodes form a closed loop; data travels in one direction and each node repeats it onward No collisions (only the token holder transmits in token ring); predictable performance under load Adding a node breaks the ring temporarily; every node is a potential point of failure unless dual-ring Whole ring fails unless a dual-ring or a bypass switch exists
MeshNodes connect to many (full mesh: every) other nodes Most robust — many alternative routes; load can be spread; no single point of failure Extremely expensive to cable; complex routing; full mesh is impractical beyond a handful of nodes Nothing — traffic reroutes. This is why the internet's core is a partial mesh
Why Why mesh is impossible to scale as a full mesh — the n(n−1)/2 argument
  1. In a full mesh every node needs a link to every other node. With n nodes, each node needs n − 1 links.
  2. Counting each link once rather than twice gives \(\dfrac{n(n-1)}{2}\) links in total.
  3. That is quadratic growth. 10 nodes → 45 links. 100 nodes → 4950 links. 1000 nodes → 499 500 links.
  4. Cost, physical space for cable and the number of network interfaces per device all grow quadratically, so a full mesh is only ever used for a small number of critical backbone routers.
  5. The internet therefore uses a partial mesh: enough redundant links to survive failures, few enough to be affordable and routable. Star is the opposite trade: linear cost (one link per node, n − 1 links total) but a single point of failure.

What it means: "most reliable" and "most scalable" are different properties, and no topology maximises both. When the argument is the wrong tool: for a home or a small classroom, the theoretical failure advantage of mesh is irrelevant next to cost and simplicity — say so in your answer.

Why standards and protocols are needed

Why this matters more than any single technology

The internet is not one network; it is about 70 000 independent networks (autonomous systems) operated by competing companies that agreed to interconnect. Nothing forces them to. The only reason a packet from a phone in Chengdu reaches a server in Frankfurt is that every one of those operators implements the same standards — agreed, published rules — and the same protocols: agreed formats and sequences for exchanging data. Standards also create a competitive market (you can buy any vendor's Wi-Fi router) and let technologies evolve in layers independently (Wi-Fi 7 replaced Wi-Fi 6 without any change to HTTP).

Key standard bodies to be able to name: the IETF publishes the RFCs that define TCP/IP; the IEEE defines the 802 family (802.3 Ethernet, 802.11 Wi-Fi, 802.15 Bluetooth); the ITU-T handles international telecommunications; W3C handles the web's core languages; ISO published the OSI model.

A2.2 · Network architecture: the two models

Two layered models exist, and you need both. The OSI seven-layer model is a teaching and diagnostic tool — a conceptual reference that was never fully implemented as a protocol suite. The TCP/IP model is what the internet actually runs.

Layer by layer — what each one actually does

7 · Application
The protocols the user's software speaks: HTTP/HTTPS (web), SMTP/IMAP (email sending / retrieval), FTP (file transfer), DNS (name resolution), SSH (secure shell). This is not the application itself (Chrome is not a layer) — it is the network protocol the application uses.
6 · Presentation
Translation between the application's data format and a network form: character encoding (UTF-8), serialisation (JSON, XML), compression, and — crucially — encryption. TLS/SSL lives here, which is why HTTPS is transparent to the layers below and to the layers above.
5 · Session
Establishes, manages and terminates the dialogue between two applications: login sessions, checkpoints and recovery, keeping concurrent conversations separate.
4 · Transport
End-to-end delivery between processes, identified by port numbers. TCP is reliable and connection-oriented: it numbers segments, acknowledges them, retransmits losses, reorders out-of-order arrivals and throttles itself to avoid congestion. UDP is connectionless and unreliable: it sends and forgets. UDP wins where speed matters more than completeness — live voice, video calls, online gaming — because a late packet is worthless there.
3 · Network
Delivery between hosts across different networks, identified by IP address. This is the layer that makes the internet a network of networks: it adds the source and destination IP addresses and makes the routing decision that moves the packet one hop closer.
2 · Data link
Delivery between adjacent nodes on one link, identified by MAC address. It packages the packet into a frame, adds error detection (the frame check sequence), and manages access to a shared medium (CSMA/CD historically, CSMA/CA in Wi-Fi).
1 · Physical
The actual signals: voltage levels on copper, light pulses in fibre, radio waves in air. It defines connectors, pinouts, modulation and bit rates. It knows nothing about frames or addresses.
How to use it — the encapsulation story to memorise

You send a web request. At the application layer your browser forms an HTTP GET. At the transport layer TCP wraps it in a segment with a source port (a random high port) and destination port 443. At the network layer IP wraps that in a packet with your IP address and the server's IP address. At the data link layer Ethernet wraps that in a frame with your MAC address and the MAC address of your router — not the server's, because you can only reach the next hop. At the physical layer it becomes signals on the cable. Your router strips the frame, reads the IP packet, decides the next hop, builds a new frame addressed to the next router's MAC, and sends it on. That last step is the bit students miss: MAC addresses change at every hop; IP addresses do not.

Trap — "TCP/IP" is two protocols, not one

Naming "TCP/IP" as if it were a single thing loses marks. IP delivers packets to a machine but does not guarantee arrival, order or non-duplication; TCP adds all of that on top. A question asking "why does a video call use UDP rather than TCP?" wants: TCP's retransmission of a lost packet introduces a delay that makes it useless for real-time audio, whereas UDP accepts occasional loss in exchange for low, even latency — a missing frame of video is a glitch, a two-second stall is a ruined call.

Addressing

Why Why we need both — and why IP alone would not work
  1. Imagine addressing only by MAC. Every router on earth would need a table entry for every device on earth — billions of entries, updated constantly as devices move. Routing tables would never converge.
  2. IP addresses are hierarchical: the network portion lets a router in Frankfurt send everything for 2001:db8:5::/48 in one direction without knowing anything about individual hosts. This is exactly why a postcode works and a name alone does not.
  3. But IP addresses are logical and assigned by whichever network you joined, so they give you no way to deliver a frame across the actual physical link — the hardware needs a hardware address.
  4. So: IP gets you across the internetwork hop by hop; MAC gets you across each individual hop. ARP (Address Resolution Protocol) bridges them: "who owns 192.168.1.1? tell 192.168.1.42".

What it means: the two addressing schemes exist because routing needs hierarchy and delivery needs physical reality. When it is the wrong lens: on a point-to-point link there is only one possible next hop, so some technologies skip MAC addressing entirely.

Why IPv6 was needed

IPv4 has 32 bits, so at most \(2^{32} \approx 4.3\) billion addresses — and because of the way blocks were allocated in the early days, a large fraction is unusable. Then three things happened at once: the number of devices exploded (phones, tablets, watches, sensors), always-on connections replaced dial-up (so an address is held continuously rather than shared), and the remaining free pool ran out. NAT delayed the crisis (see below) but at the cost of breaking the end-to-end principle. IPv6's 128-bit address gives \(2^{128} \approx 3.4 \times 10^{38}\) addresses — roughly 1028 addresses per person alive.

Connection — the end-to-end principle

The original internet design assumed any host could open a connection to any other host. NAT broke that: a device behind NAT has a private address and cannot accept unsolicited incoming connections, which is why peer-to-peer applications such as video calls and file sharing need STUN, TURN or a relay server. IPv6 restores the original design. This is a genuine architectural argument you can use in a 10-mark evaluate the transition to IPv6 question: the benefit is not just "more addresses", it is the restoration of end-to-end connectivity.

Subnetting basics

An IPv4 address is split into a network part and a host part by the subnet mask. In 192.168.1.42/24 the /24 means the first 24 bits are the network, leaving 8 bits for hosts: \(2^{8} - 2 = 254\) usable addresses (subtracting the network address itself and the broadcast address).

Worked example 1 IB-style · 6 marks · subnetting

Question. A school is allocated 172.16.8.0/22. Calculate (a) the number of host addresses available, (b) the first and last usable host addresses, (c) how many /24 subnets can be created from it.

  1. /22 means 22 network bits, so host bits = 32 − 22 = 10.
  2. (a) Total addresses = \(2^{10} = 1024\); usable hosts = 1024 − 2 = 1022.
  3. (b) Network address 172.16.8.0, so the first usable host is 172.16.8.1. The block spans 172.16.8.0 to 172.16.11.255 (because 10 host bits cover four /24s: .8, .9, .10, .11). The last address 172.16.11.255 is the broadcast, so the last usable host is 172.16.11.254.
  4. (c) A /24 subnet uses 24 network bits; we have 22, so 2 bits are available to vary → \(2^{2} = 4\) subnets: 172.16.8.0/24, .9.0/24, .10.0/24, .11.0/24.
Answer: (a) 1022 hosts; (b) 172.16.8.1 to 172.16.11.254; (c) 4 subnets of 254 hosts each. The two marks most often lost: forgetting the −2 for network and broadcast, and failing to notice that /22 covers four consecutive /24s.

DNS, DHCP and NAT

DNS (Domain Name System) is the internet's phone book: it translates names humans remember into IP addresses machines route on. It is a distributed, hierarchical database — nobody holds the whole thing.

How to use it — the DNS resolution walkthrough
  1. You type www.example.com. Your browser checks its own cache, then the OS cache, then the hosts file. If no answer, it asks the recursive resolver (usually your ISP's, or 8.8.8.8 or 1.1.1.1).
  2. The resolver checks its cache — most queries end here. If not, it asks a root name server (13 clusters worldwide): "who handles .com?"
  3. The root replies with the address of a TLD name server for .com.
  4. The resolver asks that TLD server: "who handles example.com?" and receives the address of the domain's authoritative name server.
  5. The resolver asks the authoritative server for www.example.com and receives the A (IPv4) or AAAA (IPv6) record.
  6. The answer is returned to you and cached for the TTL (time to live) specified in the record, so the next lookup is instant.

The design insight worth stating in an exam: DNS is hierarchical and cached, which is why it scales to billions of queries a day and why changing a record takes time to propagate.

DHCP (Dynamic Host Configuration Protocol) automatically hands out IP addresses, subnet masks, default gateways and DNS server addresses when a device joins a network. Without it, an administrator would have to configure every device by hand and keep a register of used addresses. The address is leased for a period and must be renewed — which is why addresses can change between sessions.

NAT (Network Address Translation) lets many devices on a private network share one public IP address. The router rewrites the source IP (and port) of every outgoing packet to its own public address, records the mapping in a table, and reverses the process for the reply.

Why Why NAT is both a lifeline and a hack
  1. The problem it solves: IPv4 exhaustion. A home with 20 devices needs one public address, not 20. NAT multiplied the usable lifetime of IPv4 by roughly the average devices-per-household factor.
  2. The incidental benefit: because a NAT router drops unsolicited inbound traffic — there is no table entry to translate — it acts as a crude default firewall.
  3. The cost: it destroys end-to-end connectivity. A device behind NAT cannot be reached from outside without port forwarding or a relay, so peer-to-peer applications need extra machinery.
  4. The second cost: it hides many users behind one address, so abuse attribution is harder and IP-based geolocation and blocking become blunt instruments that affect unrelated users.
  5. The conclusion: NAT was a workaround that worked so well it delayed the real fix by two decades. Say that in an answer — examiners reward the observation that a successful workaround can create its own problems.

A2.3 · Data transmission

Packets

A message is not sent whole; it is broken into packets. Each packet carries a header with control information and a payload with a slice of data.

| Destination MAC | Source MAC | Type |  payload (IP packet)  | FCS |
                  | Dest IP | Source IP | TTL | Protocol | payload (TCP segment) |
                                                | Dest port | Source port | Seq | ACK | Flags | data |
Why split into packets at all

Three reasons, all worth marks. Fairness: if one machine could hold the line for a five-minute transfer, nobody else could use it; packets interleave so many conversations share one link. Error recovery: if a 100 MB transfer is one unit and one bit is corrupted, you retransmit 100 MB; if it is 70 000 packets, you retransmit one packet. Routing flexibility: packets can take different routes, so the network reroutes around failures automatically. The cost, of course, is the overhead of a header on every packet, plus the need to reassemble in the right order at the far end.

Packet switching vs circuit switching

Circuit switchingPacket switching
SetupA dedicated path is established and reserved before any data flowsNo setup; each packet is routed independently
Resource useBandwidth is reserved for the whole call even during silence — wasted capacityBandwidth is used only when there is data — the link is shared statistically
RobustnessA break in the reserved path kills the callLater packets are routed around the failure
DelayConstant, predictable — good for real-timeVariable (jitter) as queues build; packets may arrive out of order
Classic exampleThe traditional telephone networkThe internet
Why Why packet switching wins on robustness and on cost — the two arguments separately
  1. Robustness (Baran's argument). In a circuit-switched network the route is chosen once; if a node on it dies, the connection dies with it. In a packet-switched network each packet is routed afresh, so the routing tables converge on an alternative within seconds and the conversation continues, perhaps with a brief pause. This was a military requirement — the original design brief was a network that survived a nuclear attack.
  2. Bandwidth sharing (the statistical argument). Network traffic is bursty: a user is silent while reading a page and then transfers a whole image. If you reserve capacity for each user's peak, the link is idle most of the time. If you share it, the law of large numbers means a hundred bursty users rarely peak simultaneously, so a much smaller link serves them all — this is statistical multiplexing and it is why your broadband is affordable.
  3. What packet switching gives up: guaranteed quality of service. When the shared link is congested, queues grow, delay and jitter rise, and routers drop packets. Voice over IP therefore needs extra engineering (buffers, prioritisation, codecs tolerant to loss) that the old telephone network got for free from its dedicated circuit.

Conclusion: packet switching sacrifices predictability for efficiency and resilience — the right trade for data, a trade that must be engineered around for real-time media.

Routing

A router is a layer-3 device that connects different networks and forwards packets between them using a routing table. For each incoming packet it reads the destination IP, finds the longest-matching network prefix in its table, and forwards the packet out of the corresponding interface toward the next hop. Two families of routing protocol maintain those tables:

  • Distance-vector / RIP: each router tells its neighbours its entire table, and hop count is the metric. Simple, but slow to converge and blind to link speed — a 10 Gbit/s fibre hop counts the same as a slow satellite hop.
  • Link-state / OSPF: each router floods information about the state of its own links, so every router builds a complete map of the network and runs a shortest-path algorithm over it. Faster convergence and better metrics, at the cost of more processing and memory.
  • Between organisations, BGP is used — a path-vector protocol whose "distance" is really a policy: which routes an operator is willing to accept, prefer or announce.
Exam technique — "explain how a router forwards a packet"

Answer in this order: (1) the frame is received and its MAC destination checked; (2) the frame header and trailer are stripped and the IP packet passed up; (3) the destination IP address is read; (4) the routing table is searched for the longest matching prefix; (5) the packet's TTL is decremented (and the packet discarded with an ICMP message if it reaches 0 — this is what stops packets looping for ever); (6) a new layer-2 frame is built with the next hop's MAC address and sent out of the chosen interface. Step 6 is where the marks are: students forget that the router rebuilds the frame.

Why fibre is faster — the physics in one paragraph

Copper carries information as changes in voltage, and a long copper wire behaves like an antenna in both directions: it picks up interference from motors, power lines and adjacent pairs, and it radiates its own signal. The higher the frequency you push through it, the worse both effects become, so bandwidth is limited. Fibre carries light in a glass core by total internal reflection. Glass does not conduct electricity, so electromagnetic interference is simply irrelevant; attenuation is far lower, so signals travel tens of kilometres without amplification; and the carrier frequency of light is around 200 THz, so there is vastly more room to modulate information onto it. That is the whole argument — and it is also why the last hundred metres into your house is still copper: it is cheap and good enough.

Transmission modes

  • Serial — one bit at a time over one wire. Parallel — several bits at once over several wires. Parallel sounds faster but suffers skew: the bits on different wires arrive at slightly different times, and the faster and longer the link, the worse the skew. That is why USB, SATA, PCI Express and Ethernet are all serial: one very fast lane beats eight slow ones that will not stay in step.
  • Simplex — one direction only (a keyboard). Half-duplex — both directions but one at a time (a walkie-talkie; classic Ethernet with CSMA/CD). Full-duplex — both directions simultaneously (a telephone; modern switched Ethernet, which has separate transmit and receive pairs).
  • USB (Universal Serial Bus) deserves its own line because it is both a physical medium and a protocol: serial, host-controlled, with device detection, four transfer types, and power delivery over the same cable. It replaced a zoo of legacy ports, which is the standards argument in miniature.

Wireless networking

SSID
The network's human-readable name, broadcast by the access point in beacon frames so clients can find it. Hiding the SSID provides almost no security — it is still discoverable by listening for probe requests.
Channel
2.4 GHz Wi-Fi has 11–13 overlapping channels of which only 1, 6 and 11 do not overlap in most regions. Neighbouring networks on overlapping channels interfere, which is why channel selection matters in a dense building. 5 GHz has many more non-overlapping channels, and 6 GHz (Wi-Fi 6E/7) more again.
Wi-Fi standards
802.11n (2.4/5 GHz, MIMO), 802.11ac (5 GHz, wider channels, higher order modulation), 802.11ax / Wi-Fi 6 (OFDMA, better performance in crowded places), 802.11be / Wi-Fi 7 (6 GHz, multi-link). Higher frequency means more bandwidth but shorter range and worse penetration through walls.
Bluetooth
Low-power, short-range (≈10 m) PAN technology using adaptive frequency hopping across the 2.4 GHz band, which is how it coexists with Wi-Fi. Bluetooth Low Energy trades data rate for months of battery life on a coin cell.
WPA / WPA2 / WPA3
Wi-Fi encryption standards. WEP was broken and must never be used. WPA2 uses AES-CCMP and is still acceptable. WPA3 adds SAE (Simultaneous Authentication of Equals), which resists offline dictionary attacks, and forward secrecy, so a captured session cannot be decrypted later if the password is discovered.
Trap — "wireless is less secure because radio can be intercepted"

The radio medium being shared is a real fact, but on its own it is not a security argument, because modern Wi-Fi encryption protects the content. Write instead: the real risks are (i) a weak or reused pre-shared key allowing an attacker to join the network, (ii) a rogue access point impersonating the legitimate SSID to harvest credentials, (iii) legacy protocols such as WEP or WPA-TKIP that are genuinely broken, and (iv) the physical perimeter extending beyond the building into the car park. "Anyone can hear the signal" is only a threat if the signal is not encrypted.

Worked example 2 IB-style · 8 marks · evaluate a network architecture

Question. A school with 1200 students is choosing between a client–server network and a peer-to-peer network for storing student coursework. Evaluate the two options and recommend one.

  1. Requirements in this context: work must not be lost; only the right student should see their own file; teachers need access to their classes' work; the school must be able to back everything up and to prove what was submitted and when.
  2. Case for P2P: no server cost; no single point of failure; each student's own machine provides the storage.
  3. Case against P2P here: the files live on 1200 laptops that are switched off, at home, or broken, so availability is poor; there is no central backup, so a lost laptop is permanently lost coursework; access control cannot be enforced centrally, so a student can alter or delete another's work; and the school cannot produce a reliable submission record.
  4. Case for client–server: one authoritative copy on backed-up servers; permissions enforced centrally by the operating system; the school controls retention and can audit access; scaling is a matter of adding storage.
  5. Case against client–server: capital and running cost, an IT administrator's time, and a server outage that blocks everyone — mitigated by redundancy.
  6. Recommendation: client–server, because for assessed work the requirements of availability, integrity and auditability dominate, and only a central server can provide all three. P2P's cost advantage does not compensate for the risk of losing coursework that counts towards a qualification.
Where the marks are: 1–2 for identifying requirements specific to the scenario, 2–3 for advantages and disadvantages of both options (not just the one you prefer), 1–2 for a clear recommendation, 1–2 for justification tied back to the requirements. The word "however" and the phrase "on balance" are worth a mark each in the examiner's mind.

The cloud

"The cloud" means someone else's computer, reached over a network. The interesting content is the service model — how much of the stack you manage versus the provider.

Advantages of cloud

  • No capital expenditure — you rent instead of buying, turning a large upfront cost into a monthly operating cost.
  • Scalability and elasticity — capacity can grow at peak times and shrink afterwards, which a purchased server cannot do.
  • Availability and resilience — the provider replicates data across data centres in different regions, which a school or small firm could never afford.
  • Accessibility — anywhere with an internet connection, on any device.
  • Automatic updates and professional security operations.

Risks of cloud

  • Dependence on connectivity — no internet, no access to anything, including your own data.
  • Vendor lock-in — proprietary APIs and data formats make migrating expensive, so bargaining power shifts to the provider over time.
  • Loss of control over data location — data may be stored in another jurisdiction with different privacy laws, raising legal questions about which country's regulators can demand access.
  • Shared-responsibility confusion — the provider secures the infrastructure; you are still responsible for your accounts, permissions, encryption and configuration. Most cloud breaches are misconfigurations by the customer, not failures by the provider.
  • Cost unpredictability — metered pricing can rise sharply with unexpected traffic.

The internet of things

IoT means everyday objects embedded with processors, sensors and network connectivity so they can report on and act in the physical world. An embedded system is a computer built into a larger device to perform a dedicated function — as opposed to a general-purpose computer that runs many applications.

The pattern: sensors gather data from the environment → a microcontroller or small processor processes it → the device sends it over a network to a gateway and then the cloud → the service analyses and returns a decision → actuators act on it.

Why IoT security is structurally worse than PC security

Name four reasons and you have a high-scoring answer. (1) No update path — a £15 smart plug has no mechanism for the manufacturer to patch it, and no user will patch it anyway, so a vulnerability found after sale is permanent. (2) Default credentials — devices ship with admin/admin, are never changed, and are then swept up into botnets such as Mirai, which launched some of the largest denial of service attacks ever seen using nothing but cameras and routers. (3) Constrained hardware — no room for strong cryptography, secure boot, or an intrusion-detection agent. (4) Physical exposure and long lifecycles — a smart meter or a door lock is installed for fifteen years, sits somewhere an attacker can reach, and outlives the manufacturer's support window. Add the privacy dimension: these devices observe the inside of people's homes, so a data breach is not just a data breach.

Error detection and correction

No transmission medium is perfect: interference, attenuation and crosstalk flip bits. We cannot prevent that, so we detect it and ask for the data again.

Parity

Add one extra bit so the total number of 1s is even (even parity) or odd (odd parity). If a single bit flips in transit, the count changes and the receiver knows something is wrong.

Worked example 3 Parity bits — and the failure the exam wants you to spot

Question. (a) Add an even parity bit to 1011001. (b) The received byte is 10110011 — is it valid? (c) The transmitted byte was 10110011 and the received byte was 10000011. Is an error detected? Explain.

  1. (a) 1011001 has four 1s. Even parity needs an even count, so the parity bit is 0 → 10110010.
  2. (b) Received 10110011: that is five 1s — odd — so under even parity it is invalid: an error is detected.
  3. (c) 10110011 → 10000011: count the differing bits. Positions 3 and 4 both changed (1→0 and 1→0), so two bits flipped.
  4. The number of 1s goes from five to three — still odd — so the parity check passes and the error is not detected.
Answer: (a) 0; (b) invalid; (c) not detected. This is the limitation the examiner is fishing for: single parity detects any odd number of bit errors and misses any even number. It also cannot correct anything — it only detects.

Check digits

A check digit is an extra digit computed from the others and appended to an identification number, so that a mistyped or mis-scanned number is rejected. The classic scheme is modulus-11 or the weighted ISBN-10 check digit.

Worked example 4 IB-style · 6 marks · ISBN-10 check digit

Question. The ISBN-10 check digit is computed by multiplying the first nine digits by 10, 9, 8, …, 2, summing the products, finding the remainder when divided by 11, and subtracting that remainder from 11; a result of 11 becomes 0 and a result of 10 becomes X. Calculate the check digit for the first nine digits 0-306-40615.

  1. Digits: 0, 3, 0, 6, 4, 0, 6, 1, 5. Weights: 10, 9, 8, 7, 6, 5, 4, 3, 2.
  2. Products: 0 + 27 + 0 + 42 + 24 + 0 + 24 + 3 + 10 = 130.
  3. 130 mod 11: 11 × 11 = 121, so remainder = 9.
  4. Check digit = 11 − 9 = 2.
  5. Full ISBN: 0-306-40615-2.
  6. Why the descending weights matter: if two adjacent digits are transposed, the sum changes by the difference of the weights — a non-zero amount — so the error is caught. With equal weights, a transposition would leave the sum unchanged and go undetected.
Answer: 2. The scheme catches all single-digit errors and all transpositions of adjacent digits, because 11 is prime and the weights are distinct. That "because" clause is the difference between a 4 and a 6.

Checksums

A checksum is a value computed from a block of data — often a simple sum, or the ones-complement sum used in the IP header — and transmitted with it. The receiver recomputes it and compares. Checksums are stronger than single-bit parity because they depend on the values of all the bytes, but they are still not cryptographic: an attacker who modifies data can simply recompute the checksum. That is why integrity against a deliberate attacker needs a cryptographic hash (SHA-256) or a message authentication code, not a checksum.

ARQ — Automatic Repeat reQuest

Detection is only useful if you can recover. ARQ is the mechanism: the receiver acknowledges correctly received packets (ACK) and the sender retransmits anything not acknowledged before a timeout. Stop-and-wait ARQ sends one packet and waits — correct but slow, because the link is idle during the round trip. Sliding-window / Go-Back-N keeps several packets in flight, so the pipe stays full, and a loss causes the retransmission of the window. This is precisely what TCP implements at layer 4.

Connection

Error detection and ARQ are the reason TCP is called "reliable" while the IP layer underneath it is not: IP detects corruption via the header checksum but simply discards bad packets; TCP notices the gap in sequence numbers and asks for the data again. The theme of layering is that each layer adds a guarantee the one below does not provide.

How to use it — the SQL injection answer

If asked to explain SQL injection and how to prevent it, write this: a web form's input is concatenated into a query string, so the query becomes SELECT * FROM users WHERE name = '' OR '1'='1' --' AND pw = ''. The OR '1'='1' makes the condition always true and -- comments out the rest, so the attacker is logged in as the first user without a password. The correct defence is a parameterised query, in which the SQL text is fixed and the user's value is bound to it as data that can never be parsed as code. Always say "parameterised queries", not "validate the input" — validation is defence in depth, but parameterisation is the actual fix.

Defences

Firewall
Filters traffic between networks against a rule set (by address, port, protocol). A packet-filtering firewall examines headers only; a stateful inspection firewall tracks connections and only allows apparently related inbound traffic. Firewalls do not inspect encrypted traffic and cannot stop an attack that arrives through an allowed port.
Proxy server
An intermediary that makes requests on the client's behalf. It hides internal IP addresses, can cache frequently requested content (saving bandwidth), filter content, and log usage. Because it terminates the connection, it can inspect traffic a firewall cannot.
Encryption
Renders data unreadable without the key. Symmetric encryption (AES) uses one shared key — fast, so it encrypts bulk data, but key distribution is a problem. Asymmetric encryption (RSA, ECC) uses a public/private key pair — slow, so it is used to exchange a symmetric session key and to create digital signatures. Real systems (TLS) use both: asymmetric to establish the session, symmetric to carry it.
Authentication
Proving identity. The three factors are something you know (password), something you have (phone, security key) and something you are (biometric). Multi-factor authentication combines two different kinds — two passwords is not MFA. It defeats phishing and password reuse, which is why it is the single highest-value control available.
Digital certificate
An electronic document binding a public key to an identity, signed by a trusted certificate authority. Your browser trusts the CA, so it trusts the certificate, so it trusts the key — that chain is what lets you know the site really is your bank and not a man in the middle.
Physical security
Locked server rooms, badge access, CCTV, cable locks, screened network sockets, and secure disposal of storage media. It is overlooked constantly, and it is decisive: anyone with physical access to an unencrypted disk owns the data on it, no matter how good the firewall is.
Why Why the CIA triad is the organising idea — and why it is a triangle of tensions
  1. Confidentiality — only authorised parties can read the data. Integrity — data has not been altered, by accident or on purpose. Availability — authorised parties can access it when they need it.
  2. Every security measure serves one of the three, and every security question can be classified by asking which one is at risk: encryption serves confidentiality; checksums, signatures and backups serve integrity; redundancy and DDoS mitigation serve availability.
  3. The tension: making data more confidential (strong encryption, air-gapping, complex approval) usually makes it less available. Making it more available (many copies, wide access) makes confidentiality harder. Requiring strict integrity checks adds latency.
  4. Therefore security is not a state you reach but a set of trade-offs you choose, and the right choice depends on the asset. A hospital's patient records need all three, and the correct answer to "which is most important" is "they conflict, and here is how I would balance them for this asset".

When it is the wrong frame: privacy is not the same as confidentiality — data can be perfectly confidential yet used in a way the subject never agreed to. Keep the two ideas separate in your answer.

Exam technique — the "evaluate a network choice" 6–8 mark answer

These questions are formulaic, and the formula scores. Write five short paragraphs:

  1. Requirements. Restate what the scenario needs: how many users, how far apart, what is carried, how sensitive, what the budget implies, whether mobility matters. Two sentences.
  2. Option A — advantages in this context. Two points, each with a consequence ("so …", "which means …").
  3. Option A — disadvantages in this context. Two points, same treatment.
  4. Option B — the same four points. If you only evaluate the option you prefer, you have written a justification, not an evaluation, and you cap your mark.
  5. Recommendation and justification that refers back to paragraph 1. "I recommend X because the scenario's priority is Y, and X delivers Y while its main drawback, Z, can be mitigated by…"

The final sentence is the one most answers omit and the one that carries the top-band mark.

Practice

  1. State two differences between a LAN and a WAN.

    Show answer

    A LAN covers a small geographic area (one building or site) and its infrastructure is usually owned by the organisation using it; a WAN spans a large area (a country or the world) and the links are usually leased from telecommunications carriers. Consequently a LAN typically offers higher bandwidth and lower latency at lower cost, while a WAN is slower, more expensive, and less secure by default because it crosses infrastructure you do not control.

  2. A small office uses a star topology with a single central switch. Describe what happens if (a) one workstation's cable is cut, and (b) the switch fails. Hence explain why the switch is described as a single point of failure.

    Show answer
    1. (a) Only that workstation loses connectivity; every other node continues to work because each has its own dedicated cable to the switch.
    2. (b) All communication stops — no node can reach any other, and shared resources such as the printer or server become unreachable.
    3. A single point of failure is a component whose failure disables the whole system. In a star, the central device carries all traffic, so its failure is total even though the cabling is individually robust.
    4. Mitigation worth a mark: a second (redundant) switch, or a resilient stack, so that one device failure is survivable.

  3. Explain the role of the transport layer and the network layer when a file is sent from one computer to another, and state which layer's address changes at each router.

    Show answer

    The transport layer (TCP) splits the file into segments, numbers them with sequence numbers, adds source and destination port numbers to identify the sending and receiving applications, acknowledges received segments, retransmits those that are lost, and reorders segments that arrive out of sequence. The network layer (IP) places each segment in a packet with source and destination IP addresses and makes the routing decision that moves it one hop closer to its destination.

    At each router the layer-2 (MAC) addresses change — the router strips the incoming frame and builds a new one addressed to the next hop — while the IP addresses remain unchanged for the whole journey, because they identify the ultimate endpoints, not the current hop.

  4. Describe how a DNS lookup resolves www.school.edu to an IP address, naming the servers involved.

    Show answer
    1. The client checks its own cache, then the operating system cache, then queries the configured recursive resolver.
    2. The resolver queries a root name server, which returns the address of the TLD server for .edu.
    3. The resolver queries that TLD server, which returns the address of the authoritative name server for school.edu.
    4. The resolver queries the authoritative server for www.school.edu and receives the A/AAAA record.
    5. The answer is returned to the client and cached for the record's TTL so subsequent lookups are answered locally.
    Marks: one each for the resolver, the root server, the TLD server, the authoritative server, and caching/TTL.

  5. A company with 200 staff in two buildings 3 km apart must connect them. Evaluate the use of a wireless link rather than a fibre link.

    Show answer
    1. Requirements: 200 staff, so substantial and continuous traffic; 3 km is short; this is a permanent business-critical link between two fixed buildings.
    2. Wireless — for: no wayleave or digging required, so much lower installation cost and much faster to deploy; the two buildings need line of sight but no road crossing or third-party permission.
    3. Wireless — against: throughput is lower and shared with other users of the band; performance degrades in heavy rain, especially at higher frequencies; the signal is broadcast, so it depends entirely on strong encryption and is vulnerable to interception or jamming; interference from other users is outside the company's control; for 200 staff it is likely to be a bottleneck.
    4. Fibre — for: very high bandwidth, low latency, immune to electromagnetic interference, unaffected by weather, and physically secure because tapping is detectable. For a 3 km permanent link between fixed buildings, the civil-engineering cost is a one-off and the link will serve the company for decades.
    5. Fibre — against: high initial cost and installation time; requires permission to dig and skilled termination; the cable is a physical asset that could be cut by third-party works.
    6. Recommendation: fibre, because the buildings are fixed and close, so the one-off installation cost is justified by capacity, reliability and security for 200 users — and a wireless link could be retained as a backup for resilience.
    Where the marks are: requirements stated, both options evaluated with a for and an against, a recommendation, and justification that returns to the scenario. Offering the hybrid (fibre primary, wireless backup) is the kind of synthesis that reaches the top band.

  6. Using even parity, state whether each received byte contains a detectable error: (a) 11010110, (b) 10101010, (c) 11110000.

    Show answer
    1. (a) 11010110 has five 1s — odd — so under even parity it is invalid; an error is detected.
    2. (b) 10101010 has four 1s — even — so it passes; no error is detected (though an even number of bit errors could still be present).
    3. (c) 11110000 has four 1s — even — so it also passes.
    Answer: (a) error detected; (b) and (c) no error detected. Remember to add: parity cannot correct the error and cannot detect an even number of bit flips.

  7. Explain the difference between symmetric and asymmetric encryption, and explain why real systems such as TLS use both.

    Show answer
    1. Symmetric encryption uses one shared secret key for both encryption and decryption. It is fast and suitable for bulk data, but the key must be shared in advance over a secure channel — which is exactly what you do not have when talking to a stranger on the internet.
    2. Asymmetric encryption uses a key pair: anything encrypted with the public key can only be decrypted with the private key. The public key can be published freely, which solves key distribution, but the mathematics is far slower.
    3. TLS uses both: asymmetric cryptography authenticates the server (via its certificate) and securely agrees a fresh symmetric session key; then symmetric encryption carries the actual data at speed.
    4. A bonus point worth a mark: the session key is ephemeral, giving forward secrecy — if the server's long-term private key is compromised later, previously recorded sessions cannot be decrypted.

  8. Discuss the security implications of installing internet-connected cameras in a hospital.

    Show answer

    A four-part answer.

    1. Stakeholders: patients, clinical staff, hospital management, IT, visitors, and insurers.
    2. Benefits and the security case for: footage deters theft of drugs and equipment, helps investigate incidents, and can support patient safety in corridors and entrances.
    3. Risks: cameras in clinical areas may record patients in vulnerable moments, which is a severe confidentiality breach and possibly unlawful; default credentials and unpatched firmware make IoT cameras an easy entry point into the network, from which an attacker can move laterally to clinical systems; a compromise of the recording server is a single point of failure for all footage; and continuous recording of staff enables function creep into performance monitoring.
    4. Controls: network segmentation so cameras cannot reach clinical systems, unique credentials and a patching regime, encryption in transit and at rest, retention limits, no cameras in treatment or bathroom areas, visible signage, and a documented lawful basis for processing.
    5. Judgement: acceptable in public areas with the controls above; not acceptable in areas where patients have a reasonable expectation of privacy, because there the security benefit does not outweigh the harm.
