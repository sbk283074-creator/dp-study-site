Computer Science HL (2027 guide)

You are sitting a different course from the one most IB resources describe. The 2014 guide — seven topics, four options, a standalone Paper 3 on the case study — is gone. The new course is two themes (A: how computing systems work; B: how you use them to solve problems), a pre-seen case study examined inside Paper 1, an internal assessment that is explicitly about the computational thinking process, and a ten-hour collaborative project shared with the sciences. Almost every free website you will find is still describing the old one. This page tells you what you are actually being examined on so the rest of this section makes sense.

HL: 240 teaching hours (SL: 150) HL only: A1.4 Translation · A3.4 Alternative databases · A4.2/A4.3 ML · B3.2 multiple classes · all of B4 Paper 1: theme A + case study · Paper 2: theme B (Java or Python)
Why this page matters more than it looks

Search "IB computer science topic 4" or "IB CS option D" and you will find thousands of pages describing content that is no longer examined. Worse, the old guide's topic numbering (1 Systems, 2 Computer organisation, 3 Networks, 4 Computational thinking…) overlaps misleadingly with the new A/B codes. If you revise from an old resource you will waste hours on object-oriented-option content that has moved, on a Paper 3 format that does not exist, and on a case study that is now examined quite differently. Learn the new map first, then fill it in.

Trap — "but I found a great resource"

Three tells that a resource is for the old course: it numbers topics 1–7; it mentions "Option D" or "the option"; it says Paper 3. Two tells it is for the new one: it uses codes like A1.2 or B4.1, and it mentions the collaborative sciences project. Content that survives from the old course (binary, SQL, OOP, networks) is still valid — the danger is missing the new content (A4 machine learning, B4 sets and hash tables, A1.4 translation, A3.4 alternative databases) because no old index lists it.

How Paper 1 and Paper 2 differ — and what each actually rewards

Paper 1 — theme A + case study (2 hours, 40 %)

What it tests: whether you understand how systems work and can reason about their consequences. Questions are explain, describe, compare, evaluate, discuss, to what extent. No programming.

What earns marks: correct technical mechanism plus a consequence. "A star topology uses a central switch" is one mark; "…so a single cable failure disconnects one node rather than the whole network, but the switch is a single point of failure" is three.

What loses marks: writing a definition when the question said explain; giving one side of an evaluate; describing a technology without ever connecting it to the stakeholders in the case study.

Paper 2 — theme B (2 hours, 40 %)

What it tests: whether you can read, trace, complete, write and justify algorithms in Java or Python, and (HL) work with abstract data types.

What earns marks: precision. Array indices, loop bounds, the exact value printed, the correct keyword. This is the most objective paper in the DP sciences — a trace either matches the markscheme or it does not.

What loses marks: off-by-one errors in traces; writing pseudocode-ish half-code that is neither Java nor Python; forgetting that the exam's own pseudocode is not what you should write when the question asks for Java or Python.

Exam technique — the two-hour arithmetic

Two hours for roughly 60–70 marks of HL material is about 1.7 minutes per mark. That sounds generous until you meet a 12-mark evaluate question. Budget: spend the first 90 seconds reading the whole paper and putting a tick next to the questions you can do cold; do those first, fast; leave the big evaluate and discuss items for last with a ring-fenced 20 minutes. An unfinished 8-mark evaluation costs you more than a slow 3-mark explanation ever will.

Java or Python: how to choose

The IBO does not care which you pick; Paper 2 questions are set so either works. Your choice should be made on three grounds, in this order.

  1. Which one does your school actually teach through to the end of B3 and B4? This dominates everything else. Self-teaching Java's type system and class syntax late in DP2 is a real cost.
  2. Which one do you write faster under time pressure? Python is terser — a hash table is a dictionary literal, a list is built in, and you write maybe 40 % fewer characters. In a two-hour handwritten exam that is a genuine advantage.
  3. Which one makes your IA stronger? If your computational solution needs a GUI, a web API, or a data-science library, Python wins. If it needs a clean OO design with inheritance and interfaces to show off B3.2, Java's explicitness helps — the marker can see extends, implements and private.
How to use it — write one language, read both

Pick one for the exam and write it exclusively from the moment you start B2. But you must be able to read the other, because textbooks, Stack Overflow and past paper answers will use it. Concretely: by the end of B2 you should be able to look at a Java for (int i = 0; i < a.length; i++) and a Python for x in a: and know instantly that the first gives you the index and the second gives you the value. Every code box on the B2 and B3 pages of this site shows both, labelled, for exactly this reason.

Trap — exam pseudocode is not a language

The IB uses its own pseudocode in exam questions (see the B1 page for the full convention). It looks like English: output, if ... then ... else ... endif, loop while ... endloop, MOD, DIV. When a question says "write pseudocode", write that. When it says "write Java" or "write Python", write real, compilable code with semicolons, braces or indentation, and the language's own keywords. Writing output "x" inside a Python answer is not a style choice; it is a syntax error and it costs marks.

How theme A and theme B connect

Connection — the IA is the point of the course

The IBO describes the internal assessment as "a unifying assessment, bringing together both theme A and theme B". Read the map above that way: a student who builds a booking system (B2, B3) that stores records in a normalised database (A3), runs over a network with authentication (A2), maybe predicts demand with a small model (A4), and documents the decomposition that got them there (B1) has used the entire course. That is what a 7-scoring IA looks like — not a clever program, but a program whose documentation shows every theme being used deliberately.

A study sequence that works

You have roughly two years. The order below is not the order of the syllabus; it is the order that minimises the number of times you have to learn something twice.

  1. B1 Computational thinking (first). You cannot program without it, and the pseudocode convention you learn here is the language every exam question is written in. Do it before B2, not alongside it.
  2. B2 Programming. Variables → selection → iteration → arrays → strings → sub-procedures → files → recursion. Write code every single week; reading code is not learning to code.
  3. A1 Computer fundamentals. Binary, hex, two's complement, logic gates. It is self-contained and heavily examined in Paper 1, so doing it early banks easy marks.
  4. B3 OOP. Needs B2 to be solid. Do the single-class work (B3.1) before inheritance (B3.2).
  5. A3 Databases. SQL is a second language; give it a clean block of time. It pays for itself because SQL questions are mechanical and therefore reliably scorable.
  6. A2 Networks. Heavy on terminology and on evaluate questions — better attempted once your English is warmed up and you have written a few evaluations elsewhere.
  7. B4 Abstract data types (HL). This is the hardest topic in the course. Put it after B2, B3 and B1, and only when you can already trace recursion comfortably.
  8. A4 Machine learning. New content, conceptually light but examinable in depth. Needs A3 (data) and B1 (thinking about algorithms) to land well.
  9. Case study + IA, interleaved from the middle of DP1. The case study is released once; study it when your school says. The IA should be started early and finished early — see the IA page for a 12-week plan.
Exam technique — learn the command terms before you learn the content

The single cheapest mark-improvement available to you is knowing what evaluate asks for that describe does not. Roughly: state = one fact; describe = give the characteristics; explain = give reasons (cause → effect); compare = similarities and differences; contrast = differences only; justify = give a reason and reach a supported conclusion; evaluate = weigh advantages and disadvantages and reach a judgement; discuss = consider different viewpoints, usually with no single right answer; to what extent = how far is the statement true, and where does it break. An evaluate answer with no judgement caps at about half marks no matter how accurate it is.

Check yourself

Practice

  1. A classmate says: "I'm revising from a 2019 website — it has topics 1 to 7, so it covers everything." Give three specific reasons why that is a bad idea.

    Show answer
    1. Missing content. Machine learning (A4) was not in the old core, and B4 sets and hash tables, A1.4 translation and A3.4 alternative databases are new or re-scoped. No amount of old revision produces those marks.
    2. Wrong assessment format. The old course had a Paper 3 for the case study at HL only. There is no Paper 3 now, and the case study is examined inside Paper 1 at both levels.
    3. Wrong language expectation. Paper 2 now expects real Java or Python, where the old course accepted IB-style pseudocode throughout. Practising only pseudocode leaves you unable to write syntactically valid code under exam conditions.
    4. (Bonus: option content was examined differently, so the depth and question style will not match.)
    Marks: one per specific, correct difference that names both the old and the new arrangement. A vague "it's outdated" scores nothing.

  2. State the HL teaching hours for each of: theme A, theme B, the case study, the internal assessment and the collaborative project. Hence show that the HL total is 240 hours.

    Show answer

    Theme A = 72, theme B = 93, case study = 30, internal assessment = 35, collaborative project = 10.

    72 + 93 + 30 + 35 + 10 = 240. ✓

    Answer: 240 hours. Also check the SL arithmetic: 38 + 52 + 15 + 35 + 10 = 150. ✓ Both totals matching is a good self-test that you have the right figures.

  3. Explain why the internal assessment is worth a smaller percentage at HL (20 %) than at SL (30 %) even though both levels get the same 35 recommended hours.

    Show answer
    1. HL students sit 4 hours of external assessment; SL students sit 2 hours 30 minutes.
    2. Because the IA is the same size at both levels, it forms a smaller share of a larger total assessment burden at HL.
    3. The consequence for you: HL grades are decided more by the exams. Strong HL students should not over-invest in the IA at the expense of Paper 1 and Paper 2 practice — but the IA is still 20 % and is the component where careful work is most reliably rewarded.

  4. You are choosing between Java and Python for Paper 2. Discuss two factors that should influence your choice and one that should not.

    Show answer

    Should influence: (i) which language your school teaches to completion of B3/B4 — self-teaching a type system late is expensive; (ii) how fast you write correct code by hand — Python's terseness is a real advantage in a handwritten exam; (iii) which language suits your IA (libraries vs explicit OO structure).

    Should not influence: which language you think the examiner prefers. The IBO sets Paper 2 so that either language scores full marks; there is no advantage either way in the markscheme.

  5. A question says: "Evaluate the use of a relational database for this application." A student writes four accurate sentences describing what a relational database is. Explain why this answer cannot score high marks, and state what an evaluate answer must contain.

    Show answer
    1. The command term is evaluate, which requires weighing advantages against disadvantages and reaching a supported judgement. Description alone answers a different question ("describe"), so it cannot access the higher markband.
    2. An evaluate answer needs: (i) the advantages in this context (e.g. enforces referential integrity, supports ad-hoc SQL queries, reduces redundancy); (ii) the disadvantages in this context (e.g. fixed schema is inflexible, overhead of a DBMS, harder to scale horizontally than a document store); (iii) a conclusion that says which consideration wins for this application and why.
    Rule of thumb: if your answer has no "however" and no "therefore", it is not an evaluation.

  6. Identify the two HL-only sub-topics inside theme A and the two HL-only sub-topics inside theme B, and state what each adds.

    Show answer

    Theme A: A1.4 Translation (HL only) — how high-level code becomes machine code: compilers, interpreters, assemblers, bytecode and virtual machines. A3.4 Alternative databases and data warehouses (HL only) — non-relational (NoSQL) models and why they exist, plus data warehouses for analysis.

    Theme B: B3.2 Fundamentals of OOP for multiple classes (HL only) — inheritance, polymorphism, aggregation/composition, UML between classes. B4 Abstract data types (HL only, the entire topic) — ADT principles, linked lists, binary search trees, sets, hash tables.

    Also HL-only: A4.2 Data preprocessing and A4.3 Machine learning approaches inside A4. That makes six HL-only codes in total — learn the list, because it tells you exactly where SL students stop.

  7. Suggest why the IBO moved the case study from a separate HL Paper 3 into Paper 1, and why it introduced the case study at SL too.

    Show answer
    1. Paper 3 was removed; folding the case study into Paper 1 keeps assessment of theme A and its real-world application in one paper, and reduces the number of separate papers to schedule and mark.
    2. Emerging technologies affect every citizen, so restricting that discussion to HL was inconsistent with the course's stated aim of producing informed users of technology.
    3. Introducing it at SL raises the proportion of the course spent on social and ethical reasoning, which aligns with the IBO's broader emphasis on ethical thinking across the DP.
    Marks: one for each plausible, developed reason. "Because they wanted to" is not a reason.
