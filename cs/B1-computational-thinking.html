Computer Science HL · Theme B · B1

B1 · Computational thinking

Computational thinking is not "thinking about computers" — it is the habit of taking a vague, messy real-world problem and reshaping it until a machine could carry it out. The five strands the syllabus names (think procedurally, logically, ahead, concurrently, abstractly) are not a list to memorise; they are five questions you ask yourself when you get stuck. Do this topic first, because every other B topic assumes it, and because the IB pseudocode you learn here is the language every Paper 2 question is written in.

Theme B · examined in Paper 2 B1.1 Approaches to computational thinking HL and SL share B1; HL goes deeper in efficiency analysis

The five strands

Each strand below is given with a worked example, because a definition alone earns nothing.

1 · Think procedurally

Break the problem into ordered steps, and notice where the same step repeats so it can become a procedure with parameters rather than being written twice.

Example. "Work out the student with the highest average mark." Procedural thinking turns this into: for each student, sum their marks and divide by how many there are; keep a record of the best average so far and the name that goes with it; whenever a student's average beats the best so far, replace both. Two sub-problems appear (average of one student; find the maximum over many), and the second is a pattern you will use for the rest of your life.

2 · Think logically

Decisions must be exhaustive and exclusive: every possible input must take exactly one path.

Example. "Grade the exam: A above 80, B above 70, C above 60, otherwise fail." Write it in descending order with a final catch-all: if mark > 80 then "A" else if mark > 70 then "B" else if mark > 60 then "C" else "Fail". Written in ascending order (if mark > 60 then "C" first), a mark of 85 is caught by the first branch and graded C — a logic error, not a syntax error, so the program runs and silently gives wrong grades. That is the practical meaning of thinking logically.

3 · Think ahead

Design for inputs you have not seen yet, and for the consequences of your own choices.

Example. You write a program that reads a class list. Thinking ahead means asking: what if the file is empty? What if a name contains an apostrophe? What if there are 40 students rather than 30? What if someone runs it twice? What if the input is a number where you expected text? Every one of those is a decision you make now, cheaply, rather than a bug you find later, expensively. It is also what makes your IA strong: a testing table with boundary and erroneous data is "thinking ahead" written down.

4 · Think concurrently

Notice which parts of a task do not depend on each other, and could therefore happen at the same time.

Example. A program downloads ten images and then processes each one. Downloading is limited by the network; processing is limited by the CPU. They do not contend for the same resource, so while image 3 is downloading, images 1 and 2 can be processed. The parts that must stay in order are the ones with a genuine dependency: you cannot process an image before it has arrived. Concurrency is the study of which orderings are real constraints and which are accidents of how you happened to write the code.

5 · Think abstractly

Decide what to keep and what to discard, and give the thing you kept a name.

Example. A navigation app does not model roads. It models a graph: places as nodes, journeys as edges with a cost. It discards the road's surface, its width, its colour, whether it has a shop on it — and keeps exactly one number, the travel time. That act of discarding is what makes the problem solvable at all, and it is why the same shortest-path algorithm works for road networks, internet routing, and the number of edits between two words. Abstraction is the highest-value of the five strands and the one that most often appears in 6-mark "explain" questions.

Connection

Abstraction is the same idea in every topic: it is the layer model in A1, the E-R model in A3, the feature selection in A4, the class in B3, and the ADT in B4. In each case the pattern is identical — hide the representation, expose the operations. If you can state that sentence and illustrate it with two examples from different topics, you have the connections question in the bag.

Decomposition, pattern recognition and generalisation

Decomposition
Breaking a large problem into smaller sub-problems, each of which is independently solvable and testable. The test of a good decomposition: you can name each piece, you can test each piece on its own, and changing one piece does not force changes in the others.
Pattern recognition
Noticing that sub-problems share a structure. If three parts of your program each "find the largest thing in a collection", that is one sub-procedure with a parameter, not three pieces of code.
Generalisation / abstraction
Rewriting the solution to the shared structure so it works for any instance: not "find the highest mark in Mr Lee's class" but "find the maximum value in an array of numbers", or better, "find the element that ranks highest by a given comparison".
Worked example 1 IB-style · 6 marks · decompose and abstract

Question. A school wants a program that, from a file of pupils each with a list of test scores, prints the name of the top pupil in each year group and the school average. (a) Decompose the problem. (b) Identify one place where pattern recognition reduces the work. (c) Identify one abstraction.

  1. (a) Decomposition: (i) read the file into a collection of pupil records; (ii) for one pupil, compute their average score; (iii) find the pupil with the highest average within one year group; (iv) compute the mean across all pupils; (v) format and output the results.
  2. Each sub-problem can be written and tested separately: you can test (ii) on a made-up pupil without any file, and (iii) on a made-up list.
  3. (b) Pattern: "highest average within year 10", "highest average within year 11", "highest average within year 12" are the same computation with a different filter. So write one sub-procedure topPupil(pupils, year) and call it three times.
  4. (c) Abstraction: a pupil is reduced to just the attributes the problem needs — name, year group, and the list of scores. Address, date of birth, medical notes and photo are discarded because they cannot affect the answer. Equally, "the file" is abstracted into "a collection of pupil records", so the rest of the program does not care whether the data came from a CSV, a database or a keyboard.
Marks: 2 for a decomposition with at least four named, independently testable sub-problems; 2 for recognising that the per-year computation is one parameterised procedure; 2 for identifying what is discarded and why. "It makes it simpler" is not an abstraction — say what is kept and what is thrown away.

Algorithm design tools

Structured English

Numbered steps in plain language, precise enough to be unambiguous but without code syntax. It is the right first draft: you can show it to a non-programmer (your IA client!) and they can tell you whether it is correct.

1. Set bestAverage to 0 and bestName to an empty string.
2. For each pupil in the list:
   2.1 Add up all of that pupil's scores.
   2.2 Divide the total by the number of scores to get the average.
   2.3 If this average is greater than bestAverage:
        set bestAverage to this average
        set bestName to this pupil's name.
3. Output bestName and bestAverage.

Flowcharts

Trap — flowchart arrows and decision labels

Three habits lose marks. (1) A decision diamond drawn with one arrow out instead of two. (2) Both branches labelled "yes" — or worse, unlabelled. (3) A loop with no exit: if the arrow back into the loop cannot be avoided, your algorithm is infinite. Always check that every diamond has exactly two labelled exits and that every loop has a condition that can eventually become false.

Exam technique — pseudocode earns logic marks, not style marks

Examiners are instructed to accept any unambiguous pseudocode. You will not lose a mark for writing endwhile instead of endloop, or for using Python-style indentation. You will lose marks for: an ambiguous condition, a missing block terminator so the reader cannot tell what is inside the loop, or using a variable that was never initialised. Indentation is free and it is the single best way to signal structure — use it even though the IB convention also uses explicit terminators.

Trap — MOD and DIV are not the same as / and %

DIV is integer division: it gives the whole-number quotient and throws away the remainder. MOD gives the remainder. So 17 DIV 5 = 3 and 17 MOD 5 = 2, and the identity \(a = (a \text{ DIV } b) \times b + (a \text{ MOD } b)\) always holds. In Python these are // and %; in Java / on two ints is DIV and % is MOD, but / on a double is ordinary division — the classic source of "why is my average zero?" bugs.

Trace tables

A trace table records the value of every variable after each significant step. It is the only reliable way to answer "state the output of this algorithm" and the only reliable way to debug a loop. The method:

How to use it — build the table mechanically
  1. Make one column per variable plus one for output. Include loop counters and accumulators.
  2. Write the initial values as the first row.
  3. Walk the algorithm one line at a time. Every time a variable changes, add a row.
  4. At a loop, evaluate the condition before each pass and stop when it is false.
  5. Never do two steps in your head at once — that is where errors enter.
  6. Sanity-check at the end: does the final value make sense?

Worked example 3 IB-style · 7 marks · trace with a sub-procedure and by-reference parameters

Question. State the output.

procedure bump(a, b)
    a = a + 10
    b = b * 2
    output a, b
endprocedure

x = 5
y = 3
bump(x, y)
output x, y
  1. Initial: x = 5, y = 3.
  2. Call bump(x, y) with pass by value (the default in the IB pseudocode model): the procedure receives copies, so a = 5 and b = 3 locally.
  3. Inside: a = 15, b = 6. Output: 15 6.
  4. Return. The copies are discarded; x and y in the main program are unchanged.

Answer: "15 6" then "5 3". The mark hinges on knowing the parameter-passing convention: with pass by value the caller's variables cannot change. If the question states (or your language uses) pass by reference — as Python does for mutable objects such as lists, and as Java does for arrays and objects — then y would be changed in the caller. Always state which convention you are assuming; that sentence is itself often awarded a mark.

Standard algorithms

Find maximum / minimum, count, sum, average

All four share one skeleton: initialise an accumulator, loop over the collection, update the accumulator, output it. The only thing that changes is the initial value and the update rule — and the initial value is where the bugs live.

// maximum of an array A of n values, indices 0..n-1
maxVal = A[0]                 // NOT 0 — see the trap below
loop for i = 1 to n - 1
    if A[i] > maxVal then
        maxVal = A[i]
    endif
next i
output maxVal
Trap — initialising the maximum to zero

maxVal = 0 is wrong whenever all the values could be negative: with the array [-5, -2, -9] the algorithm would report 0, a value that is not in the array at all. Always seed the accumulator with the first element and start the loop at index 1. Symmetrically, when finding a minimum, seed with the first element rather than 0 — otherwise an array of positive values reports 0. And when counting or summing, seed with 0 and divide by the count, never by a hard-coded constant.

Linear search

found = false
index = -1
i = 0
loop while (found = false) AND (i < n)
    if A[i] = target then
        found = true
        index = i
    endif
    i = i + 1
endwhile
output index

It examines elements one by one until it finds the target or runs out. It works on unsorted data, which is its main virtue. On average it examines half the elements; at worst all of them.

Binary search

low = 0
high = n - 1
found = false
loop while (low <= high) AND (found = false)
    mid = (low + high) DIV 2
    if A[mid] = target then
        found = true
    else
        if A[mid] < target then
            low = mid + 1        // discard the left half INCLUDING mid
        else
            high = mid - 1       // discard the right half INCLUDING mid
        endif
    endif
endwhile
Why Why binary search needs sorted data, and why it is O(log n)
  1. The algorithm's entire claim is: if A[mid] < target, then because the array is sorted, every element at index ≤ mid is also less than the target, so the target cannot be in the left half and we may discard it.
  2. That inference is only valid because of the ordering property. On unsorted data, "A[mid] is too small" tells you nothing at all about A[mid−1], so discarding half the array is unjustified and the algorithm can return "not found" for an element that is present. This is why "state the precondition" is a one-mark question that follows every binary search question.
  3. Why log₂ n. Each comparison halves the search space: n → n/2 → n/4 → … → 1. After k comparisons the remaining space is \(n / 2^{k}\). The search ends when that reaches 1, so \(n / 2^{k} = 1\), giving \(2^{k} = n\) and \(k = \log_{2} n\).
  4. So 1 000 000 elements need at most about \(\log_{2}(10^{6}) \approx 20\) comparisons, against 1 000 000 for a linear search in the worst case. That is the entire argument for sorting data you intend to search repeatedly.
  5. The catch: sorting costs O(n log n), so if you search once it is not worth sorting first. Sort once, search many times — that is when binary search pays.

What it means: the log behaviour is not a rule to memorise; it falls out of halving. When it is the wrong tool: on a small array, or on a linked list, where there is no random access to the middle element at all.

Bubble sort

swapped = true
loop while swapped = true
    swapped = false
    loop for i = 0 to n - 2
        if A[i] > A[i+1] then
            temp   = A[i]
            A[i]   = A[i+1]
            A[i+1] = temp
            swapped = true
        endif
    next i
endwhile

Each pass walks the array comparing adjacent pairs and swapping any that are out of order, so the largest remaining value "bubbles" to the end. The swapped flag is the optimisation: if a whole pass makes no swap, the array is sorted and the algorithm can stop early.

Worked example 5 IB-style · 6 marks · bubble sort pass by pass

Question. Show the state of the array after each pass of bubble sort on [5, 2, 9, 1, 3], and state how many comparisons and swaps occur in total.

  1. Pass 1: compare 5,2 → swap → [2,5,9,1,3]; compare 5,9 → no swap; compare 9,1 → swap → [2,5,1,9,3]; compare 9,3 → swap → [2,5,1,3,9]. The 9 is in its final place. (4 comparisons, 3 swaps.)
  2. Pass 2: 2,5 no swap; 5,1 swap → [2,1,5,3,9]; 5,3 swap → [2,1,3,5,9]. The 5 is placed. (3 comparisons, 2 swaps.)
  3. Pass 3: 2,1 swap → [1,2,3,5,9]; 2,3 no swap. (2 comparisons, 1 swap.)
  4. Pass 4: 1,2 no swap. (1 comparison, 0 swaps.) No swaps occurred, so the flag stops the algorithm.
  5. Totals: 4 + 3 + 2 + 1 = 10 comparisons; 3 + 2 + 1 = 6 swaps.
Answer: [2,5,1,3,9] → [2,1,3,5,9] → [1,2,3,5,9] → [1,2,3,5,9]; 10 comparisons, 6 swaps. Marks: 1 per correct pass, 1 for the totals. Notice the pattern: for n = 5 the comparisons are 1 + 2 + 3 + 4 = 10 = n(n−1)/2 — the same quadratic formula as the mesh-topology argument in A2.

Selection sort

loop for i = 0 to n - 2
    minIndex = i
    loop for j = i + 1 to n - 1
        if A[j] < A[minIndex] then
            minIndex = j
        endif
    next j
    // swap A[i] with A[minIndex]
    temp       = A[i]
    A[i]       = A[minIndex]
    A[minIndex] = temp
next i

Each pass finds the smallest value in the unsorted remainder and swaps it into position — so each element moves at most once.

Worked example 6 IB-style · 6 marks · selection sort pass by pass, and comparison with bubble sort

Question. Show the array after each pass of selection sort on [5, 2, 9, 1, 3] and compare its efficiency with bubble sort on the same data.

  1. Pass 1: scan indices 0–4; the minimum is 1 at index 3; swap with index 0 → [1, 2, 9, 5, 3].
  2. Pass 2: scan indices 1–4; the minimum is 2 at index 1; already in place → [1, 2, 9, 5, 3].
  3. Pass 3: scan indices 2–4; the minimum is 3 at index 4; swap with index 2 → [1, 2, 3, 5, 9].
  4. Pass 4: scan indices 3–4; the minimum is 5 at index 3; already in place → [1, 2, 3, 5, 9]. Sorted.
  5. Comparisons: 4 + 3 + 2 + 1 = 10 — the same as bubble sort, because both scan the unsorted portion. Swaps: at most 2 here (indices 0 and 2), against 6 for bubble sort.
Answer: [1,2,9,5,3] → [1,2,9,5,3] → [1,2,3,5,9] → [1,2,3,5,9]. Both are O(n²) in comparisons, so neither is fast for large n. Selection sort does at most n−1 swaps, which makes it better when writing to memory is expensive (flash storage, or sorting records that are costly to move). Bubble sort is faster when the data is already nearly sorted, because its swapped flag detects that after a single pass — selection sort cannot.

Algorithm efficiency and Big-O

Big-O describes how the number of steps grows as the input size \(n\) grows. It deliberately ignores constants and lower-order terms, because at large \(n\) only the fastest-growing term matters.

ComplexityNameWhat it meansExamplen = 1 000 000
\(O(1)\)ConstantIndependent of the input sizeAccessing A[5]; pushing onto a stack1 step
\(O(\log n)\)LogarithmicHalving the problem each stepBinary search; searching a balanced BST≈ 20 steps
\(O(n)\)LinearProportional to the input sizeLinear search; summing an array; traversing a linked list1 000 000 steps
\(O(n \log n)\)LinearithmicSplit, sort the halves, mergeMerge sort, quicksort (average), heap sort≈ 20 000 000 steps
\(O(n^{2})\)QuadraticEvery element against every otherBubble sort, selection sort, nested loops over the same array1012 steps
\(O(2^{n})\)ExponentialDoubles with each addition to the inputNaive recursive Fibonacci; brute-force subset searchimpossible
Why the constants are ignored — and when that is misleading

An \(O(n^{2})\) algorithm that does one operation per iteration beats an \(O(n \log n)\) algorithm that does a hundred, for every \(n\) you are likely to meet. Big-O describes the shape of the growth, not the absolute time, and it is a statement about what happens as \(n\) becomes large. This is exactly why bubble sort is still taught and still used: for \(n = 20\) it is perfectly fine, and it is three lines long. Say this in an answer and you sound like someone who understands the concept rather than someone reciting a table.

Worked example 7 IB-style · 6 marks · state the complexity of an algorithm

Question. State the time complexity of each fragment, with a reason.

(a)  total = 0
     loop for i = 0 to n - 1
         total = total + A[i]
     next i

(b)  loop for i = 0 to n - 1
         loop for j = 0 to n - 1
             output A[i] + A[j]
         next j
     next i

(c)  low = 0
     high = n - 1
     loop while low <= high
         mid = (low + high) DIV 2
         ...
     endwhile

(d)  output A[0]
  1. (a) One loop, n iterations, constant work each → O(n), linear.
  2. (b) A loop of n iterations inside a loop of n iterations → n × n = n² → O(n²), quadratic.
  3. (c) The search space halves each iteration → O(log n), logarithmic.
  4. (d) A single array access with no loop → O(1), constant.
  5. Extra credit that often carries a mark: if (a) and (d) appear in the same program, the total is O(n) + O(1) = O(n), because the slower-growing term is discarded — the overall complexity of a program is determined by its dominant part.
Answer: (a) O(n); (b) O(n²); (c) O(log n); (d) O(1). Always give the reason in words ("the search space halves", "a loop inside a loop"), not just the notation.

Testing

Three kinds of error

TypeWhat it isWhen it appearsExample
Syntax errorThe code breaks the grammar of the languageAt compile time (Java) or immediately at run time (Python)Missing colon in Python; missing semicolon or unmatched brace in Java
Logic errorThe code runs but does the wrong thingNever reported — you find it by testingUsing > where >= was needed; the wrong loop bound; grading in ascending order
Runtime errorThe program crashes while running because of a situation it cannot handleOnly on the input that triggers itDivision by zero; index out of bounds; trying to open a file that does not exist; null reference

Syntax errors are the easy ones: the computer tells you. Logic and runtime errors are the ones your testing strategy exists to catch, and they are caught by choosing the right data.

Three kinds of test data

TypePurposeExample for "enter an age between 0 and 120"
Normal (valid)Show that it works for ordinary, expected input25, 47, 90
Boundary / extremeProbe the edges of the valid range, where off-by-one bugs live0, 120, and the just-invalid values 1 and 119 if the test is inclusive; also −1 and 121
Erroneous / invalidCheck that bad input is rejected gracefully rather than crashing−5, 200, "twenty", an empty string, 3.7
Why Why boundary testing catches the off-by-one bug specifically
  1. An off-by-one error is a mistake at the edge of a range: < instead of <=, starting a loop at 1 instead of 0, or n - 2 instead of n - 1.
  2. Inside the range, all those mistakes give the same answer as the correct code, so normal data cannot detect them. A loop over 10 items behaves identically whether it runs to i < 10 or i <= 10 for the middle eight items — they differ only at the ends.
  3. Therefore the only inputs that can distinguish the two are the ones at the boundary, plus the first value just outside it.
  4. That is why a test plan without boundary data is not a test plan: it systematically misses the most common class of logic error in student code — and, for the same reason, the most common class of bug in real code.
  5. Practical rule: for a valid range a to b inclusive, test a−1, a, a+1, a middle value, b−1, b, b+1. Seven cases, and they cover virtually everything.

Practice

  1. State the output of this pseudocode.

    n = 5
result = 1
loop for i = 1 to n
    result = result * i
next i
output result
    Show answer

    result = 1 × 1 × 2 × 3 × 4 × 5 = 120. This is 5! (5 factorial). Trace: 1, 1, 2, 6, 24, 120.

    Trap: if the loop were i = 0 to n, the first multiplication would be by 0 and the answer would be 0 — a single-character difference with a completely different result.

  2. Explain the difference between a syntax error, a logic error and a runtime error, giving an example of each.

    Show answer

    A syntax error breaks the grammar of the language (missing colon in Python, missing semicolon in Java) and is reported before or immediately at run time.

    A logic error is valid code that computes the wrong thing (using > where >= was needed, or the wrong loop bound). It is never reported; only testing reveals it.

    A runtime error crashes during execution because of a specific situation (division by zero, index out of bounds, opening a file that does not exist). It only appears on the input that triggers it, which is why erroneous test data matters.

  3. State the output of the following, and explain what the algorithm does.

    count = 0
loop for i = 1 to 20
    if (i MOD 3 = 0) AND (i MOD 5 = 0) then
        count = count + 1
    endif
next i
output count
    Show answer
    1. The condition is true when i is divisible by both 3 and 5, i.e. by 15.
    2. Between 1 and 20, only 15 qualifies.

    Output: 1. The algorithm counts numbers in the range that are multiples of 15.

    Trap: AND means both conditions must hold. With OR, the count would be 6+4−1 = 9 (multiples of 3 or 5, remembering 15 is counted once).

  4. Explain why binary search cannot be used on unsorted data, using a concrete example.

    Show answer

    Take the array [9, 3, 7, 1, 5] and search for 1. Binary search computes mid = 2, sees A[2] = 7 > 1, and concludes the target must be in the left half — so it discards indices 3 and 4. But the target, 1, is at index 3, which was just thrown away. The algorithm reports "not found" for an element that is present.

    The inference "A[mid] > target, therefore everything to the right is also too big" is valid only because of the sorted-order property. Without it, the value at one position tells you nothing about any other position, so halving is unjustified.

  5. An array of 1024 sorted values is searched. State the maximum number of comparisons needed by (a) linear search and (b) binary search, and explain the difference.

    Show answer
    1. (a) Linear search: 1024 in the worst case (the target is the last element or absent).
    2. (b) Binary search: \(\log_{2} 1024 = 10\), so at most 11 comparisons in practice (ten halvings plus the final equality check that terminates the loop).
    3. The difference arises because binary search halves the search space at each step: 1024 → 512 → 256 → 128 → 64 → 32 → 16 → 8 → 4 → 2 → 1.
    4. The precondition is that the data is sorted, and the cost of achieving that must be counted if the data is not already sorted.

  6. Show the state of [7, 3, 5, 3] after each pass of bubble sort, and state the total number of comparisons.

    Show answer
    1. Pass 1: 7,3 swap → [3,7,5,3]; 7,5 swap → [3,5,7,3]; 7,3 swap → [3,5,3,7]. (3 comparisons, 3 swaps.)
    2. Pass 2: 3,5 no swap; 5,3 swap → [3,3,5,7]. (2 comparisons, 1 swap.)
    3. Pass 3: 3,3 no swap. (1 comparison, 0 swaps.) No swaps, so stop.
    4. Total comparisons = 3 + 2 + 1 = 6 = n(n−1)/2 with n = 4.
    Answer: [3,5,3,7] → [3,3,5,7] → sorted; 6 comparisons. Note that the two 3s are not swapped when they meet, which is what makes this variant stable — equal elements keep their relative order.

  7. State the time complexity of an algorithm whose running time is \(T(n) = 4n^{2} + 100n + 50\), and justify your answer.

    Show answer
    1. Big-O keeps only the fastest-growing term and drops constant multipliers.
    2. The terms are \(4n^{2}\), \(100n\) and \(50\). As \(n\) grows, \(n^{2}\) dominates \(n\), and the constant 50 does not grow at all.
    3. So \(T(n) = 4n^{2} + 100n + 50\) is O(n²).
    4. Check: at n = 1000, the \(4n^{2}\) term is 4 000 000, the \(100n\) term is 100 000, and the constant is 50 — the quadratic term is already 97 % of the total, and the proportion grows.
    Answer: O(n²), quadratic. Stating that the constants are dropped because they do not affect the shape of the growth is what earns the justification mark.
