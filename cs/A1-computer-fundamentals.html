Computer Science HL · Theme A · A1

A1 · Computer fundamentals

Everything a computer does, from streaming video to training a neural network, is the fetch–decode–execute cycle running billions of times a second over patterns of bits. This topic is where you learn what those bits are, how they are stored, how they are moved, and how the machine is organised to move them. It is the most self-contained topic in the course and the most reliably scorable in Paper 1 — there is no opinion in "convert 173 to hexadecimal", only right and wrong.

Theme A · examined in Paper 1 HL only: A1.4 Translation (compilers, interpreters, assemblers, bytecode, VMs) A1.1 Hardware · A1.2 Data representation and logic · A1.3 Operating systems and control systems

A1.1 · What a computer system is, and the layers of abstraction

A computer system is a combination of hardware and software working together to accept input, process it, store it, and produce output. That sentence is examinable almost verbatim, but the interesting part is the word system: no single component can do anything useful alone. A CPU with no memory cannot remember the instruction it just fetched. Memory with no operating system is a grid of bits with no meaning. An operating system with no application does nothing a user cares about.

Why abstraction is the central idea

Computing is built in layers, and every layer is defined by what it hides from the layer above. The transistor hides the physics. The logic gate hides the transistor. The CPU hides the gates. Machine code hides the CPU's wiring. Assembly hides the bit patterns. A high-level language hides the registers. The operating system hides the hardware entirely. Your Python program hides all of it. Each layer offers the one above a simpler interface and a set of promises — and that is the whole trick: you can reason at any layer without knowing the details below it. When an exam asks "explain the role of abstraction", this is the answer: managing complexity by hiding unnecessary detail behind a well-defined interface.

The stored-program concept (von Neumann architecture) is the insight that made modern computing possible: instructions are data. Both the program and the data it manipulates live in the same memory, in the same binary encoding, fetched over the same bus. Before this, "programming" a machine meant physically rewiring it. After it, running a new program meant loading different numbers into memory.

Why Why the stored-program concept changed everything — and what it costs
  1. If instructions and data share one memory, the machine needs only one mechanism to get either: put an address on the address bus, read what comes back on the data bus.
  2. Therefore the machine can treat instructions as data: a program can generate, modify, or load other programs. That is what a compiler, an interpreter, a loader and a just-in-time compiler all do.
  3. Therefore one machine can run an unbounded number of different programs without any hardware change — which is precisely why your phone is a camera, a map, a bank and a games console.
  4. The cost — the von Neumann bottleneck. Because instructions and data share one bus, the CPU cannot fetch an instruction and fetch data at the same moment. It must serialise them. This is the structural reason cache memory exists, and why modern designs separate instruction cache from data cache.

What it means: the flexibility of general-purpose computing is bought with a throughput limit. When it is the wrong lens: a GPU or a purpose-built ASIC abandons this generality deliberately, which is why specialised hardware beats a CPU on narrow tasks.

Computer architecture

The parts, and what each actually does

Control unit (CU)
Fetches instructions, decodes them into control signals, and coordinates every other component. It does not compute; it directs. It is the component that asserts "read" on the control bus and then waits.
Arithmetic logic unit (ALU)
Performs arithmetic (add, subtract, multiply) and logical operations (AND, OR, NOT, comparisons). It receives two operands, performs one operation selected by the control unit, and puts the result somewhere — usually the accumulator. It also sets flags (zero, carry, negative, overflow) that later instructions test.
Program counter (PC)
Holds the address of the next instruction to be fetched. After each fetch it increments; a jump instruction overwrites it instead. This single register is why programs run in sequence.
Memory address register (MAR)
Holds the address of the memory location about to be read from or written to. Whatever is in the MAR is what appears on the address bus.
Memory data register (MDR)
Holds the data just fetched from memory, or about to be written to it. Acts as a buffer between the fast CPU and the slower memory.
Accumulator
A general-purpose register that holds one operand and then the result of an ALU operation. Older/simpler architectures have essentially one; modern ones have a register file of many, but the exam model keeps the accumulator because it makes the cycle easy to explain.
Cache
Small, very fast memory sitting between the CPU and RAM, holding recently and nearby used data.
Clock
A signal that switches at a fixed frequency and synchronises every step. "3.4 GHz" means 3.4 billion cycles per second.
Why cache exists — and why it works

RAM is hundreds of times slower than the CPU. If the CPU waited for RAM on every access it would idle away most of its life. Cache is expensive, tiny, and fast, so we put a copy of some of RAM in it. The reason this pays off is not magic, it is observed behaviour: programs exhibit temporal locality (if you used a value, you will probably use it again soon — think of a loop counter) and spatial locality (if you used address 1000 you will probably soon use 1001–1031 — think of iterating an array). Caches therefore load a whole block of consecutive addresses, not a single byte, and keep what was used recently.

Why Why clock speed alone does not determine performance
  1. Work done per second ≈ (instructions per second) × (work per instruction).
  2. Instructions per second ≈ clock rate ÷ average cycles per instruction (CPI). A 4 GHz chip that needs 3 cycles per instruction is slower than a 3 GHz chip that needs 2.
  3. But if the required data is not in cache, the CPU stalls for tens or hundreds of cycles waiting for RAM — so effective CPI is dominated by cache hit rate for memory-heavy code.
  4. More cores only help if the problem can be split into independent pieces (and if the software is written to use them). Doubling cores on a strictly sequential task does nothing.

Conclusion: clock speed, core count, cache size and bus width all matter, and the exam expects you to say that none of them alone determines real performance. When the shortcut is wrong: comparing two CPUs by GHz alone is the classic mistake examiners reward you for spotting.

The fetch–decode–execute cycle

Every instruction the CPU ever runs goes through the same three stages. Learn it as a fixed ritual; Paper 1 questions award a mark per correct step and students routinely lose two by merging them.

How to write it in the exam
  1. Fetch: the address in the PC is copied to the MAR; the CU issues a read on the control bus; the contents of that memory location travel along the data bus into the MDR; the instruction is copied into the current instruction register; the PC is incremented.
  2. Decode: the control unit examines the opcode and determines the operation and the operand (which may be an immediate value, a register, or another memory address that must itself be fetched).
  3. Execute: the operation is performed — the ALU computes, or data is transferred, or the PC is overwritten by a jump address.
  4. Repeat, checking for interrupts between cycles.

Name the registers. "The CPU gets the instruction from memory" is worth less than "the address in the program counter is copied into the memory address register".

Machine code and thinking at assembly level

An instruction is a binary word split into an opcode (what to do) and an operand (what to do it to). A tiny invented machine with a 4-bit opcode and a 12-bit operand could represent 0001 000000110010 as "opcode 1 = load the value at address 50 into the accumulator".

Worked example 1 IB-style · 4 marks · trace an assembly program

Question. Memory contains: address 50 = 7, address 51 = 5, address 52 = 0. Trace this program and state the final contents of address 52.

LDA 50
ADD 51
STA 52
HLT
  1. LDA 50: accumulator ← memory[50] = 7.
  2. ADD 51: accumulator ← 7 + memory[51] = 7 + 5 = 12.
  3. STA 52: memory[52] ← 12.
  4. HLT: stop.
Answer: memory[52] = 12. The point of the question is that assembly is imperative and sequential: each line changes exactly one piece of state, and the state is the accumulator plus memory. Trace it one line at a time and never do two steps in your head at once.
Worked example 2 IB-style · 6 marks · counting with a branch

Question. Explain what the following program does and state the final value in address 60. Assume address 60 starts at 0 and address 61 holds the value 4.

 LDA 61
LOOP BRZ DONE
 STA 60
 SUB ONE
 JMP LOOP
DONE HLT
ONE DAT 1
  1. LDA 61: accumulator ← 4.
  2. BRZ DONE: the zero flag is not set (4 ≠ 0), so continue.
  3. STA 60: memory[60] ← 4.
  4. SUB ONE: accumulator ← 4 − 1 = 3. JMP LOOP.
  5. Iteration 2: 3 → memory[60] = 3, accumulator = 2. Iteration 3: memory[60] = 2, accumulator = 1. Iteration 4: memory[60] = 1, accumulator = 0.
  6. Iteration 5: BRZ DONE — the zero flag IS set, so jump to DONE and halt.
Answer: memory[60] = 1. The loop copies a decreasing counter into address 60 and stops before storing 0. This is the off-by-one pattern in hardware form: the placement of the zero test relative to the store determines whether 0 is stored. A student who assumes it stores 0 has missed that BRZ runs before STA.
Connection

Assembly-language thinking reappears in B2 (recursion and the call stack), in B4 (a linked list is literally nodes holding a value and an address), and in A1.4 Translation (an assembler is a one-to-one translator; a compiler is not). Every time you see "address of" in this course, it is the MAR idea again.

A1.3 · The operating system

An operating system (OS) is software that manages the computer's hardware and provides services to applications. Its job is to be the layer that lets a program say "save this file" without knowing what kind of disk is installed.

Why interrupts rather than polling

The alternative to an interrupt is polling: the CPU repeatedly asks "are you ready yet?". That wastes millions of cycles on a device that will take milliseconds to respond. With an interrupt, the device asserts a signal on the control bus when it is ready, the CPU finishes the current instruction, saves its state, services the device, restores state and carries on. The device sets the pace instead of the CPU guessing it. This is the same design argument as event-driven programming in B2 and as callback-based I/O in a networked application in A2 — signal when something happens; do not loop asking.

Control systems

A control system (embedded system) is a computer system built into a larger device to monitor and control it — a washing machine, a car's anti-lock brakes, an insulin pump. The pattern is always the same loop: a sensor measures the physical world, the computer compares the reading with a target, and an actuator changes something physical.

  • Sensor — input device that measures a physical quantity and converts it into an electrical signal: temperature, light, pressure, proximity, acceleration. Crucially, sensors produce analogue signals (continuously varying voltage), which must pass through an analogue-to-digital converter (ADC) before the CPU can use them.
  • Actuator — output device that converts an electrical signal into physical action: motor, solenoid, valve, heater, buzzer, LED. Where the output must be smooth (motor speed, speaker volume), a digital-to-analogue converter (DAC) is used.
Worked example 3 IB-style · 6 marks · a greenhouse control system

Question. A greenhouse uses a microcontroller to keep the temperature between 18 °C and 24 °C. Describe the role of the sensor, the processor and the actuator, and explain why an ADC is required.

  1. A temperature sensor (e.g. a thermistor in a potential divider) produces a voltage that varies continuously with temperature — an analogue signal.
  2. An ADC samples that voltage at intervals and converts each sample to a binary integer, because the microcontroller can only process digital values.
  3. The processor compares the reading with the stored limits: if the value is below 18 the heater is switched on; if above 24 the vent motor is switched on; otherwise both stay off.
  4. The actuators — a heater relay and a vent motor — convert the digital decision into a physical change.
  5. The loop repeats continuously, typically with a delay, so the system monitors and corrects itself.
Answer: sensor → ADC → compare → actuator → repeat. Marks: 1 for the sensor measuring continuously, 1 for the ADC converting analogue to digital, 1 for the comparison against stored limits, 1 for the actuator changing the physical state, 1–2 for explaining that the loop repeats. Naming the specific devices in the scenario (heater, vent) is what lifts an answer from generic to contextualised.

A question that says "justify the choice of storage for a laptop used by a video editor" is not asking for the table above. Always name the property, then tie it to the scenario's need. A list of features with no "therefore" scores about half.

A1.2 · Data representation

How many values can n bits represent?

One bit has 2 states. Two bits have \(2 \times 2 = 4\) states: 00, 01, 10, 11. Each extra bit doubles the count. So:

\[ \textbf{number of distinct values} = 2^{n} \qquad \textbf{range for unsigned integers} = 0 \text{ to } 2^{n}-1 \]
Trap — the minus one

8 bits represent \(2^{8} = 256\) different values, but the largest unsigned value is 255, because zero consumes one of the 256 patterns. Students lose a mark on "what is the largest value an 8-bit register can hold" every single session. And if the register holds a memory address, the question is about how many locations can be addressed — that is 256, not 255, because address 0 is a location.

Denary to binary — two methods

Method 1: successive division by 2. Divide by 2, record the remainder, repeat with the quotient until it is 0, then read the remainders bottom-to-top.

Worked example 4 Convert 173 to binary and then to hexadecimal

Denary → binary (division method).

  1. 173 ÷ 2 = 86 r 1
  2. 86 ÷ 2 = 43 r 0
  3. 43 ÷ 2 = 21 r 1
  4. 21 ÷ 2 = 10 r 1
  5. 10 ÷ 2 = 5 r 0
  6. 5 ÷ 2 = 2 r 1
  7. 2 ÷ 2 = 1 r 0
  8. 1 ÷ 2 = 0 r 1
  9. Read the remainders upwards: 10101101.

Binary → hexadecimal. Split into groups of 4 from the right: 1010 | 1101 → A | D → AD.

Check: \(\text{AD}_{16} = 10 \times 16 + 13 = 160 + 13 = 173\). ✓

Answer: 173 = 10101101₂ = AD₁₆. Always do the reverse check — it takes five seconds and catches the single most common error, which is reading the remainders in the wrong order.

Method 2: place-value subtraction. Write the column headings (128, 64, 32, 16, 8, 4, 2, 1), put a 1 where the value fits and subtract, and a 0 where it does not.

Worked example 5 Convert 205 to binary by place values, and convert 10010110 to denary

205 → binary.

  1. 128 fits into 205: 1, remainder 77.
  2. 64 fits into 77: 1, remainder 13.
  3. 32 does not fit into 13: 0. 16 does not: 0. 8 fits: 1, remainder 5.
  4. 4 fits: 1, remainder 1. 2 does not: 0. 1 fits: 1.
  5. Result: 11001101.

10010110 → denary.

  1. Columns: 1×128 + 0×64 + 0×32 + 1×16 + 0×8 + 1×4 + 1×2 + 0×1
  2. = 128 + 16 + 4 + 2 = 150.
Answer: 205 = 11001101₂; 10010110₂ = 150. Sanity check on the second: the leading bit is 1, so the value must be at least 128 — if you get less than 128 you have misaligned a column.
Why Why hexadecimal exists — the compactness argument
  1. Humans read and transcribe long binary strings badly: 1110101100101101 is 16 characters with no structure, and miscopying one is invisible.
  2. Hexadecimal uses base 16, and \(16 = 2^{4}\), so each hex digit maps to exactly 4 bits and vice versa. No arithmetic is involved — you translate four bits at a time, independently.
  3. So the same value becomes EB2D: four characters, chunked, and each chunk carries meaning (the high byte, the low byte).
  4. Why base 16 and not base 10? Because 10 is not a power of 2, so decimal digits do not align with bit boundaries — converting between denary and binary requires real division arithmetic, whereas hex is pattern matching.
  5. Why not octal (base 8)? It also aligns (\(8 = 2^{3}\)), but it does not divide a byte into a whole number of digits, which is why hex won.

Where you see it: MAC addresses, IPv6 addresses, colour codes (#FF8800), memory dumps, and Unicode code points. When it is the wrong tool: never do arithmetic in hex if you can do it in denary — hex is a notation, not a number system you compute in.

How to use it — the hex conversion ritual
  1. Binary → hex: split into groups of four starting from the right. Pad the leftmost group with zeros if needed.
  2. Hex → binary: expand each digit to exactly four bits, including leading zeros (A = 1010, 0 = 0000).
  3. Hex → denary: multiply each digit by its power of 16 and add: \(\text{2F9}_{16} = 2(256) + 15(16) + 9 = 761\).
  4. Denary → hex: either convert to binary first and group, or divide repeatedly by 16.

BCD — binary-coded decimal

In BCD, each decimal digit is stored in its own 4-bit group. So 47 is 0100 0111, not the pure binary 00101111.

Worked example 6 IB-style · 4 marks · BCD, and why it is used

Question. (a) Represent 582 in BCD. (b) State one advantage and one disadvantage of BCD compared with pure binary.

  1. Each decimal digit → 4 bits: 5 = 0101, 8 = 1000, 2 = 0010.
  2. So 582 in BCD = 0101 1000 0010.
  3. Advantage: conversion to and from the decimal digits a human reads is trivial — no division, just read each nibble. This matters in digital clocks, calculators, meters and any device whose output is decimal digits.
  4. Disadvantage: it wastes storage. BCD uses 12 bits here where pure binary needs only 10 (582 = 1001000110), and in general 4 bits per digit represents 10 of 16 possible patterns, so about 37 % of the patterns are unused. Arithmetic in BCD also needs correction steps after addition.
Answer: (a) 0101 1000 0010. (b) Advantage: exact decimal representation and trivial conversion for display/kiosk devices; no rounding error for money. Disadvantage: inefficient use of bits and more complex arithmetic. Applications where decimal exactness matters (financial displays) are the standard IB example.

Character encoding: ASCII and Unicode

A character set is an agreed mapping between numbers and characters. ASCII originally used 7 bits — 128 characters: the English letters, digits, punctuation and control codes. Extended ASCII uses 8 bits for 256 characters, adding a few accented letters and box-drawing symbols, but inconsistently between manufacturers.

Why Unicode was necessary

8 bits gives 256 patterns. English fits. Nothing else does. Chinese alone has tens of thousands of characters; add Arabic, Cyrillic, Devanagari, Korean, Greek, Thai, and the world's emoji, and 256 is not a constraint you can engineer around — it is simply too small. The pre-Unicode workaround was code pages: the same byte value 0xE4 meant "ä" on one system and a Chinese character on another, so a document was meaningless without knowing which page it was written in. Unicode solves this by giving every character in every writing system a single unique code point (written U+0041 for "A", U+4E2D for ), decoupling "which character is this" from "how many bytes does it take to store".

UTF-8 is the variable-width encoding that stores those code points: characters in the ASCII range use 1 byte (so old ASCII files are valid UTF-8 — a deliberate design decision that made adoption possible), most European characters 2 bytes, CJK characters typically 3 bytes, and emoji 4 bytes.

Trap — characters are not bytes

In Java, a char is 16 bits (UTF-16) and in Python 3 a string is a sequence of Unicode code points, so len("") is 1. But a file containing needs 3 bytes in UTF-8. Exam questions that say "a text file contains 500 characters" and then ask for the file size in bytes cannot be answered without knowing the encoding — and if the file is ASCII, it is 500 bytes; if it is Chinese in UTF-8, it is 1500. Say which assumption you are making.

Worked example 7 IB-style · 6 marks · a sound file size and a download time

Question. A mono audio recording is sampled at 44 100 Hz with a sample resolution of 16 bits and lasts 3 minutes. Calculate the file size in MiB, and the time to transmit it over a 2 Mbit/s connection.

  1. Number of samples = 44 100 × 180 s = 7 938 000.
  2. Bits per sample = 16, and mono means one channel (no ×2).
  3. Total bits = 7 938 000 × 16 = 127 008 000 bits. In bytes: ÷ 8 = 15 876 000 bytes.
  4. In MiB: ÷ 1024 ÷ 1024 = 15 876 000 / 1 048 576 ≈ 15.1 MiB.
  5. Transmission time = 127 008 000 bits ÷ 2 000 000 bit/s ≈ 63.5 s.
Answer: ≈ 15.1 MiB; ≈ 64 s. Method marks: (1) samples = rate × time, (1) bits = samples × resolution × channels, (1) convert bits to bytes, (1) convert to MiB, (1) time = bits ÷ bit rate, (1) sensible units. Two classic traps: using 1000 instead of 1024 when MiB is asked for, and forgetting that a "2 Mbit/s" link is bits while your file size is bytes.

Run-length encoding, worked through

RLE replaces a run of identical values with a single value and a count. It is the compression you can do entirely by hand, which is why the exam likes it.

Worked example 8 IB-style · 6 marks · RLE by hand

Question. A black-and-white image row is stored as WWWWWWWWBBBWWWWWWBBBBBWWWW. (a) Encode it using run-length encoding as (count, value) pairs. (b) Calculate the number of bits saved if the original uses 1 bit per pixel and each RLE pair uses 8 bits for the count and 1 bit for the value. (c) State a type of image for which RLE would increase the file size.

  1. Count the runs: 8 W, 3 B, 6 W, 5 B, 4 W.
  2. Encoded: 8W 3B 6W 5B 4W.
  3. Original: 8+3+6+5+4 = 26 pixels × 1 bit = 26 bits.
  4. Encoded: 5 pairs × (8 + 1) bits = 45 bits.
  5. So this encoding actually wastes 19 bits — the runs are too short to pay for the count field.
  6. (c) An image with no runs — alternating black and white pixels, or a photographic image with smooth noise — produces a count of 1 for every pixel, so every pixel costs 9 bits instead of 1.
Answer: (a) 8W 3B 6W 5B 4W. (b) 26 → 45 bits, so 19 bits worse. (c) Any image with few or no repeated adjacent pixels, e.g. random noise or a finely detailed photograph. The general lesson the examiner wants: compression is not free and not universal — its effectiveness depends entirely on the statistical structure of the data.
Note — why RLE works on some images and not others

RLE exploits spatial redundancy: neighbouring pixels tend to be the same colour. Cartoons, icons, scanned line art and screenshots have huge flat areas, so RLE (and PNG more generally) is excellent. Photographs almost never have exact repeats because of sensor noise, which is why JPEG uses a completely different strategy — it transforms the image into frequency components and throws away the high-frequency ones your eye would not resolve anyway.

Binary arithmetic

Addition and overflow

Binary addition follows the same rules as denary: add the column, carry if it exceeds the base. In base 2 that means 1 + 1 = 0 carry 1, and 1 + 1 + 1 = 1 carry 1.

Worked example 9 Addition, and an overflow that matters

Question. Using an 8-bit register, add 200 (11001000) and 100 (01100100). State the result the hardware stores, state the value of the carry flag, and explain why this is a problem.

  1. Add column by column from the right, carrying where a column totals 2 or 3: 11001000 + 01100100 = 1 00101100.
  2. The register has only 8 bits, so the leading 1 is the carry out and is discarded. The stored result is 00101100 = 44.
  3. The true sum is 200 + 100 = 300, which exceeds the maximum unsigned value 255, so 300 − 256 = 44 is stored instead. The carry flag is set to 1.
  4. The stored value 44 is simply wrong for the intended calculation, and nothing warns the program.
Answer: 00101100 (44), carry flag = 1. Overflow matters because the machine does not raise an exception: the wrong answer propagates silently into every later calculation. This is why a program that sums large values must use a wider type (a 64-bit integer, or an arbitrary-precision integer as Python's int does by default). Notice also that in signed two's-complement interpretation the same bits mean something different — overflow is detected by comparing the carry into the sign bit with the carry out of it, not simply by the carry flag.
Trap — overflow produces no error

In most high-level languages an integer overflow is not a crash; it is a wrong number. In Java, int i = 2147483647; i = i + 1; gives −2147483648, wrapping around. Python's int grows automatically and does not overflow, but NumPy fixed-width types do. Never write "the program will crash" in an overflow question unless you are certain — write "the result will be incorrect / will wrap around".

Negative numbers: two's complement

Three representations of signed numbers you should be able to distinguish, and one you should be able to use.

  • Sign and magnitude: the leftmost bit is the sign (0 = +, 1 = −), the rest is the magnitude. Problem: two representations of zero (+0 and −0), and the hardware needs separate add and subtract circuits.
  • One's complement: negate by inverting every bit. Still two zeros. Addition needs an "end-around carry" fix-up.
  • Two's complement: negate by inverting every bit and adding 1. One zero. Subtraction is addition. This is what every real machine uses.
How to use it — the two-step rule
  1. To negate: start from the right, copy all bits up to and including the first 1, then flip every bit after it. (This is a faster way to do "invert then add 1" and gives the same answer.)
  2. To read a negative value: either apply the same operation to find its magnitude, or use the place-value method with the leftmost column negative: for 8 bits the headings are −128, 64, 32, 16, 8, 4, 2, 1.
  3. Range: with n bits, \( -2^{n-1} \) to \( 2^{n-1} - 1 \). For 8 bits: −128 to +127.
Proof Why two's complement makes subtraction work — the modular arithmetic argument
  1. An n-bit register cannot distinguish values that differ by \(2^{n}\). Everything it does is arithmetic modulo \(2^{n}\): the hardware simply discards the carry out of the top bit.
  2. In modulo-\(2^{n}\) arithmetic, subtracting \(b\) is identical to adding \(2^{n} - b\), because \(a - b \equiv a + (2^{n} - b) \pmod{2^{n}}\).
  3. And the two's complement of \(b\) is defined to be \(2^{n} - b\). (Check: "invert every bit" of an n-bit number \(b\) produces \((2^{n}-1) - b\); adding 1 gives \(2^{n} - b\).)
  4. Therefore adding the two's complement of \(b\) performs subtraction, using exactly the same adder circuit, with no special cases and no sign checks.
  5. Worked check with 8 bits, 7 − 5: 5 = 00000101, invert → 11111010, add 1 → 11111011 (= 251 = 256 − 5). Now 00000111 + 11111011 = 1 00000010. Discard the carry out of bit 7 → 00000010 = 2. ✓
  6. Why the "one zero" property follows: +0 is 00000000; its two's complement is 11111111 + 1 = 1 00000000, which discards to 00000000 — the same pattern. So there is exactly one zero, and the spare pattern 10000000 is free to represent −128, which is why the negative range is one larger than the positive.

What it means: two's complement is not a convention anyone invented for tidiness; it is the unique representation under which an ordinary binary adder performs signed subtraction correctly. When it is the wrong tool: for floating-point values — those use a sign bit with a separate exponent-and-mantissa format (IEEE 754), not two's complement.

Worked example 10 IB-style · 5 marks · two's complement both ways

Question. Using 8-bit two's complement: (a) represent −43; (b) state what 10010101 represents.

  1. (a) +43 = 00101011 (32 + 8 + 2 + 1).
  2. Invert: 11010100. Add 1: 11010101. So −43 = 11010101.
  3. Check with the fast method: copy up to and including the first 1 from the right in 00101011 → the last bits 1, then flip the rest → 11010101. Same answer. ✓
  4. (b) The leading bit is 1, so 10010101 is negative. Apply the negation: copy up to and including the first 1 (that is just the final 1), then flip everything else → 01101011.
  5. 01101011 = 64 + 32 + 8 + 2 + 1 = 107. So 10010101 = −107.
  6. Check by place values with a negative top column: −128 + 16 + 4 + 1 = −107. ✓
Answer: (a) 11010101. (b) −107. Always do the second check — if the two methods disagree, you have flipped the wrong bit.

Binary fractions and floating point

In fixed-point binary the column headings continue past the point as halves, quarters, eighths: for \(101.101_2\) the headings are 4, 2, 1, ½, ¼, ⅛, giving \(5 + 0.5 + 0.125 = 5.625\).

Worked example 11 IB-style · 6 marks · why 0.1 is not storable

Question. Explain why the denary value 0.1 cannot be represented exactly in binary, and state the consequence for a program that adds 0.1 ten times and compares the result with 1.0.

  1. A fraction terminates in base 2 only if its denominator (in lowest terms) is a power of 2. 0.1 = 1/10, and 10 = 2 × 5, so it has a factor 5 — it does not terminate. (This is exactly why 1/3 does not terminate in decimal: 3 is not a factor of the base.)
  2. Repeatedly doubling: 0.1 → 0.2 → 0.4 → 0.8 → 1.6 → 1.2 → 0.4 … the fractional part cycles, so the binary expansion 0.0001100110011… repeats for ever.
  3. Stored in a finite number of bits (24-bit mantissa in single precision, 53 in double), the value is truncated, so the stored number is very slightly more or less than 0.1.
  4. Adding it ten times accumulates that error, so the result is not exactly 1.0 and a direct == 1.0 comparison is false.
  5. The correct technique is to compare against a tolerance: abs(x - 1.0) < 1e-9, or to work in integer units (store cents instead of dollars).
Answer: 0.1 has a recurring binary expansion, is stored approximately, and repeated addition accumulates the error, so the comparison fails. This is the standard "explain why" question on floating point — the marks are for (1) the recurring expansion / non-power-of-2 denominator, (1) truncation to a finite mantissa, (1) the accumulated error, (1) the consequence for equality testing.

Boolean logic

George Boole's insight was that logical reasoning could be done with algebra, where the variables take only two values. A century later Claude Shannon noticed this is precisely how switching circuits behave — and digital computing became applied Boolean algebra.

Deriving a Boolean expression from a truth table

How to use it — the sum-of-products method
  1. Identify every row where the output is 1.
  2. For each such row, write an AND term: include the variable itself if it is 1 in that row, and its complement if it is 0.
  3. OR all those terms together. That expression is correct by construction — it is true on exactly the rows you selected.
  4. Simplify with Boolean algebra or a Karnaugh map if the question asks for the simplest circuit.
Worked example 12 IB-style · 8 marks · truth table → expression → circuit → simplification

Question. A burglar alarm sounds (Z = 1) when the sensor S is triggered AND the system is armed A, OR when the panic button P is pressed regardless of anything else.

  1. Write the truth table (3 inputs → 8 rows). Z = 1 when P = 1 (four rows), plus the row S = 1, A = 1, P = 0. So Z = 1 in five rows.
  2. Direct expression from the words: \(Z = (S \cdot A) + P\).
  3. Verify with the sum-of-products method on the five 1-rows to confirm it matches.
  4. Simplify using Boolean algebra:
  5. Expand the S·A term so every term contains P: \(S \cdot A = S \cdot A \cdot (P + \overline{P}) = S \cdot A \cdot P + S \cdot A \cdot \overline{P}\).
  6. Now \(Z = S A P + S A \overline{P} + P\). Use the absorption law \(X + X Y = X\) with \(X = P\): the term \(S A P\) is absorbed into \(P\).
  7. So \(Z = S A \overline{P} + P\). Two terms instead of five — a simpler circuit with fewer gates.
  8. Circuit: one NOT gate on P, one AND gate combining S, A and ¬P, one OR gate combining that with P.
Answer: Z = (S·A) + P, simplifiable to Z = (S·A·¬P) + P. Marks: (2) correct truth table, (2) correct unsimplified expression, (2) correct simplification with the law named, (2) correct circuit. The exam rarely requires you to find the minimal form, but it does require you to show the algebra — the simplification is where the method marks are.
Worked example 13 IB-style · 5 marks · expression → truth table

Question. Draw the truth table for \(F = \overline{A} \cdot B + A \cdot \overline{B}\) and identify the gate this implements.

  1. Row A=0, B=0: ¬A·B = 0, A·¬B = 0 → F = 0.
  2. Row A=0, B=1: ¬A·B = 1, A·¬B = 0 → F = 1.
  3. Row A=1, B=0: ¬A·B = 0, A·¬B = 1 → F = 1.
  4. Row A=1, B=1: both terms 0 → F = 0.
  5. The pattern 0,1,1,0 is exactly XOR: output 1 when the inputs differ.
Answer: F = A ⊕ B. This is the classic exam move: an unfamiliar expression that turns out to be a single standard gate. Building the truth table is the only reliable way to spot it — do not try to see it by inspection.
Connection

Every if condition you write in B2 is a Boolean expression. De Morgan's laws — \(\overline{A \cdot B} = \overline{A} + \overline{B}\) and \(\overline{A + B} = \overline{A} \cdot \overline{B}\) — are exactly the rule you use in Python when you rewrite not (a and b) as (not a) or (not b), or in Java when you rewrite !(x < 5 && y > 3) as x >= 5 || y <= 3. Same algebra, different notation.

A1.4 · Translation HL only

Source code cannot be executed directly; it must be translated into machine code. There are three kinds of translator, and the difference between them is when translation happens and whether the result is saved.

Bytecode and the virtual machine is the middle path, and it is how Java works. The compiler translates source into bytecode — a machine code for a processor that does not physically exist. The Java Virtual Machine (JVM) then interprets or just-in-time compiles that bytecode for the actual hardware. The payoff is portability: the same .class file runs on Windows, macOS and Linux without recompilation, because each platform supplies its own JVM. Python does something similar: CPython compiles your .py into bytecode in a __pycache__ folder and the Python VM runs that.

Exam technique — the evaluate question you will get

"Compare a compiler and an interpreter for the development of a commercial application" wants four things: (1) a compiler produces an executable that runs fast and hides source code, which suits commercial distribution; (2) but the edit–compile–test cycle is slower and errors are reported in bulk, which slows development; (3) an interpreter gives immediate feedback and platform independence at the development stage, which speeds debugging; (4) but it runs slower and requires the source or the runtime to be present, which suits neither performance-critical nor proprietary distribution. Then conclude: development in an interpreted environment, distribution as compiled code — which is exactly what the bytecode/JVM hybrid achieves.

Social, ethical and legal dimensions

These are examined, and examined seriously, usually as a 6–10 mark discuss or to what extent question, often attached to the case study. The content is easy; the skill is writing a balanced evaluation.

Privacy and surveillance

Every digital service collects data about you. The ethical question is not "is data collected" but who decides, for what purpose, with what consent, and with what recourse. Arguments for collection: personalisation, safety, fraud prevention, public health. Arguments against: function creep (data collected for one purpose used for another), chilling effects on behaviour, disproportionate impact on minorities, and the impossibility of genuine consent when the alternative is not using the service.

Intellectual property and open source

Copyright protects the expression of an idea; patents protect an invention; trade secrets protect confidential business information. Software sits awkwardly across all three, which is why licences matter. Proprietary licences restrict use, modification and redistribution. Open source licences grant those rights, sometimes with a copyleft condition (GPL: derived work must also be open) and sometimes without (MIT, Apache: do almost anything, just attribute). Arguments for open source: scrutiny improves security, education, no vendor lock-in. Arguments against: no guaranteed support, unclear liability, harder to fund development.

Accessibility and the digital divide

Accessibility means designing so people with disabilities can use the product — screen-reader-compatible markup, captions, keyboard navigation, sufficient contrast. The digital divide is the gap between those who have affordable access to computing and the skills to use it and those who do not, along lines of income, geography, age, language and disability. It is a compounding problem: as services move online, those excluded lose access to the service itself.

Sustainability and e-waste

Computing consumes energy (devices, data centres, networks, and training large AI models), water for cooling, and rare-earth minerals for manufacture. Discarded devices create e-waste containing toxic materials, much of which is shipped to countries with weaker environmental regulation. Tension to name: efficiency improvements are frequently cancelled out by increased use (Jevons paradox) — faster, cheaper computing drives more of it.

How to write a balanced evaluation — the four-paragraph template
  1. Paragraph 1 — define the stakes in this scenario. Who are the stakeholders? Name at least three (users, the company, employees, governments, non-users, future generations — pick the ones the scenario actually implies).
  2. Paragraph 2 — the strongest case for. Not three weak points; one or two strong ones, each developed with a concrete consequence.
  3. Paragraph 3 — the strongest case against, again developed. Use "however" and "on the other hand" explicitly so the examiner can see the balance.
  4. Paragraph 4 — a judgement. "On balance…", "This is acceptable provided that…", "The benefit outweighs the risk for X but not for Y." A conclusion that weighs, not one that simply repeats.

The mark that is most often lost is the final one. An evaluation with no judgement is capped around half marks however accurate the analysis — the command term asked you to weigh, and weighing produces a verdict.

Trap — being generic

"Privacy is a concern because personal data could be misused" is true of every technology ever built and scores almost nothing. "In this system, the camera records the resident's daily routine continuously, so the data reveals not just what they did but when they are out of the house — information that is valuable to a burglar as well as to the care provider" is worth marks. Always attach the abstract harm to a specific mechanism in the specific scenario.

Practice

  1. Convert 219 to (a) binary, (b) hexadecimal. Show your method.

    Show answer
    1. 219 ÷ 2 = 109 r 1; 109 ÷ 2 = 54 r 1; 54 ÷ 2 = 27 r 0; 27 ÷ 2 = 13 r 1; 13 ÷ 2 = 6 r 1; 6 ÷ 2 = 3 r 0; 3 ÷ 2 = 1 r 1; 1 ÷ 2 = 0 r 1.
    2. Read upwards: 11011011.
    3. Group in fours from the right: 1101 | 1011 → D | B → DB.
    4. Check: 13 × 16 + 11 = 208 + 11 = 219. ✓

  2. Using 8-bit two's complement, (a) represent −89, (b) state the denary value of 11100110, (c) state the range of values that can be held.

    Show answer
    1. (a) +89 = 01011001 (64 + 16 + 8 + 1). Invert → 10100110. Add 1 → 10100111.
    2. (b) Leading bit is 1, so negative. Negate: copy up to and including the first 1 (the last bit), flip the rest → 00011010 = 16 + 8 + 2 = 26. So −26. Check: −128 + 64 + 32 + 4 + 2 = −26. ✓
    3. (c) −128 to +127.

  3. Explain, with reference to the stored-program concept, why a single general-purpose computer can function as a word processor, a games console and a web browser.

    Show answer
    1. Instructions and data are stored in the same memory in the same binary form.
    2. Therefore the computer's behaviour is determined entirely by the contents of memory, not by its physical construction.
    3. Loading a different program simply puts different bit patterns into memory; no hardware change is needed.
    4. Each application is therefore just a particular sequence of instructions fetched and executed by the same fetch–decode–execute cycle.
    Marks: 1 for instructions-as-data, 1 for same memory, 1 for behaviour depending on memory contents, 1 for the conclusion that no hardware change is needed.

  4. Describe the role of the MAR, the MDR and the program counter during the fetch stage.

    Show answer

    The address of the next instruction is copied from the PC into the MAR; the MAR's contents are placed on the address bus; the control unit issues a read signal; the data returned on the data bus is placed in the MDR; the instruction is copied from the MDR into the current instruction register; and the PC is incremented so it points at the next instruction.

    Naming all three registers with their specific role is what earns the marks. "The CPU fetches the instruction" earns none of them.

  5. A 24-bit colour image is 1920 × 1080 pixels. Calculate its uncompressed size in MiB. State one reason a photograph of the same dimensions saved as PNG might be much larger than one saved as JPEG.

    Show answer
    1. Pixels = 1920 × 1080 = 2 073 600.
    2. Bits = 2 073 600 × 24 = 49 766 400 bits. Bytes = ÷ 8 = 6 220 800 bytes.
    3. MiB = 6 220 800 ÷ 1 048 576 ≈ 5.93 MiB.
    4. PNG is lossless, so it must preserve every pixel exactly; a photograph contains sensor noise so adjacent pixels rarely match, making run-length and dictionary methods ineffective. JPEG is lossy and discards high-frequency detail the eye will not resolve, so it can be far smaller at the cost of permanent quality loss.

  6. Give the truth table for \(F = \overline{(A + B) \cdot C}\) and hence write an equivalent expression using only AND, OR and NOT applied to single variables.

    Show answer
    1. Apply De Morgan: \(\overline{(A+B)\cdot C} = \overline{(A+B)} + \overline{C} = \overline{A}\cdot\overline{B} + \overline{C}\).
    2. Truth table (A, B, C): F = 0 only when (A+B) = 1 and C = 1, i.e. rows 011, 101, 111 (in A,B,C order: 0,1,1; 1,0,1; 1,1,1). All other rows give F = 1.
    3. So F = 1 for 000, 001, 010, 100, 110 and F = 0 for 011, 101, 111.
    Answer: F = ¬A·¬B + ¬C. Check row 011: ¬A·¬B = 1·0 = 0, ¬C = 0 → F = 0 ✓. Row 000: 1·1 = 1 → F = 1 ✓. This is a NAND-of-OR structure: (A NOR B) OR (NOT C).

  7. HL only Explain the difference between a compiler and an interpreter, and explain how bytecode and a virtual machine combine advantages of both.

    Show answer
    1. A compiler translates the whole source program into machine code once, producing an executable. It runs fast and the source need not be distributed, but errors are only reported after compilation and the edit–test cycle is slow.
    2. An interpreter translates and executes one statement at a time. Errors are reported immediately at the failing line and development is fast, but execution is slower (each statement is re-translated on every run and on every loop iteration) and the source or interpreter must be present.
    3. Bytecode + VM gets both: the source is compiled once to an intermediate, portable bytecode, then that bytecode is executed by a platform-specific virtual machine (often with just-in-time compilation of hot code). Portability comes from the bytecode; speed approaches compiled code via JIT; and development still feels immediate.
    Marks: 1–2 for each of compiler and interpreter with a distinguishing property, 1–2 for the bytecode/VM combination and the specific advantage it delivers.

  8. Discuss whether a company should be permitted to collect and analyse the location data of its employees' delivery vehicles.

    Show answer

    A high-scoring answer has four elements.

    1. Stakeholders: the company, the drivers, customers awaiting deliveries, and society (road safety).
    2. For: route optimisation reduces fuel use, emissions and cost; customers get accurate delivery windows; stolen vehicles and goods can be recovered; drivers can be protected in an emergency.
    3. Against: continuous location tracking reveals breaks, medical appointments and union meetings — function creep beyond the stated operational purpose; it creates pressure and stress; it may breach data-protection law if it is excessive relative to the purpose (data minimisation); and drivers who are not consulted cannot give meaningful consent given the power imbalance.
    4. Judgement: on balance it is defensible provided that data is collected only during shifts, is retained for a limited period, is not used in disciplinary proceedings without agreement, and that drivers are consulted and can see what is recorded about them.
    Where the marks are: 1–2 for named stakeholders, 1–2 for developed arguments for, 1–2 for developed arguments against, 1–2 for a clear, supported judgement. Naming a legal principle such as data minimisation or purpose limitation is what distinguishes a 7 from a 5.
